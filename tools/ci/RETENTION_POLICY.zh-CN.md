# CI 产物与运行记录保留规则

普通构建默认可丢弃。成功、失败、取消采用相同期限；只保全明确选定的交付、问题复现及直接必要的证据。源码仍由 Git 保存。

| 对象 | 规则 |
| --- | --- |
| 两个主要工作流的普通完整包 | Installed18u、Touch terminal 在 PR、开发分支 push、main push 时默认不上传；编译、制包验证和测试照常执行 |
| 普通附件、小报告 | 上传保留 5 天；清理器要求工件创建时间及父运行最近更新时间均超过 5 天，且父运行已完成 |
| 普通运行及平台日志 | 创建和最近更新时间均超过 7 天，且没有仍需保留的附件，才清理 |
| 明确选定材料 | 精确保护 artifact ID，并保留其父运行；不自动保护该运行的其他附件 |

运行中、排队中、近期重跑及当前清理运行均不删除。查询失败或分页不完整时停止清理；删除前再次读取对象和父运行状态。检查结果为失败不构成额外保全理由，未知用途也不构成无限期保全理由。

## 明确请求交付或问题复现

在 `Installed 18u compile and offline checks` 或 `Touch terminal prototype` 的手动入口选择目的 `delivery` 或 `reproduction`、所需架构，并填写具体用途。默认 `checks-only` 只执行检查。通过 workflow 的 `ref` 选择源码版本；回执记录实际 checkout 的 SHA，不把其他版本的产物混作同一交付。

选定包及回执使用 `selected-{purpose}-{product}-{kind}-{sha}-attempt-{N}` 名称。清理器只有在父运行是 `workflow_dispatch`、产品与工作流路径一致、源码 SHA 和尝试编号匹配时，才将这些**具体 artifact ID**及父运行加入本次动态保护。普通 PR/push 不产生这种选定标记。重试使用独立名称，保留旧尝试的身份。

手动入口仍执行原有编译与验证。供后续检查消费的小报告继续上传，不能因减少大包而关闭全部附件上传。交付包和问题复现材料必须如实保留成功/失败状态；失败检查不能改称已通过。

## 持久保全与外部归档

`retention-protected.json` 是精确、持久的项目清理例外，记录 artifact ID、父 run ID、SHA-256 和明确用途。原有固定保全不因本次政策自动解除。仅同一运行的其他普通附件不进入名单。

新选定包和回执的 GitHub 原生保留期为 14 天。动态保护和项目清单都不能延长平台到期时间，也不能阻止人工删除。因此应在到期前把选定原 ZIP、身份和必要日志归档到明确的交付目录或 Release，并核对哈希；要在附件到期后继续保留父运行，须把确切 ID 登记到静态清单。普通产物不做全量转存。

清单中的 SHA-256 是身份记录；清理器校验其格式，不会在每次清理中重新下载并计算哈希。替换交付或调查结案后，解除持久保留须留下具体对象与依据，不能按分支名或文件大小猜测等价包。

## 清理与审计

每日清理仍在北京时间约 03:23 执行，时间可能受 GitHub 调度延迟影响。手动运行默认只预演；显式启用删除才执行。预演和实际执行均输出可机读报告，区分候选、实际删除、跳过和失败，并记录数量、字节和对象编号。

删除运行会连带删除它的附件，必须先完整列举并核对保留条件。保护父运行不递归保护附件；该边界有模拟测试。

本规则不删除源码、Release、用户本机 Downloads、共享交换目录或独立构建缓存。平台日志随运行按 7 天规则处理；作为附件上传的日志 ZIP 按工件计期。释放量按 API 返回的工件字节计算，不代表账单即时抵扣或已核实的账户剩余额度。
