# 桌面触摸键盘中文操作指南

## 触屏试用版 v1（`--touch-ui`）

帮助在键盘内部按三页显示，底部“上一页/下一页”翻页，原“帮助”键变成“返回”，点它回到键盘；设置与帮助一次只显示一个面板。预览中打开/返回帮助保留组合、语言和本地正文，覆盖区域不会点击穿透。实际宿主入口打开帮助仍会停止会话并取消绑定，返回后须重新绑定目标。

当前新增独立的触屏实用视图，先试效果。原完整100键视图及其入口保留；17u/23u候选保持冻结。触屏视图横向仍18u，主体84键的编码/基础层/Shift层不变，纵向键高为原设计80%（设计15.24mm，实际尺寸须量尺），顶部编辑行高0.75u（设计14.2875mm），间隔0.1u。共98个触摸键：84个原主体键和14个触屏控制键。

原F1–F12不再显示。顶部依次为设置、帮助、绑定（预览中为清空）、取消、CN/EN、←、→、Home、End、选区、全选、Delete、最小化和退出；原Pause/Break位置改为退出，Layout偏好移入设置。编辑键在有中文组合或暂停组合时拒绝操作，先确认或取消组合再编辑。取消保留已确认正文；全选与Delete按预览/实际宿主行为执行。

顶部交互区压成100px：一行组合/绑定状态（预览另显示本地测试输出）和紧凑候选条，‹/›在候选条两端。正式宿主入口不显示本地测试输出。此版减少占屏，但不会自动改变其他应用窗口；实际可见正文、光标与宿主操作空间需在本屏试用。

点设置打开键盘内部面板，不会输入下方被遮住的键。面板收纳变码/全码/简码、英文键帽偏好、标点入口、字形/ID、按键音、配色、三档字号、尺寸校准和参考尺；点左上返回继续输入。设置可在未绑定宿主时使用；文字、候选与编辑操作仍需有效绑定。编码模式切换取消原组合；中文下调整英文偏好不会改中文视图。帮助暂时独立保留。

触屏试用必须通过专用入口或显式`--touch-ui`启动，仅支持18u主区中文预览/宿主路径。省略该参数保持原完整视图，不能把两种视图的键数、几何及实际输入结果混填。

## 原完整盘面与共用功能说明

2026-10-28 启动声音修正：首次声道在词典、字体和窗口就绪后打开；异步打开或播放失败后定时检查并间隔至少一秒重试，无需先最小化。最小化、退出及静音关闭声道；这三个动作本身保持静音。可选输入诊断仅记录声道状态、错误和缓冲计数，不录音、不记录正文。

2026-10-28 最小化修正：音频设备的打开和清理由独立后台线程负责，最小化、静音和退出只发出停止请求，不等待驱动返回。旧声道清理完成前不重复打开新声道；恢复后按键会重试，期间声音可能暂不可用，输入仍可继续。

2026-10-27 按键音播放修正：本轮SoundWire路径中，单独短流及末尾补静音均未听到，相同PCM在连续流可清楚听到。现使用保持打开的音频流，空闲填零，按中时插入原24ms敲击；不再继续增幅。同一持续播放实现的四次独立试听已反馈清楚，实际键盘窗口仍需单独确认。旧包与更正记录保留，不据接口成功推定实际发声；系统或应用会话音量未改。

2026-10-27 可选按键音：`--key-sound click`启用短促轻敲声，`--key-sound off`或省略参数保持静音。预览/中文宿主界面提供“按键音：开/关”按钮，无需先绑定宿主即可切换；开启时发起一次试听，关闭时静音。有效盘面、候选和预览控制动作在抬手被接受后响一次；移出、取消、禁用/未接入键、过期候选和已报告发送失败不响。声音确认动作被键盘处理，不能代替检查宿主正文。按键音切换保留组合，取消其他正在按住的触点和虚拟修饰。播放失败显示“按键音：不可用”，不改变输入或重放文字。启用时预先持续输出静音，再按需插入敲击；关闭声音、最小化或退出释放音频流，恢复后按原开关重新打开。播放在后台进行，极快连按可能截短或合并声音请求，不积压迟到提示。不改变系统音量，效果取决于当前音量/静音和音频输出设备。开关仅在本次运行内保留，截图及自动自检不打开音频流。

2026-10-27 字号修正：键面ASCII与音元字号随校准后的键面尺寸计算，区别于顶部界面字号；字符上下位置按实际字体行高安排，下档完整留在键面内。此修正不改变键位、命中区域、编码或字形文件。

2026-10-27 配色选项：启动时加 `--theme dark` 使用深灰背景、稍浅灰色键面和白字，候选、输出及工具栏也使用深色；按下/修饰开启以低亮度绿色提示。加 `--theme original` 或省略参数使用原配色。配色只改变绘制，不改变键位、尺寸、禁用状态、输入语言和字典，也不修改 Windows 主题或屏幕亮度。深色键面不再用原色组区分音元，判断功能请看键帽与实际动作。切换语言或 Layout 不切换主题；此选项不保存到用户设置。

2026-10-22，H02 触屏辅助导航版，基于 main 合并 PR #76。开发基准为 **18u 主区、100 键、342.90 mm**，每 u 为 19.05 mm。17u / 23u 保留为冻结候选。旧 #74/#76 包及此前英文包的行为不追溯改变。

## 解压与启动

1. 选择与你的 Windows 架构匹配的包，完整解压到一个新目录。不要在 ZIP 内直接启动，也不要把不同包的文件混放。x64 已做受控开发检查；ARM64 目前仅交叉构建，尚无原生验收。
2. 双击 `Start Keyboard.cmd`、`Start Main Area.cmd` 或 `YimeTouchKeyboard.exe`，均默认打开 18u 中文键盘。无需源码目录、Go、Python、网络或另一个已安装输入法。首次加载需校验完整三模式词典并生成临时索引，请等待，避免重复启动。
3. 用实体尺复核顶部 100 mm 参考线和主区宽度，每次验收都独立记录，不沿用旧设备反馈。
4. 在目标应用正文中亲自点好光标，再点键盘“绑定目标”。组合只在键盘中显示，明确确认后才向目标发送。重新绑定取消旧组合和触点，保留宿主中已输入的文字。

`Start Preview.cmd` 打开只写窗口内文本的中文预览；关闭即丢弃内存文本。`Start English Only.cmd` 保留旧版英文输入路径，不启用中文引擎。实验结果不代表 Word、记事本、管理员窗口或所有应用均已接受输入。

## 中文组合与编辑

1. 用变码／全码／简码按钮选择编码模式。按原盘面音元键输入，组合栏显示原始 ASCII，下一行显示当前页候选。点候选或用空格／Enter 确认首选。中文无组合时，空格／Enter 直接输出空格／换行；非空且无候选时保持组合，不提交。切换编码模式取消未确认组合，保留已确认正文。
2. 主区 1–9 有候选时选择当前页对应序号；非空候选页上不存在的序号不操作，没有候选时才按既有规则输出数字。主区 0 和非编码 ASCII 保持实验规则。编码标点只在单字符组合时提供自身字面候选。
3. Esc 取消键盘组合，不向宿主发送 Escape。主区退格先编辑活动中文组合；无活动中文组合时编辑目标正文。
4. 中英文切换键同时切换输入语言与标点；键帽只显示当前输入语言：中文为 CN，英文为 EN。英文下即使 Layout 切回原盘面，语言键仍显示 EN。英文输入暂停并保留中文组合，暂停候选不可点击，切回中文可继续。中文固定 CN 盘面；英文时 Layout 切换原盘面／英文键帽，保留本次运行中的偏好。EN 盘面字母基础层为小写，Shift 为显式大写，例如 `R05K06` 为 `a`/`A`；原盘面保留自身显式映射，例如 `R05K07` 为 `a`/`]`。23 个英文空白键禁用，不按颜色推断功能。
5. 没有活动组合时，编辑键及 Ctrl/Alt 快捷键发给目标，是否生效取决于应用。18u 键盘上方输出栏右侧增加 **← 左、右 →、Home、End、选区：关/开**，操作见下节；100 个盘面键、尺寸和颜色不变。经典 EDIT 的历史受控检查未响应 Ctrl+A，不用它作为选区前提。英文主区和侧区 Shift+Enter 保留 Shift，由应用解释；中文主区有候选时 Shift+Enter 确认首选，无组合时发送带 Shift 的 Enter。
6. 左右数字区直接输入数字和 Enter，不选中文候选。两侧 Num Lock 独立切换数字／编辑模式，编辑模式 5 无操作。未标注主区标点入口开关默认关闭；开启不改变编码层。Unicode 符号输入仍限于六个已审阅键帽。
7. Shift 可点一次再点字符，也可一指按住 Shift、另一指点字符。Ctrl、Alt 可点一次再点下一键；再点同一修饰键取消。不要同时按住真实物理键盘的 Shift/Ctrl/Alt/Win；程序不会擅自释放这些物理按键。

当前中文预览/宿主的语义输入路径中，Caps Lock 和两个 System 键虽然不执行输入或系统动作，仍会消耗本次虚拟 Shift/Ctrl/Alt，点后修饰高亮会熄灭，无需再次关闭。23个英文空白禁用键直接忽略触点，保留原修饰状态。此处说明单次点按的虚拟状态，不表示物理键盘修饰键被释放。

2026-10-28 笔防回弹试用：`--pen-recontact-ms 80`仅用于交互式`--preview --touch-ui`，默认0关闭。只过滤同一原生笔标识、同一字符键在前次抬起后80ms内的再次接触；连续回弹从最后抬起重新计时，第一下仍立即处理。其他已接受动作会打断此匹配，取消/切换会清除历史；手指、鼠标兼容回退、不同键和修饰/控制键不进入该过滤。它可能合并极快的有意同键连点，暂为可关闭的对照实验，不能作为无漏字或无重复验收。原兼容鼠标消息去重仍保留。
8. 按下后移出键面，即使移回也取消。候选已翻页、模式已切换或目标已变化时，旧触点不继续提交；重复抬手不重复发送。

“字形 → ID”切回 ID 标注。基础 60 音元使用包内字体，派生 R ID 保持 ID 显示。字体只在本进程加载，不安装到系统。Caps Lock、系统键和 Pause 未接入。

## 触屏辅助导航与选区

在中文预览或默认绑定目标入口中，先确认或 Esc 取消中文组合。英文模式下暂停的中文组合也必须取消；有组合或会话停止时辅助控件灰显且不执行，不自动提交、删除组合或移动宿主光标。旧英文专用入口不增加此栏。

- 点 ← 左／右 → 移动光标，点 Home／End 到起止位置。预览沿用按 Unicode 码点左右移动、Home/End 到全文开头/结尾；真实应用收到原生 Left/Right/Home/End，通常为行首/行尾，具体由宿主解释。先在单行正文中验收，再分别记录多行差异。
- 点“选区：关”变为“选区：开”，再逐次点四个导航按钮扩展或缩小选区。只需单指或单笔连续点按，无需同时按 Shift。每次导航独立发送带 Shift 的完整按下/抬起，不在操作间按住系统 Shift，也不继承盘面 Shift/Ctrl/Alt。
- 再点“选区：开”关闭扩展，已有选区仍保留。关闭后点左/右按宿主规则收拢选区；点字符替换选中文字，点退格删除选中文字。字符、退格、模式/布局/其他控件操作会关闭扩展开关；不会把后续字母变成大写。
- 辅助控件在原按钮内抬起才执行；移出再移回仍取消，长按不自动重复。导航与其他触点不并行：后按下的导航或普通键取消尚未抬起的另一类触点。请依次点按，避免迟到字符落入新光标位置。
- 失焦、重绑、最小化、帮助、显示环境变化、异常捕获丢失及发送失败都会清除扩展开关和旧触点。开关不表示宿主一定已有选区，实际高亮与正文需观察确认。

使用上述辅助控件完成导航、选择、替换、删除，可以计入对应新包的纯手指或纯触控笔覆盖；操作过程中借助鼠标、物理键盘、侧区/全盘或笔加手指则单列辅助/混合结果，不能并入该结论。鼠标及程序化事件回归仅属开发证据。

## 失焦或发送失败

焦点离开（即使再返回）、最小化键盘、打开帮助或显示环境变化后，未确认组合和触点取消。重新在目标文本区点光标并绑定后继续。

遇到发送失败、部分发送或结果不明，先查看正文中实际留下的内容。程序停止后续发送，不自动重放、补发或删除前缀。人工核对后重新绑定，再输入所需内容。

Windows SendInput 无法原子绑定某个窗口。提交前后检查和已经收到的焦点通知不能排除发送瞬间全部切换竞态；确认时不要切换应用。“输入事件已发送”不等于应用已接受。权限不同的宿主可能拒绝输入。

## 预览与包自检

预览中的“本地输出”按 Unicode 码点编辑；18u 主区提供退格和无组合时 Ctrl+A，辅助栏提供左右、全文 Home/End 和选区扩展。`│` 表示光标，`⟦…⟧` 表示可见选择片段，`↵`/`⇥` 表示真实换行/Tab 的显示标记。输出在辅助栏左侧单行显示并随当前光标截取，两端 `…` 表示还有内容；内部正文仍保留真实换行。它不是完整编辑器，不支持保存或剪贴板；“清空输出”只清除预览自己的组合和文本。

双击 `Check Package.cmd` 校验包内资源，并在内存中验证三模式选词，成功时生成 `package-check.json`。该检查不打开键盘窗口、不发送宿主输入；失败时不要把以前留下的报告当作本次通过。也可从终端运行：

```text
YimeTouchKeyboard.exe --check-package --data-report package-check.json
```

资源缺失、被修改或混包时程序拒绝启动，请重新完整解压同一包到新目录。不要手工改包内 profile、字体、指南或词典；资源清单与程序绑定。包内 manifest 及 CI 下载记录可用于核对身份，哈希不是数字签名。

完整词典每次启动生成独立临时索引，正常退出清理；强制终止可能留下本程序临时目录。程序不读取已安装产品或用户词库，不自动迁移学习数据。

Ruler −1% / +1% 只调整像素与毫米换算，不改变每 u 19.05 mm 的几何。校准只在本次运行有效。命令行可以填入有效显示宽度和默认校准下参考线实测长度，例如：

```text
YimeTouchKeyboard.exe --screen-width-mm 597.73 --ruler-observed-mm 98.5
```

显示宽度只量发光区，不含边框；屏幕对角线不能代替宽度。换屏、旋转或改变显示设置后重新量尺。空间不足时报错，不自动缩小键帽。

本包不安装输入法，不更改已安装或默认输入法、注册项、系统字体或既有用户数据。鼠标、模拟触摸、渲染图、内存检查和自有 EDIT 结果均为开发证据。真实手指、触控笔、真实应用及 ARM64 原生结果仍待分别记录。
