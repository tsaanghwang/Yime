## 状态

动态生成核心的评估库存：程序给每个来源门禁合格、已有编码的字串分配 R0–R5 覆盖层，输出不能

## R0–R5

| 层 | 含义 | 程序动作 |
| --- | --- | --- |
| R0 | 确定性无效、显式拒绝或读音对齐错误 | 修复或隔离 |
| R1 | 所有读音均不能由更小来源部件恢复 | 寻找最小部件或构式；修复前保留必要覆盖 |
| R2 | 部分读音可恢复、部分不可恢复 | 补齐缺失读音覆盖 |
| R3 | 全部可达，但组合深度或最短路径竞争超出可靠门槛 | 评估中间部件、beam 或有界缓存 |
| R4 | 全部读音在可靠门槛内动态可恢复 | 由动态核心服务 |
| R5 | 基础字符、受保护类别、人工批准项或有证据缓存 | 带理由静态保留 |

频率只影响缓存收益和审查顺序，不参与 R0 判定。动态可恢复也不否定词汇身份。

## 长串迁移

长度不少于 5、BCC 为 0、无下游复用、非强制静态、全部读音可恢复，且属于普通词汇或生产短语
的 472,671 个字串，已经迁出静态核心但保留动态恢复。71,574 个同条件领域词和专名受类别保护。
当前二级运行选择包含 7,867 个有证据或受保护长串，迁移对象误入数为 0。

两级运行构建在物化前执行相同审计；超过零违规门槛会直接失败。

`build_two_level_runtime_trial.py` 同时强制执行 R0–R5 全量覆盖门禁，并把分层统计写入最终
`manifest.json` 的 `dynamic_candidate_coverage`。以后来源、分类或选择发生变化时，不可能只更新
词典而遗漏本项验收。

## 完成门禁

本任务按以下条件关闭：

1. 每个已编码字串恰好获得一个 R 层；
2. R0 为 0，确定性完整性扫描无结构错误和占位编码；
3. R1–R3 均输出残差样例和核心改进方向；
4. 当前运行选择按 R 层留痕；
5. 长串迁移对象没有重新进入运行选择；
6. 来源词库保持只读，程序不写删除裁决；
7. 路线图、架构和项目说明以动态覆盖闭环为准。

以上程序门禁已经满足。R1–R3 后续数量下降属于持续提升生成能力，不再作为“清理任务未完成”
挂在路线图中。
