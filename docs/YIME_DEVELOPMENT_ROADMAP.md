# Yime 开发路线图

更新：2026-09-16。范围：YimeCore 主开发线、Rime/PIME 稳定维护线及共同离线数据工程。当前事实见[项目现状](YIME_PROJECT_ASSESSMENT.md)，产品边界见[双产品计划](project/YIME_DUAL_PRODUCT_DEVELOPMENT_PLAN_2026-09-05.md)。

## 当前阶段

双产品独立运行和简版安装维护已经落地，清理后源码候选包已完成已报告范围内的实机验收。后续工作以具体缺陷、性能和目标平台为单位推进；不再接续旧固定事务恢复链，也不把所有历史待办重新作为安装前提。

从 `c5216861` 制作的完整双产品包包含安装器包完整性与卸载失败处理修复，源码 CI 与本地包验证通过；来源、下载和 SHA-256 见 [HANDOFF](../installer/simple/HANDOFF.md)。本轮仅交付，没有新包实机验收，也不要求测试机安装、卸载、重启或重测。

## 后续优先顺序

### 1. 维持可重复的开发交付

影响产品：按具体变更标明 YimeCore、Rime/PIME 或两者。

- 从当前主线开始，每个任务明确源码改动、验证范围及包来源。
- PR #57 完整包按本轮交接发布 URL、大小、SHA-256 与来源证据；后续如需实机安装和输入验收，再明确新包对应的测试范围。
- 新运行载荷在开发端完成相应构建、制包和安装输入验证，再交给测试端；纯文档工作只检查文档，不改变现有安装。
- 持续覆盖缺包拒绝、配置移除失败、文件占用、启动项、日志与父子进程返回；保持另一产品和系统字体边界。

完成标准：源码、CI、包、报告可以互相定位；失败与未执行步骤明确，测试端不负责临时修安装器。生产用户数据迁移暂缓。

### 2. 推进 YimeCore 日常稳定性、性能和 x86 验证

影响产品：YimeCore。

- 保持 x64 日常使用与 x86 WOW64 工作并行；x86 按源码/契约、双架构包、安装态注册宿主、真实 32 位应用顺序验证。
- 宿主改动重点覆盖异步编辑完成结果、失焦取消、已提交文本保护、语言栏对象生命周期及候选 HWND 生命周期。
- Broker 改动保留连接所属会话清理和完整观察集的 mutation 幂等性回归。
- 性能工作从 [i7-7820X 报告](project/YIMECORE_I7_7820X_NATIVE_BENCHMARK_RESULT_2026-09-09.md) 的 E3 学习开销问题继续，使用明确的源码与测试条件；CPU 采样只能定位，不能替代性能通过结果。

完成标准：新基线的受影响回归和实际宿主记录可复核。历史 local.13 行为通过、保护对照暂缓及未封存结论原样保留，不重开旧补证链，也不宣称新包已全面封存。

### 3. 独立维护 Rime/PIME 与共同数据链

影响产品：Rime/PIME；共同数据变化时另加 YimeCore 验证。

- 优先修复有复现的候选、语言栏、部署、用户词库和原生工具问题，不要求与 YimeCore 功能同步。
- 继续由 Rime 拥有分页，保留页大小读回、带引号 YAML 键和 `data.id` 子菜单命令兼容。
- 三模式由同一规范记录与布局派生；读音审查与候选排序分别保留来源和决策证据。
- 语流音变仅按[语流计划](project/MANDARIN_CONNECTED_SPEECH_PLAN.md)扩展有来源、可移除的词/短语别名；共同产物变化必须覆盖三模式真实 Rime 和独立 YimeCore 测试。

完成标准：每个改动有受影响产品的回归，安装行为变化有对应新包证据；不以可选 Rime 对照代替 YimeCore 正确性。

### 4. 按批准范围扩展平台

批准范围由 [development-scope.json](../tools/yimecore/development-scope.json) 管理：MYCOMPUTER 的 x64/x86、已识别的主流 x64 测试机，以及待识别实机的 Windows ARM64。

ARM64 必须使用当前产品身份重新构建原生 Runtime/Broker、TSF 和完整包，再取得原生注册与真实宿主结果。交叉编译成功不能作为兼容性通过；旧身份载荷保留为历史，不能改名交付。新增云机器、硬件采购及未列出的平台不在本路线图执行范围内。

### 5. 完成公开发行所需工作

当前简版工程尚未完成正式签名发布流水线。后续按[发布与签名指南](YIME_RELEASE_AND_SIGNING.md)实现可信签名、完整包验证及明确的版本与来源记录，再对最终签名产物进行安装、输入、重启和维护验收。

公开发行还需明确生产用户数据策略；开发测试允许的显式清空不能代替生产迁移方案。`version.txt` 当前为 `1.4.0-dev.1`，它不证明双产品已经统一正式发布。

## 长期维护与研究

- 读音事实与候选质量：持续处理有来源的读音冲突、高频不足、用户复现和回放指标，避免为了数量补造拼音或音元码。
- 数据维护：在独立产品边界内设计升级、备份、恢复和跨版本兼容；不自动跨产品迁移学习数据。
- 语音研究：片音边界、听知时限及自然语音重建需要独立实验，不能从音元 ID 或四元位置推出声学结论。

## 推进规则

候选序号始终为 `⇧1`—`⇧9`，裸数字始终输入编码。不得用扩大功能范围、删减回归、修改历史结果或放宽门槛代替当前问题的解决。

任务结束时分别写明源码验证、包交付和实机结果；没有执行的层级明确写未测。阶段与优先级变化更新本文，实际操作更新 [HANDOFF](../installer/simple/HANDOFF.md)，原始结果留在带日期的报告中。工程约束以 [AGENTS.md](../AGENTS.md) 为准。
