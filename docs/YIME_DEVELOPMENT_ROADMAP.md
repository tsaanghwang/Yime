## 近期优先顺序

### 1. 收敛 18u 安装版候选与分支

影响产品：独立 18u YimeCore 输入链与安装工具。

- #95/#96 已合入 `validation/18u-simple-installer-20261102`，#97 仍在该分支的审阅队列；先明确合入对象及受影响回归，不能把这些功能写成 main 已完成。
- 微星 test.7 使用固定源码 `33b7113c` 的完整前端包；[更新后交付清单](https://github.com/tsaanghwang/Yime/blob/c07c9545227ed0a333ca44eed060df098cb8259a/docs/testing/18u/2026-11-03/msi-preparation/TEST7-DELIVERY.zh-CN.md)区分首次交付状态与后续单次宿主结果。[现状页](YIME_PROJECT_ASSESSMENT.md#已有交付与实机证据)分别列出安装静态核验、重启会话报告、固定自有宿主摘要及未上传原始证据的边界。
- 自有宿主已有一次 CN/variable 的实际 DLL 加载、注册 profile 激活及提交/读回；后续分别验证普通应用中的身份、跨进程认证、激活 TIP、提交/读回、焦点取消和支持的编辑动作，不自动重复成功用例。单次自有宿主 commit 通过不能替代这些场景或独立启动验收。
- 指笔测试按设备能力、固定包和动作逐项记录。鼠标、模拟事件、受控 TSF、人工反馈和自动正文读回分别标注；“计算机”保留纯鼠标范围，不列指笔待补测。

完成标准：候选源码、构建、包、安装和普通应用证据相互对应；已支持/未支持操作明确，失败与未执行项保留，物理验收不由 CI 推定。

### 2. 完成 ARM64 新包的权限与输入验证

影响产品：标准 YimeCore、ARM64 Rime/PIME 候选和独立 18u 候选，分别处理。

- ASUS 原生 ARM64 设备已可用；停止沿用 9 月“无机器冻结”的待办。
- `956350e4` 所在分支修复由提升进程启动常驻 Runtime 的问题；新制包需分别固定主线运行载荷与修改后的安装器来源，证明由普通用户父进程核验后启动，并读回实际进程令牌。
- 标准版 ARM64X/x86 的 9 组注册宿主通过，不自动证明常驻 Runtime 正确或 Word/Edge 等真实应用兼容。新包继续按实际宿主与位数记录。
- Rime/PIME ARM64 构建、真实 Rime及 DLL 加载证据，与 18u ARM64 前端证据分别保留；草稿不标成正式完整交付。18u 原生 ARM64 TSF 尚不能覆盖推断 x64/x86/ARM64EC 应用。
- `installed18u-arm64-readiness-r1` 仍是因缺原生 test.6 包而停止的旧任务；新候选需要自己的包身份和派测范围。

完成标准：可追溯完整包、普通用户运行、已安装注册宿主、真实应用及获准的重启/维护各有对应记录。标准版与实验版互不覆盖注册、字典和状态。

### 3. 持续保护标准产品和数据链

- YimeCore 保留 x64/x86 异步编辑、失焦取消、回调/窗口生命周期、连接所属会话清理及完整 observations 幂等回归。
- Rime/PIME 独立维护候选、语言栏、部署和用户工具；保留原生分页所有权、页大小读回、带引号 YAML 键和 `data.id` 子菜单兼容。
- 标准布局与实验布局各有唯一真源和生成资产，不相互替换。概念键盘的 ANSI 路径只要求功能完整，不加输入效率或 Shift 次数门槛。
- 语流变化遵循[准入计划](project/MANDARIN_CONNECTED_SPEECH_PLAN.md)，共同资产变化分别运行真实 Rime 三模式与 YimeCore 回归。

完成标准：受影响产品的回归和包身份可复核；不以扩大功能范围或修改历史结果代替缺陷闭环。

### 4. 性能、稳定性与正式发行

- 保留[开发机 9 月 19 日 E3 通过](testing/simple-maintenance/2026-09-19/current-readiness/DEVELOPMENT.md#e3-performance)与 [i7-7820X 历史失败](project/YIMECORE_I7_7820X_NATIVE_BENCHMARK_RESULT_2026-09-09.md)的不同来源。新测量固定包、机器、条件和指标，不能将包检查或 CPU 采样称为端到端性能验收。
- 最终签名产物须重新经过相应安装、启动、输入及维护验证。当前 test.6/test.7 未签名测试包不等于可信正式发行。
- 生产用户数据迁移、备份恢复和跨版本兼容独立设计；开发测试的显式重置不替代生产策略。

## 交接与文档维护

从最新 main 建立目标明确的开发分支，固定源码和包身份。主线进展、候选交付、设备结果分别进入[项目现状](YIME_PROJECT_ASSESSMENT.md)；标准安装在 [HANDOFF](../installer/simple/HANDOFF.md)接续，18u 便携在[桌面交接](../prototypes/touch-terminal/desktop/HANDOFF.md)接续，安装版使用对应候选分支交接。task-results 分支只按原任务范围解释，已完成批次不自动重开。

大包使用明确的 artifact/Release URL、SHA-256 和保留期限；源码 checkout 不是包交付。带日期报告保留原始成功、失败、跳过和未测项，摘要更新不更改原始 JSON 或哈希。工程约束见 [AGENTS.md](../AGENTS.md)。
