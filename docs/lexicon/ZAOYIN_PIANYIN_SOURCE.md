# 噪音类片音真源与稳定登记边界

## 1. 当前链路

首音处理分为三层：

1. `syllable/pianyin/zaoyin_pianyin.json`：记录规范拼音首音、条件音值、来源、适用条件和规范拼音还原关系；
2. `syllable/yinyuan/zaoyin_yinyuan_enhanced.json`：只登记现行稳定音元 ID 和运行字符；
3. `shouyin_codepoint.json` 等文件：从稳定登记派生的运行映射。

音节分析器先产生首音标签，再由稳定登记把标签投影为音元 ID/运行字符。分析规则和运行字符不在同一层决定。

旧的 `pianyin_initial.json`、`initial_ipa.json` 和 `shouyin_analyzer.py` 不再属于现行来源链。它们可以保留作历史材料，但不得据其内容覆盖结构化真源或稳定登记。

## 2. 二十七项登记

- N01–N22：二十一规范辅音声母和零首音；
- N23–N24：`y`、`w` 对应的正字法半元音入口；
- N25：`ü` 行的 `[ɥ]`；
- N26：语气词“啊”在后鼻音末音后形成的 `[ŋ]` 首音；
- N27：语气词“啊”的舌尖同化首音；在 `ɿ` 后实现为 `ɹa/za`，在 `ʅ` 或 `er` 后实现为 `ɻa/ʐa`。

N25–N27 已进入稳定登记、运行字符映射和唯一键盘布局。N25 由正式音节编码链用于 ü 行的
`[ɥ]` 虚首音，不再兼容投影到 N23。N26/N27 只允许经审核的语气词“啊”语境规则显式引用，
不会仅因登记存在而自动生成候选。布局中 N26 与 N12 共用撇号键，N27 与 N25 共用反引号键；
共享关系只在 `internal_data/manual_key_layout.json` 的 `shared_yinyuan_key_groups` 登记。

### 2.1 发音部位记忆顺序

`zaoyin_pianyin.json` 另设 `articulatory_memory_groups`，按大致固定发音部位排列：

1. 唇音：`b p f m`；
2. 上龈音：`d t l n`；
3. 软腭音：`g k h ŋ`；
4. 上齿背音：`z c s a_apical`；
5. 龈腭间音（卷舌）：`zh ch sh r`；
6. 硬腭前部音：`j q x y`；
7. 后置组三项（只表示记忆顺序，不是完整类别）：
   - `'`：舌位为非高的乐音前的虚首音；
   - `w`：音质为 `[u]` 的高乐音前的虚首音；
   - `ɥ`：音质为 `[y]` 的高乐音前的虚首音。

前六组各四项，最后三项统一置末；全局 `memory_no` 为 1–27。该编号只服务于记忆、练习和后续分组，不能替代或重排稳定的 `yinyuan_id`。例如 `[ŋ]` 的记忆序号是 12，但稳定 ID 仍是 N26；非高舌位乐音前的虚首音记忆序号是 25，但稳定 ID 仍是 N12。

“发音部位记忆组”和“结构角色”是两条并行分类轴，不能混为一谈。完整的虚首音结构类别包括 `'`、`y[j]`、`w`、`ɥ` 四项；其中 `y[j]` 为了和 `j[tɕ]`、`q[tɕʰ]`、`x[ɕ]` 组成硬腭前部四项记忆组，排列在第六组。因而第七组只能称为“后置组三项”，不能称为完整的“虚首音组”。

`a_apical` 只合并稳定登记 ID，不再混写具体实现：`ɿ → ɹa/za`，`ʅ` 或 `er → ɻa/ʐa`。把它放在上齿背组只是为了保持四项记忆结构，并不主张四种实现具有完全相同的发音部位。

## 3. 安全重建

```powershell
python tools/rebuild_zaoyin_registry.py
```

默认命令只校验，不写任何登记文件。需要查看 27 项登记提案时显式运行：

```powershell
python tools/rebuild_zaoyin_registry.py --write-proposal
```

提案只能写入 `.generated/zaoyin-registry/`。该命令不能覆盖现行 `zaoyin_yinyuan_enhanced.json`。

## 4. 后续语境规则接入条件

为 N26/N27 新增或扩大语气词“啊”的运行时语境规则前，必须另行完成：

- 每项具体音值和条件的来源复核；
- 显式语境候选及规范拼音还原边界审查；
- 三种编码模式的完整派生和碰撞报告；
- 布局变更锁、反查和 Windows 运行时回归。
