# 候选语料库整理路线图

## 文档定位

本文记录统一候选语料库在完成来源合并、拼音门禁、轻声范围约束和运行库重建之后的工程现状，并规定
下一阶段的整理顺序。它是“现在整理到哪里、下一步整理什么”的长期入口。

这里使用“候选语料库”，而不简单称为“词库”，因为全集同时包含词、专名、术语、固定表达、能产
组合、句法片段、语料切片和少量确定性无效材料。系统不预先假定每个高频字串都是词，也不把低频、
古旧或暂时不能动态恢复等同于无效。

相关文档分工如下：

- [字词拼音与频次统一语料包](LEXICON_SOURCE_BUNDLE.md)：来源、构建口径和产物格式；
- [汉语输入候选整理与动态组合系统](INPUT_CANDIDATE_MODEL.md)：分类、决策覆盖层和动态组合器；
- 本文：现状快照、质量判断、整理优先级和分阶段路线；
- [当前实现总览](CURRENT_ARCHITECTURE.md)：整个拼音—音元—运行候选生产链的工程事实入口。

## 三层必须分开

```text
统一来源语料库 source_lexicon.sqlite3
  保存完整来源事实、读音、频次、分类和拒绝证据
              │
              ▼
候选整理覆盖层 input_model.sqlite3
  保存 proposed / approved / rejected / deferred 决策
              │
              ▼
运行候选 pinyin_hanzi.db
  只承载当前发布所需的静态候选和编码结果
```

来源语料库应尽量完整并可追溯；整理覆盖层可以逐步积累稀疏判断；运行候选以后可以缩减。不得为了
缩小运行词库而删除来源证据，也不得把尚未审查的机器建议直接写成生产事实。

## 已经完成的整理能力

### 未编码字串可以进入可审计的人工准入流程

`tools/review_unencoded_candidates.py` 提供本机可视化工作台，面向没有合规读音、尚未进入已编码候选
的字串。审查者可以主要通过鼠标完成准入、拒绝或暂缓，并按材料分类和预期用途记录理由。所有判决
进入独立覆盖层并保留改判历史；即使人工准入，缺少真实读音来源的字串仍标记为不可进入运行词库，
不得由界面猜读音或生成编码。

对于能产短语和半固定构式，工作台已经提供独立的规则族登记：以一个代表例、同族正例、反例、结构
说明和排除边界为审查单位。已登记正例进入 `model_only` 并退出逐条待审队列，反例不被连带判决；
登记状态明确保持为“未验证、不可运行”。当前尚未实现的下一阶段是基于真实组件读音和回放指标把
通过验证的规则族提升为可执行组合规则，并批量标记 `dynamic_recoverable`。

构式发现已经支持正序前缀和逆序后缀的层级筛选。审查者可先用短根项取得全集，再用方向兼容的更长
项细分；系统按最长命中项拆分候选，并分别核验左右组件是否已有来源门禁合格读音。两侧合格的结果可
批量带入动态组合、半固定构式、专名或领域规则族的正例，缺读音项则留在来源核验路径；筛选本身不写
判决。

同一窗体也支持 `以{依据}为{目标}`、`在{处所}(中|上|下){后续?}` 一类框式模板。槽位整体有合规
读音时停止，否则从多字递归到已注音原子；两字组合在两个单字均有合格注音时直接进入动态组合，
只有至少一个单字缺音时进入专门例外，多种同等拆分进入歧义
审查。只有唯一递归覆盖的框式实例才能作为批量正例，模板及解析结构随规则族保存并由后端重新验证。

自动筛查层会把已登记规则应用到尚无 assessment 的未编码整体：唯一无冲突命中可批量写入
`model_only + unvalidated`，精确反例、缺音两字例外、拆分歧义、跨分类冲突和缺读音项目分别留队。
没有规则但可递归覆盖的项目标为 `unclassified_composition`，并按首字/末字聚类为后续规则建议。
因此人工工作量可以逐步从表面字串数量收敛到有限的新规则、冲突和例外数量，同时不放宽来源及运行时
门禁。

### 1. 来源边界已经闭合

- 只读取真实本地上游文件；
- BCC 各分域原始计数分别保存，汇总频次取各分域最大值；
- 不把二次合并频次文件重新当作来源；
- 万象的 `cuoyin`、`mixed` 默认不进入拼音解码来源；
- 每个输入文件在 manifest 中保存路径、摘要和大小。

### 2. 拼音进入编码前有统一门禁

- 非法字符、异常拼式和缺失注音可以拒绝并报告；
- 新音节必须有真实来源和明确审查，不自动补齐声调；
- 不猜读音，不手写音元码、Yinyuan ID 或键位；
- 过时读音可以定点排除，不扩张成全局音节禁用。

### 3. 轻声与词境读音已经分层

- 记录轻声位置和来源解释状态；
- 区分完整候选读音与仅供词境使用的证据；
- 单字本调、词汇性轻声和临时语流弱化不再压成同一张五声闭合表。

### 4. 来源真源能够传导到运行候选

统一来源库重建后，正式单字导入和运行刷新可以清除陈旧读音，而不仅是给旧行重算编码。来源排除、
单字库存、音节依据和运行候选已经形成可验证的闭环。

## 当前不能作出的结论

### “只拒绝 11 条”不等于词库已经很干净

来源门禁检查的是注音能否安全、可解释地进入编码链。一个字串有合法拼音，不代表它一定是词，也不
代表它值得静态进入候选框。万象中仍包含人名、地名、诗词、专业条目和联想组合；BCC 中仍包含大量
宽松切分结果。这些应在候选整理覆盖层判断，不应伪装成拼音错误。

### “BCC 高频”不等于“词汇性强”

高频只能决定审查优先级。某些高频项可能来自固定报头、日期模板、连续文本截片或历史语料格式。
必须结合来源分域、长度、上下文、左右边界和组合可恢复性判断。

### “可以动态组合”不等于“应立即删除静态词条”

动态组合必须先通过回放验证。只有当短组件已经批准、读音有来源、组合召回稳定且排序不恶化时，长
候选才可以标为 `dynamic_recoverable`。精简运行词库是路线末端，不是整理起点。

## 分阶段整理路线

### 阶段 A：固定可重复的质量快照（已完成）

目标：每次来源更新后都能回答“新增、减少和拒绝了什么”。

工作：

1. 重建统一来源包并执行验证；
2. 导出按 BCC 排序的未解码和多读音摘要；
3. 对比 manifest、拒绝数、冲突数和运行候选数；
4. 保证来源库、单字导入和运行刷新形成固定点。

完成标准：相同上游与策略连续重建得到相同统计和摘要；验证为零错误、零警告。

当前状态：已完成。来源包、输入模型、静态容量、运行选择和报告均有可重建 manifest。

### 阶段 B：递归筛查未编码字串并以 517 个最高频项作诊断集（已完成）

目标：先用较短已编码字串自动建立全量动态可达性证据，再用最高频项检验模型，而不是要求人工逐项
标注全部 517 项，也不急于为整体自动注音。

自动模型至少区分：

- 能由较短已编码组件唯一恢复的组合；
- 存在多个等优切分的结构多解；
- 组件存在多个来源读音的读音多解；
- 因尚无已编码单字根基而无法覆盖的材料；
- 虽技术可达、但仍需上下文判断是否固定词或专名的材料。

完成标准：全量未编码多字串均具有可复现的递归组合证据或明确缺口；517 个高频项只作为诊断和抽样
复核集，人工集中处理模型冲突、来源缺口和规则无法解释的残余项。组合输入序列不得写成整体词音。

当前状态：已完成。1,667,070 个未编码多字串全部获得分层路径，最高频 517 项作为诊断集保留。

### 阶段 C：建立上下文证据和保守规则（构式基础设施已完成）

目标：把“像不像词”的直觉转为可复查证据。

优先增加：

1. BCC KWIC 前后文；
2. 左右邻接频次、左右熵和互信息；
3. 数字、时间、数量结构和标点边界规则；
4. 助词、语气词、连词、量词及框式结构的切分建议；
5. 万象显式类别到人名、地名、术语等分类的保守映射。

规则只能输出 `proposed` 建议。不能因为命中规则就自动批准，更不能由 LLM 填写拼音或编码。

完成标准：第二批 11,274 个高频项能够按可解释特征分队列，并形成可抽样评估的建议集。

当前状态：助词构式、框式模板、前后缀发现、规则族和审查队列已程序化。KWIC 等新证据可持续补充，
但不再阻塞原 Phase 4.3 的关闭。

### 阶段 D：整理多读音冲突（处理机制已完成）

目标：把“同形多读”拆成默认读音、限定读音和来源错误，而不是粗暴去重。

审查顺序：

1. 运行高频且存在 BCC 证据的冲突；
2. 单字本调与词内轻声冲突；
3. 人名、地名、姓氏与普通词读音冲突；
4. 文白、古今和方言读音；
5. 低权重孤立来源与可能的注音错误。

完成标准：高频冲突具有明确默认读音或适用范围；无法判断者保持多读或 `deferred`，不猜选。

当前状态：多读音保留、词境限定、来源冲突和 `deferred` 路径已落地；新增来源继续走常规质量门禁。

### 阶段 E：动态组合回放（首轮验收已完成）

目标：验证哪些长候选可以由来源门禁合格的短组件恢复，以及哪些自动可达路径能够安全进入发布
运行规则。证据阶段不要求短组件先作人工分类；发布提升仍须回放。

评测至少包括：

- 目标候选召回率；
- 首屏和前若干位排序；
- 多音组件带来的组合歧义；
- 静态保留与动态恢复的内存、速度和候选质量差异；
- 人名、机构名、框式结构和数量结构等不同类别的分项表现。

完成标准：只有通过回放阈值的条目才能标记为 `dynamic_recoverable`。

当前状态：固定回放 5,830 项；生产范围 2,449 项冷启动首选率99.6325%，95% Wilson 下界99.3030%。

### 阶段 F：形成精简发布层（已完成）

目标：在不破坏来源事实和召回率的前提下缩小静态运行候选。

发布政策：

- 高频基础词、固定表达、重要专名和不能稳定动态恢复的材料静态保留；
- 已验证可恢复的长组合转入动态层；
- 明确无效材料进入 R0 修复或隔离，不用频率替代判定；
- 领域词库可以按场景分包，不必全部常驻；
- 完整来源证据和整理决策继续保留，不随运行精简删除。

完成标准：精简前后具有可比较的回放报告，并能从同一来源真源稳定再生成。

当前状态：Windows 两级运行层已落地；1,152,157个不同字串被选择，46,095个已编码单字全部
进入运行链；472,671个可恢复零证据长串迁出静态核心，迁移违规为0。

## 每轮整理的固定工作流

```powershell
# 1. 重建统一来源语料包
.\venv312\Scripts\python.exe tools\build_lexicon_source_bundle.py

# 2. 校验来源库
.\venv312\Scripts\python.exe internal_data\pinyin_source_db\validate_source_pinyin_db.py

# 3. 更新可提交的高频审查摘要
.\venv312\Scripts\python.exe tools\export_lexicon_review_summary.py

# 4. 同步完整候选整理全集
.\venv312\Scripts\python.exe tools\build_input_candidate_model.py

# 5. 用较短已编码串递归筛查未编码长串
.\venv312\Scripts\python.exe tools\build_recursive_composition_model.py

# 6. 对全部已编码候选执行 R0-R5 动态覆盖验收
.\venv312\Scripts\python.exe tools\evaluate_dynamic_candidate_coverage.py
```

来源或单字读音发生变化并需要进入运行库时，还应走正式 prototype 单字导入和运行刷新链；不得直接
删除 SQLite 中的个别运行行。

## 持续优化（不再作为 Phase 4.3 未完成项）

无 BCC 条目的同频长尾也不再挂作未完成清理：运行排序已经实现 BCC 主证据、
RIME-LMDG 缺失补充、静态效用非频次保底的严格分层。详见
[候选排序证据与长尾结构](CANDIDATE_RANKING_EVIDENCE.md)。新增独立语料只替换临时证据，
不会反写 BCC，也不会重新打开删除式“噪声清理”。

2026-07-28 全量报告已经为 2,441,908 个已编码字串逐一分层：R0 0、R1 4,798、R2 1,397、
R3 60,312、R4 2,054,255、R5 321,146，完成门禁通过。R1–R3 是动态核心的持续改进队列，不是
删除队列，也不使本项重新变为“待做”。

后续迭代按收益处理：

1. 为 R1 找最小可复用部件或构式；
2. 为 R2 补齐缺失读音覆盖；
3. 为 R3 评估中间部件、搜索宽度或有界缓存并做排序回放；
4. 持续验证 R4 的动态服务质量和 R5 的静态保留理由。

同时维护运行与发布回归：

1. 保持纯净 Windows 用户库连续积累开发文本，周期性记录冷启动纠正、重复首选、重启保持和用户库
   增长；
2. 对 `lexicon-promotion-scan` 发现的高频缺词做跨周期审核，避免把单人误选直接提升为系统词；
3. 扩大医学、生物、化学、姓名、地名、古籍及扩展区汉字的硬失败样本，优先检查“根字符/读音缺失”
   而不是完整长词是否预装；
4. 固定旧大词库安装泄漏、反查核心优先级和全新用户目录部署回归；
5. 继续保存早期容量档作离线对照，但不再把它们描述为当前 Windows 默认方案；
6. 获得真实用户遥测后，再校准产前99%估计和公共词条晋升阈值。

候选整理工作的最终交付不再是覆盖全部来源字串的人工分类表，而是分层输入架构的训练、回放和容量
证据：来源全集用于基础解码门禁和测试；可恢复材料进入动态组合回放；用户真实选择进入个人学习；
上下文转移先用本地数据模拟语义排序，将来可由远程排序服务替换。具体边界见
[分层输入架构迁移](LAYERED_INPUT_ARCHITECTURE.md)。

路线的核心不是给四百多万字串逐一贴上“词/非词”二元标签，而是建立一套能够保存不确定性、区分
来源事实与发布决策、并用动态恢复逐步替代冗余静态组合的输入模型。

第二批审查入口为 `tools/export_second_batch_bcc_review.py`；语料输入变化后，以重新生成的 manifest 为准。
