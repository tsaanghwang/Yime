# Yime 独立输入法工具栏子系统实施方案

## 1. 定义

本功能称为“独立输入法工具栏子系统”，不是候选框组件，也不是候选框的扩展区域。

子系统由三部分组成：

1. `input-toolbar.exe`：独立的 Go/Win32 浮动工具栏进程；
2. 工具栏状态同步模块：在工具栏与 Yime Go 后端之间同步输入状态和控制意图；
3. Unicode 提交桥：后续由 PIMETextService/TSF 把工具栏选中的 Unicode 字符提交到原编辑器。

## 2. 强制边界

- 工具栏和候选框必须使用不同的窗口、进程边界和生命周期。
- 候选框随预编辑出现和消失；工具栏由用户独立打开、关闭和移动。
- 候选框关闭、翻页、组句结束或尺寸变化不得影响工具栏。
- 工具栏关闭、移动或点击按钮不得清空预编辑、改变候选框尺寸或接管 Rime 候选分页。
- Unicode 字符面板不得复用候选框，不得把无拼音字符混入普通拼音候选分页。
- Yime 后端是输入状态的真实来源；工具栏显示后端确认的状态，不维护第二套互相矛盾的输入状态。

## 3. 状态模型

第一阶段同步以下状态：

- 中文/英文；
- 半宽/全宽；
- 中文标点/英文标点；
- 简体/繁体；
- 当前输入方案（只显示，为以后扩展保留）。

状态文件位于用户 Rime 目录：

`%APPDATA%\PIME\Rime\yime_input_toolbar_state.json`

状态文件使用原子替换和进程间锁。工具栏写入明确的目标值而不是“翻转一次”命令，使多个编辑器会话最终收敛到相同状态。Yime 在每次 PIME 请求开始前读取新版本，在请求结束后只在真实状态发生变化时发布新版本。

该文件只保存 Yime 自身的 UI 状态，不读取、写入或修改 PIME 安装目录。

## 4. 分阶段实施

### 第一阶段：独立工具栏和基础双向同步

- 在“设置”菜单增加“输入法工具栏（开）/（关）”；
- 构建并安装独立的 `input-toolbar.exe`；
- 工具栏标题为“音元”，包含中英、全半、标点、简繁、Unicode 字符、指法练习和设置按钮；
- 标题栏不显示关闭按钮；“设置 → 隐藏”只隐藏工具栏，语言栏菜单可重新显示同一进程；
- 新状态默认垂直排列并出现在屏幕右侧上下居中；“设置”按钮提供定制显隐、垂直/水平、隐藏、候选设置和 Windows 系统设置；
- 工具栏根据可见按钮总宽度或垂直堆叠高度自动调整窗口尺寸；
- 键盘、语言栏或设置菜单产生的状态变化动态反映到工具栏；
- 点击工具栏状态按钮写入明确的目标状态，并在当前编辑器下一次输入请求前应用；
- 工具栏关闭不影响候选框和预编辑；
- 为菜单点击路径、状态文件完整性和构建打包增加回归测试。

### 第二阶段：即时控制通道

- 在 Go 后端和工具栏之间增加用户级、单实例、可验证来源的本地 IPC；
- 工具栏命令不再等待下一次键盘请求；
- 新编辑器激活时发送完整状态快照；
- 断线重连后重新查询真实状态；
- 保留状态文件作为启动快照和故障恢复手段，不把它当高频消息队列。

### 第三阶段：Unicode 字符面板

- 工具栏的“字符”按钮打开独立 Unicode 窗口；
- 支持码位、区段、字符名称、部首、笔画、部件和常用分类检索；
- 使用固定版本的 Unicode Character Database/Unihan 数据并记录来源；
- 正确处理增补平面字符、组合序列、表情序列和异体字选择序列；
- 不伪造拼音，不改写 Yime 的正式音节编码词典。

### 第四阶段：TSF 原生提交

- 保存点击工具栏前的活动 TSF 编辑上下文；
- 通过受控的 PIMETextService 编辑会话提交所选 Unicode 字符或字符串；
- 最终路径不得覆盖剪贴板，也不得依赖模拟按键；
- 分别验证 x64 记事本、Codex IDE 和 x86 SysWOW64 charmap。

## 5. 验收标准

- “输入法工具栏（开）/（关）”文字与独立窗口真实状态一致；
- 工具栏和候选框能够分别显示、隐藏和移动；
- 中英等状态无论由键盘、语言栏还是工具栏切换，最终显示一致；
- 新打开的编辑器继承用户最后明确选择的状态；
- 候选框的 `⇧1` 至 `⇧9` 标签和 Rime 原生分页不发生变化；
- 工具栏菜单点击路径不会导致宿主退出；
- 构建、安装、签名清单和已安装运行时核验均包含 `input-toolbar.exe`；
- Unicode 阶段覆盖 BMP、`U+20000`、表情序列和异体字选择序列。
