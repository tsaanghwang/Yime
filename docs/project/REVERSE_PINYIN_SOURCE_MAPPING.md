# 同编码不同拼音反向映射

## 问题性质

Yime 为减少音元数量，有意让少数不同拼音共用同一音元序列。这不影响正向输入，
但单凭候选文字和键位序列不能总是唯一还原规范拼音。该现象是有意设计的多对一映射，
不是编码表错误，也不应通过拆分音元来消除。

当前等长码共有 9 组合并关系；投影到等长、变长、省键三种模式后，审计报告中表现为
27 组模式级歧义：

- `e1/o1`、`e2/o2`、`e3/o3`、`e4/o4`、`e5/o5`；
- `me1/mo1`、`me4/mo4`、`me5/mo5`；
- `le5/lo5`。

`ong/ueng`、`eng/ong`、`e/ê`、`ing/iong` 当前并不构成同一等长码，不能据名称相近
写入本附表。

## 数据与生成

运行时附表为
`go-backend/input_methods/yime/data/yime_pinyin_reverse_source.tsv`，字段为：

| 字段 | 含义 |
|---|---|
| `text` | 候选字词 |
| `source_full_code` | 生成时的等长码，仅用于证据和覆盖校验 |
| `numeric_pinyin` | 原型规范读音真源中的数字调拼音 |
| `marked_pinyin` | 同一真源中的调号拼音证据 |

附表不人工逐项维护。`yime-reverse-pinyin-derive` 同时读取编码表、等长运行词典和原型
`lexicon_source_bundle/entries.tsv`，只保留含歧义音节的运行词条。当前生成结果覆盖
41,849 个“候选文字 + 等长码”项，共 41,850 条读音记录；多出的 1 条说明同一候选和
同一码确有两个规范拼音，附表必须允许一对多，不能强行挑选一个。

生成器遇到任一歧义候选无法在规范读音真源中复原时会失败，不会静默生成残缺附表。
导入脚本把 `entries.tsv` 和附表的 SHA-256、附表行数写入
`yime_core_source_manifest.json`。

## 运行时规则

1. 附表保存数字调拼音；加载时根据当前布局编码表分别投影到等长、变长、省键模式，
   因而换键位布局不需要改写真源。
2. 反查命中“候选文字 + 当前模式编码”时，返回附表中的一个或多个真实拼音。
3. 候选框选择“标准拼音”注释时，也优先使用同一附表；多读音用 ` / ` 并列。
4. 附表缺失或当前候选不在歧义范围内时，保留原有确定性逆映射作为兼容回退。
5. 附表属于安装时共享只读数据。运行时只读取它，不写 PIME 安装目录、用户词典或
   原型数据库。

该补救层只恢复已经在正向映射中丢失的拼音来源，不改变候选编码、规范词典读音、
三种输入模式规则，也不参与语流音变候选生成。
