## 发布阶段与保留范围

1. 并列试验：保留生产 Rime/PIME 注册、安装与默认输入法；试验栈使用独立 CLSID、TIP、目录和用户数据。不因为自动化选不中任务栏按钮而更改默认输入法。
2. 首次独立发布：完成发布门禁并获明确批准后，才提交默认切换操作。至少一个稳定发布周期内保留源码中的 RimeAdapter、旧安装器和可校验的旧发布包；默认切换不等于删除旧组件。
3. 后续退役：稳定周期结束后另行评审卸载、数据保留期和删除范围。任何用户数据删除必须单独授权，不随升级或回退执行。

“保留回退包”是保存独立的已校验安装介质、manifest 和证据，并不要求升级器无限保留 Program Files 中全部非活动目录。成功升级后，旧试验安装目录可能按既有事务流程清理；不能把这些目录视为可靠备份。

## 演练前置资料

- 记录 Windows SID、宿主位数、OS、实际默认输入法与语言列表，不根据可见图标推断活动 profile。
- 保存生产和试验 COM 的 x64/x86 值、TIP/profile、Run 和卸载项的实际值及类型，以及运行进程路径、PID、启动时间、runtime config 和状态。
- 保存当前与回退目标安装包的 manifest、载荷哈希、签名状态和可复现的源码身份；不得仅按目录修改时间选包。
- 在停止相关写入后制作一致的用户词库、学习 snapshot/journal 和设置备份，记录格式版本。运行中任意复制 snapshot 与 journal 不构成一致性证明。
- 生产 Rime 与 YimeCore 学习格式不同，不宣称它们可以直接互换；回退保留两套数据，不将新栈学习文件覆盖进生产 Rime 用户目录。
- 列出预期变更的精确试验路径/注册项、恢复命令、人工验收步骤与负责人；演练选择隔离环境或获明确批准的窗口，不自动操作开发机生产注册。

## 两种回退必须分开验证

| 路径 | 验证重点 | 不能替代的证据 |
|---|---|---|
| 试验包 A 升级 B 失败后事务恢复 A | 完整 staging 后才处理旧安装；恢复 COM/profile、TIP、Run/卸载值类型、config 和原运行状态；保护旧目录和用户数据 | 不能等同于最终独立版回退生产 Rime/PIME |
| 独立版回到保留的生产输入法 | 先确认生产安装与注册可用；经批准选择生产 profile；真实宿主输入通过；新栈数据保留；重启后再次核对 | 不能仅由 mock、PE 静态检查或并列包正常升级推断通过 |

原试验安装器仍只管理试验产品身份。最终独立产品身份若有变化，必须另行审查迁移/回退脚本，不能直接套用试验版卸载命令。

## 验收与中止条件

- 新开 Word 等目标宿主，明确选择目标输入法后，记录实际加载的 DLL 路径和哈希；再验证中/英切换、语言栏左右键、组合/提交、裸数字组字与 `Shift+1` 至 `Shift+9` 选词。
- 英文模式的 `Shift+字母/符号` 不得在释放后意外切回中文。注册宿主测试与人工真实任务栏验收分开记录，不能互相冒充。
- 测试后及重启后分别核对 Run 的实际路径、类型和包身份；仅看到新 runtime 正在运行不足以证明下次登录自启动正确。
- 一旦发生生产注册被改写、错误 SID、数据丢失、写入失败或回退目标无法启动，立即停止后续切换/清理，保留证据，按已审查步骤恢复。不强杀 Explorer 或强删被宿主加载的 DLL。
- 此前进程隔离视图掩盖系统 Run 陈旧值的问题已修复并经过真实登录自启动验收；22:21 的原生事务回退另证实系统 Run/卸载/用户 TIP 可恢复。不要再用早期进程视图记录推翻较新的独立系统证据。
