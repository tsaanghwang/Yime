# Yime 仓库数据边界

状态：已启用；默认拒绝跨仓读取。

## 边界

Yime 是编码、词库、布局、评估和 Windows 交付的唯一产品仓库。旧 Python 原型可以保留，用于清理
自身数据、核对历史现场和准备候选导出，但原型的提交、工作树、数据库、生成目录和环境变量均不是
Yime 的输入。原型发生任何修改，都不会自动改变 Yime。

同样的边界适用于 `RIME-LMDG`、历史键盘布局仓库及其它 Git 工作树。这里限制的是数据导入；CMake、
Go、Rust 等按版本锁定的源码依赖继续由各自构建门禁管理。

## 正常数据流

```text
外部来源或清理工作区
  -> 明确授权的一次性转移
  -> 不属于任何 Git 工作树的只读归档
  -> SHA-256/大小锁定与恢复演练
  -> YIME_LEXICON_EXTERNAL_ROOT 指向的独立工作副本
  -> Yime 来源、编码、词库和发布门禁
```

`external_inputs.lock.json` 只保存稳定 ID、归档相对路径、大小和 SHA-256，不保存原型路径、其它仓库
路径或回退位置。没有外部根目录时工具直接失败；符号链接、junction 和路径规范化后的真实目标也要
接受仓库边界检查。

## 两种可重现级别

| 目标 | 仅克隆 Yime | 额外前置 |
|---|---:|---|
| 构建、测试、安装和运行已批准词典 | 是 | 编译器和平台 SDK |
| 重放已批准的固定交接并派生三种模式 | 是 | Python、Go |
| 从原始 BCC/Unihan/字符库/万象证据重建来源数据库 | 否 | 锁定的独立证据根和恢复演练证据 |

第三项不能通过把大型原始来源塞回 Git、搜索同级仓库或跳过校验来改成“是”。这是证据保管边界，
不是对旧原型的依赖。普通 CI 不要求 `YIME_LEXICON_EXTERNAL_ROOT`；发布级来源重建和涉及来源变化
的维护操作必须要求它，未设置时失败是预期门禁。

## 临时例外

确有必要直接读取其它仓库时，必须同时满足：

1. 已有明确的用户或审查授权，并记录可追踪的授权引用；
2. 在 `tools/data_import_approvals/` 添加 JSON，写明来源仓库根、必要性、批准人和精确输入 ID；
3. 批准有效期不超过 31 天，不允许通配符；
4. 数据仍通过原有内容哈希、来源合规和语义审查；
5. 完成一次性转移后删除活动批准，后续只读独立归档。

命令行开关、环境变量、同级目录搜索、旧绝对路径或“文件存在就使用”的逻辑均不构成批准。

## 强制门禁

- `yime.repository_boundary.assert_data_source_allowed`：Python 数据入口的运行时门禁；
- `tools/assert-data-source-boundary.ps1`：PowerShell 核心词典导入门禁；
- `tools/lexicon/check_repository_data_boundary.py`：扫描锁文件、功能代码和活动批准；
- `tools/lexicon/test.ps1` 与 CI：每次离线工具验收都执行上述静态门禁；
- 回归测试：验证无外部根失败、`legacy_path` 失败、其它 Git 仓库失败，以及精确限时批准仅放行指定输入。

不得为了让某次导入通过而删减这些检查；应先把数据转移到独立归档，或按临时例外流程取得批准。
