# CI 并行分片

影响面：CI 调度及测试工具；不修改已交付的共存候选、产品运行时或实机验收结果。
本项在共存候选 `097cf2d2` 提交并推送后开展。先保留其独立 CI，再推送本次调度优化，避免取消测试机交付的验证。

## 拆分依据

基准为成功运行 [34546499233](https://github.com/tsaanghwang/Yime/actions/runs/34546499233)：全程约 50 分钟。
real-Rime 为 13 分 48 秒，nsis-preflight 为 7 分 39 秒，普通合同为 22 分 12 秒；安装事务 PS5 为 28 分 55 秒，PS7 为 22 分 30 秒。
六个旧长合同任务已经并发，瓶颈来自各任务内部的串行用例。

## 新调度

- real-Rime：动态枚举全部顶层测试，按稳定名单分成 3 片。每项测试的三模式子测试保持完整；每片使用独立 Windows runner 和进程。
- 普通合同：39 个原步骤分为 core（5）、package（7）、maintenance（27）三组；原有步骤正文及双 shell 调用保留。`tools/ci/contract-test-lanes.json` 固定归属，廉价门禁拒绝遗漏、重复和错误条件。
- 安装事务：完整声明名单按序分 3 片，PS5/PS7 各执行三片。receipt-store 和 evidence-archive 保持各自完整双 shell 套件，总计 10 个长合同任务。
- shard-coverage：收集 3 个 real-Rime 和 6 个事务结果，核对提交、脚本原始哈希、分片序号、声明名单与实际通过名单，要求完整并集且无重复。全部通过后才能继续 installer-payload 和最终 core-build。

每个事务分片仍返回 `full_suite_executed=false`，不能单独冒充完整事务矩阵。新的汇总证明仅为 CI 测试覆盖，不提升 installed acceptance。
real-Rime 不仅要求 `go test` 退出为零，还核对 JSON 中每项被分配测试都确实通过，不能用空测试匹配或跳过代替执行。
新增测试自动进入动态分片；新增普通合同步骤必须更新固定归属表。所有矩阵仍使用 fail-fast，保留源头廉价门禁和现有失败/取消/跳过传播规则。

## 验证和后续测量

本地 real-Rime 三片全部通过，分别约 170.5、148.4、161.3 秒。这些是开发机数据，不能直接作为 GitHub runner 提速结果。
本地九份实际结果经汇总器核对通过：real-Rime 共 35 项，安装事务 PS5、PS7 各 47 项（每种 shell 分为 16、16、15 项），无遗漏或重复。39 个普通合同步骤去除分组条件后，与交付提交的正文逐字一致。
调度变异测试、覆盖缺片/重复/失败/旧来源拒绝测试、原有双产品源码合同和 actionlint 用于保护拆分后的门禁。
首次完整新 CI 的总时长还受 runner 配额、排队、checkout 和缓存影响；不能按原时长机械除以三。
暂不削减 nsis-preflight、真实 Rime 三模式覆盖、PS5 兼容性、事务故障恢复或签名/制包门禁。
