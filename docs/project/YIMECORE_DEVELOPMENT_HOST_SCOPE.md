# YimeCore：本开发机 x64 优先阶段

生效日期：2026-09-02。依据用户决定，本阶段优先于历史试验计划中的多架构、多机型验收要求。

## 范围

- 唯一活动目标：本开发机 `MYCOMPUTER`，原生 Windows x64（本次决策时为 i9-13900K）。本机结果不自动代表所有同型号或同档次机器。
- 冻结：ARM64、x86（包括本机上的 32 位宿主）、老旧 x64、其他主流/超前实体机，以及硬件分档模拟。暂不租云机器、不添置测试机，不以这些证据缺失阻塞本机开发。
- 解冻：本机独立核心完全可用后，另行评审和批准恢复其他目标；不自动解冻。老旧档不因此自动重新进入支持范围。
- 签名证书正在申请，等候审批，暂缓相关事项。

## 默认流程

`tools/yimecore/development-scope.json` 是范围配置；共同入口核验机器名、原生架构和 64 位 PowerShell，构建入口另外拒绝非 `windows/amd64` Go 目标。

1. `Upgrade-YimeCore-Trial.cmd` 经 v3 入口只重建 x64，安装后只执行 x64 注册宿主测试。保留既有 staging、同 SID 提权、事务回退、自启动修复和最终只读复核。
2. E6-C 基包仍须完整校验。x86/ARM64 载荷按基包哈希原样带入，manifest 记录冻结来源；不重新编译，不执行其测试，不宣称与新核心兼容。保留文件是为了现有安装维护/回退契约，不是继续适配。维护器仍可管理已有试验注册；生产 Rime/PIME 不变。
3. E6-D 只要求活动 x64 COM/runtime 收敛。对全部留存载荷做完整性/依赖静态审计、读取两种注册视图用于生产保护，不等同于被冻结平台的兼容验收。
4. 性能入口保留原文件名 `run-yimecore-tier-performance.ps1`，但只运行 `development_host_x64` 自然调度测量，不施加 CPU 配额或固定亲和性。保留原 50/100 ms 交互预算；单进程内存预算为原高配档的 1536 MiB。三种编码模式的 E1/E2/E3 覆盖仍必须完整。
5. E7 输出本机里程碑状态 `ready_for_development_host_milestone`。冻结项列入 `deferred_checks`，`passed=null`，不是通过；旧未标范围或双档模拟证据不能冒充当前证据。`ready_for_cutover_proposal` 不因本机通过而自动变为 true。

历史多架构脚本、模拟工具及 x64/x86 测试源码保留，但当前不运行历史入口绕过范围配置。不修改历史验收记录来制造“新范围全部通过”。

## 本机仍须完成

- 当前包/源码身份、独立依赖、COM/runtime、自启动及重启后收敛。
- 本机原生 x64 宿主功能：明确选择试验输入法，再核验 DLL、语言栏、组合与候选提交、裸数字组字、Shift+1…9、英文 Shift 组合，以及更多本机宿主应用。
- 用户学习、词库、设置等功能的数据安全；升级失败恢复、数据备份及经批准的本机回退演练。
- 完成本机独立产品的安装/维护闭环；保留方案和生产切换需要明确批准。本阶段范围调整不是卸载 Rime/PIME 或更改默认输入法的授权。

真实任务栏能人工操作但 Computer Use 不能向独立任务栏发输入，是自动化限制，不能重新列为产品阻塞。Word 未主动选择试验输入法也不算失败。
