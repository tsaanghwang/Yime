## 前一轮结束时的具体缺口（后续完成范围见上方更新）

1. **正向来源链。** 当前历史 `particle_a_stage6d.go` 会扫描生成的全码 Rime 词典，并经编码反查拼音及音元元组。该实现本轮只读检查、没有执行生成；它不能充当当前要求的“规范词条读音 → 四音元 → 布局 → 三模式别名”的正向来源证明。不得借重新生成之名恢复反向推导，也不得主动读取其他 Git 仓库补数据。
2. **三模式严格不增码。** `report.go` 的 `modeLengthProjectionValid` 只检验音节位置及模式形状，历史测试还明确接受变码/简码增长。它的 PASS 与本轮 SR0 可达性均不等于 `alias_length <= canonical_length`。旧 manifest 没有覆盖全部层的、与当前规范/布局绑定的逐条两路线码长证明；旧审定表的 `delta` 也不能代替独立重算。
3. **当前 Broker 接线。** `cmd/yimebroker/main.go` 的多模式 builder 当前取专业词库模块；本轮没有加入语流模块 manifest 加载、启停配置或持久化事务。核心索引与模块集合/哈希必须作为同一不可变代际管理，不能通过闭包捕获可变模块列表使旧会话悄然换源。

这些是重新接入的工程/证据缺口，不是已安装 local.12 新出现的输入故障。本轮没有修改旧研究判定以伪造新准入，也没有新增音变规则或运行时推断。
