# 普通话语流音变的编码输入实现

> 文档性质：实施前准备方案
> 当前状态：准备阶段 P 至阶段 3-3 已完成离线审计、分层试验、简单轻声全量临时包和统一语境调层—质层假设模型；尚未接入正式语流音变运行时
> 初始记录：2026-07-29；转入准备阶段：2026-08-02
> 当前阶段：阶段 3-3 已建立调层与质层共用的有界、非递归偏序规则图和冲突表；全部类别仍为 `research_only`
> 总原则：规范读音是真源；语流读音只形成有来源、可撤销的附加输入路径

## 1. 目的

音元输入法使用带调音节编码。用户在连续说话或默念句子时，脑中出现的往往是语流中的实际读音，
不一定是词典记录的规范读音。支持常见语流音变，可以减少用户在输入前把实际读音还原为词典读音
的负担。

本文所称“编码输入实现”，是为经过审定的语流读音准备附加输入编码，使用户能够按照语流音变后的
音节编码输入对应的规范汉字。它不是把语流读音改写成规范读音，不是修改单音节基础编码，也不是
语音合成、语音识别或声学模拟。

与普通拼音输入法不同，Yime 的语流音变不需要增加音节位置或追加特殊标记。每个规范音节已有
“首音—呼音—主音—末音”四个音元位置；变调、轻声、儿化及其他音变可表达为这四个位置内部的
音元等位替换，主要改变音元调级或音质。完整等长表示仍保持四个音元。

本方案统一规划以下现象：

1. 变调；
2. 轻声；
3. 儿化；
4. 其他语境音变，包括语气词的音变、音节间的同化和异化等。

本工作已从长期备忘转入实施前准备阶段。由于可信代码签名条件短期内尚未具备，当前等待期用于
收口数据格式、来源和例外、接口边界、离线审计要求、回归样例与回退方案。准备阶段不生成或安装
运行别名，不修改三模式系统词典，不迁移用户数据；只有准备阶段的退出条件全部满足并经评审后，
才另行启动第一批程序实现。

《普通话水平测试大纲》把变调、轻声、儿化列为多音节语音能力，并在朗读中考查连读音变；
《汉语拼音正词法基本规则》则要求规范拼写一般保留本调。这两条共同构成本方案的设计依据：
规范形式保持稳定，语流形式作为附加入口。

## 2. 三层数据模型

### 2.1 规范读音层

规范读音层继续承担唯一真源职责：

- 核心候选的规范数字标调拼音；
- `yime_pinyin_codes.tsv` 的音节编码映射；
- `pinyin_normalized.json` 和“标准拼音”候选注释；
- 三模式系统词典、用户词库、学习迁移和反查的稳定身份；
- 词典哈希、来源证据和可重复构建。

任何语流音变功能都不得直接修改这层数据。

### 2.2 语流读音层

语流读音层描述某个已知词或短语在特定条件下可以怎样读：

- 每条记录必须指向规范文本和规范拼音；
- 必须标明音变类型、适用范围、规则或来源；
- 必须区分词汇固有读音、常见语境读音和自由口语变体；
- 不确定、地域性或强烈依赖语气的读音不得默认启用；
- 涉及词界、句法或韵律边界时，必须显式记录边界条件。
- 面向机器的最终表示不是任意拼音字符串，而是规范四音元到语流四音元的等位替换。

语流读音层内部再区分“来源观察”“稳定兼容表示”和“可选语流实现”。原始材料中的词形、注音、
空格、撇号以及 `r`、`er`、`ér` 等形式必须原样保存；转录校正、语音解释和编码决策另设字段，不得
静默覆盖来源记录。pypinyin、万象、BCC、PSC 注音材料和审音表各自使用独立的来源解释政策，不能
用一套无调或儿尾规则机械归一。

稳定兼容表示保证既有候选始终可输入；可选语流实现则在证据充分时增加更接近实际语音的并行入口：

- 轻声以数字调 `5` 和现行三个中调乐音序列作为兼容表示，可另行派生有语境证据的表层调值别名；
- 儿化先以“基础音节 + 轻声儿 `er5`”作为儿缀兼容表示，再从同一结构化记录派生融合卷舌别名；
- 两条路径映射到同一候选文字，兼容路径不得因语流实现成熟而被删除；
- 语流实现关闭或删除后，稳定兼容路径、规范注释、反查和用户数据必须保持有效。

所谓“从儿缀还原儿化”不是从扁平键码中删除 `er5`。记录必须另存基础音节、附着位置、儿化身份、
文字中的“儿”位置和来源证据；融合路径据此重新派生，只在基础音节自身的四音元位置内进行音质或
调级替换。儿缀码与融合码是同一来源记录的两个并行产物，不是相互覆盖的规范读音。

### 2.3 输入别名层

输入别名层把审定后的语流读音转换为 Yime 可接受的附加编码：

- 别名必须绑定到完整词或短语，不得改写单字基础编码；
- 同一候选始终保留规范读音编码；
- 每个音节的语流等长表示仍为四个音元，只允许替换，不允许插入或删除位置；
- 别名必须从替换后的四音元记录同时派生变长、等长、省键三套编码；
- 等长模式每音节固定四码；变长和省键从音变后的四音元重新派生，每音节允许在 `2—4` 码内
  增加、减少或不变，不把确定性派生造成的增码误判为失败；
- 不为同一候选的语流别名另造词频权重：三模式中都有精确规范词条时继承其原权重；三模式均无
  精确词条、原候选由 Rime 动态组句产生时，保留动态评分并转入动态候选实现路径，不为物化别名
  编造固定权重；只有三模式部分缺失或既有权重互不一致时才拒绝生成并进入人工复核；
- 删除输入别名层后，核心词典和用户数据仍应正常工作；
- 语流规则不能进入按键解释逻辑，不得让按键含义随上下文改变。

### 2.4 四音元等位替换层

语流音变的核心中间表示为固定四位置元组：

```text
[首音, 呼音, 主音, 末音]
```

规则作用于元组中的一个或多个位置：

```text
规范四音元
    -> 按上下文替换指定位置的音元调级/音质
    -> 语流四音元
```

基本不变量：

- 输入和输出的音节数相同；
- 每个音节输入和输出都恰好有四个位置；
- 规则只能替换位置内容，不能插入第五个音元或删除既有位置；
- 首音若发生同化，也只能在首音位置等位替换，不能破坏音节边界；
- 每次替换必须记录位置、原音元、目标音元、改变的属性和规则 ID；
- 调级替换与音质替换可以组合，但必须有固定顺序和冲突检查。

儿缀兼容路径和融合儿化路径是同一结构化来源记录的两个并行实现，不把前者作为后者的四音元改写
输入。因此“音节数不变”约束分别作用于每条路径内部的音元替换；不得通过删除儿缀路径中的 `er5`
位置来伪造融合结果。

规则应作用于稳定的音元 ID 和属性，而不是直接作用于当前 QWERTY 键。当前布局仍有部分音质、
调级语义通过 ASCII 键组表达；正式实现前应完成“稳定音元 ID/属性—可替换键位投影”的边界，
避免布局变化改变音变规则。

三模式派生顺序固定为：

```text
规范四音元
    -> 语流音变等位替换
    -> 布局键位投影
    -> 等长/变长/省键派生
    -> 码长与碰撞门禁
```

等长模式天然保持每音节四码。变长和省键必须从替换后的四音元重新派生，并逐音节验证处于
`2—4` 码范围。音变可能改变相邻同音元合并和中调省略条件，因此码长增加、减少或不变都属于正常
结果；门禁检查确定性、范围和报告完整性，不按增减方向裁决读音。

## 3. 不可回退的总边界

1. 不把语流音变写回核心等长词典真源。
2. 不修改 `yime_pinyin_codes.tsv` 中规范音节到编码的一一对应关系。
3. 不把语流读音显示成“标准拼音”。
4. 不为同一个单音节建立依赖后续按键的基础编码。
5. 不先接通某一种 schema，再把另外两种留作以后补齐。
6. 不把词汇固有轻声推广成任意语境轻读规则。
7. 不把带“儿”字的文本和不带“儿”字的文本无条件互换。
8. 不把语气词的实际读音直接当成候选汉字替换规则。
9. 不把渐变、可选或地域性的同化、异化现象默认转换成键盘别名。
10. 不在缺少来源、碰撞报告、真实 Rime 回归和安装态验证时默认启用新模块。
11. 不使用 LLM 在运行时猜测词界、语气、韵律或实际读音。
12. 不人为追加音变标记、后缀或额外分隔符；三模式码长变化只能来自四音元重新投影。
13. 不绕过固定四音元层直接把“语流拼音字符串”翻译成临时键码。
14. 不把音质或调级规则绑定到不可替换的物理键位。

## 4. 统一术语

| 术语 | 本方案中的含义 |
|---|---|
| 规范读音 | 词典、规范拼音和核心词典记录的稳定读音 |
| 语流读音 | 连续言语中受相邻音节、词法、句法、语气或韵律影响的实际读法 |
| 词汇固有 | 已成为具体词语读音组成部分，应由词条明确记录 |
| 语境音变 | 只有满足上下文条件才出现的读音变化 |
| 来源观察 | 原样保存某一来源的词形、注音、符号、位置和转录状态，不包含工程判决 |
| 稳定兼容表示 | 保证既有候选可输入的内部表示，例如轻声 `5` 和儿缀 `er5` |
| 可选语流实现 | 根据来源和语境派生、可单独关闭的表层轻声或融合儿化输入路径 |
| 输入别名 | 不改变候选文本和规范读音，仅增加一条可接受编码 |
| 等位替换 | 在四音元固定位置内替换调级或音质，不增删音元位置 |
| 强规则 | 条件明确、例外可列举、可确定性生成 |
| 弱规则 | 可选、渐变、地域性或依赖语气，只能审定收录或用于研究 |

## 5. 模块一：变调

### 5.1 “一、不”变调

这是最适合首先试验的强规则模块。

初始可审定规则：

- “一”在四声前可接受 `yi2` 语流别名；
- “一”在一、二、三声前可接受 `yi4` 语流别名；
- “不”在四声前可接受 `bu2` 语流别名；
- 其他情况保持规范读音，除非审定清单明确列出。

上述条件只用于筛选待审短语，不能直接当作运行时生成器。阶段 2A 盘点发现，现行词典已经直接保存
部分语流读音，例如“一定 `yi2 ding4`”“一天 `yi4 tian1`”“不对 `bu2 dui4`”；这类词条不再
重复生成别名。只有现行直接词典路径确实缺失、来源可追踪且三模式投影逐音节保持 `2—4` 码的完整
短语读音，才进入离线别名试算。

第一版只使用完整词或短语的显式审定清单，不自动处理：

- 单念、词尾或数字串中的“一”；
- 序数“第一”等保持本调的结构；
- “看一看”等可能轻读的重叠结构；
- `A不A` 中可能轻读的“不”；
- 跨词、跨分句和依赖重音的情况。

### 5.2 上声变调

上声变调比“一、不”更依赖词界和韵律边界，应独立立项：

- 先覆盖词典明确的双音节词；
- 三个及以上连续上声必须记录韵律切分，不得只看相邻数字声调；
- 不跨未知词界自动生成；
- 不改变标准拼音注释；
- 必须验证变调别名不会压低规范路径的首选稳定性。

### 5.3 “七、八”等可选变调

“七、八”不得与“一、不”按同一优先级处理，也不得建立“第一声遇四声一律变二声”的全局规则。

若后续加入，只允许：

- 有规范语音资料或人工审定依据的固定词；
- 作为可删除的词组级别名，并继承同一候选规范路径的原权重；
- 单独统计使用收益和新增碰撞；
- 证明有价值后再扩大范围。

### 5.4 语法、重音和语气引起的调值变化

焦点重音、语气强调和句末语调可能改变实际调值，但不一定改变音系声调类别。初期不得把调值连续
变化离散成新的数字标调音节。此类现象先保留为研究数据，不进入编码别名。

## 6. 模块二：轻声

轻声必须拆成两类。

### 6.0 暂定工程表示原则

准备阶段及既有运行链把轻声视为一种有来源、依附于具体词语或语境的特殊读音类别。当前不选择下列
任何一种理论承诺：

1. 不强制为每个轻声音节追溯或补造一个属于阴平、阳平、上声、去声的深层本调；
2. 不把受前一音节、重音、语调等条件影响的表层调值直接固化为基础音节码或规范词典码。

数字调 `5` 及现行三个中调乐音（音元）序列暂时只承担稳定工程标识和兼容输入码职责。它不表示
“第五个固定声调”，也不声称等同于轻声的深层调类或实际表层音高。后续实现必须继续识别并兼容这套
表示，但不得据此改写规范拼音、候选文字、基础码表或既有用户数据。

只有在来源、词义或词位、适用语境、前接表层声调以及实测或规范音值证据均足够时，才可以在词语或
构式层设计轻声表层输入别名。此类别名仍须走固定四位置等位替换和三模式统一派生；不得反向修改轻声
身份，也不得强制补出深层本调。

轻声采用“兼容码常开、语流码可选”的双轨策略：现有 `5` 码继续保证按轻声身份输入；将来查明深层
本调时可作为可空的分析属性保存，但不据此取消 `5` 码；将来取得具体语境中的表层调值证据时，再从
同一词语或构式记录派生表层输入别名。找不到深层本调的少数轻声按显式例外处理，不得为了闭合模型而
猜造本调。

### 6.1 词汇固有轻声

词典明确的轻声属于规范词条的一部分，可继续使用数字调 `5` 或项目既有的无调标记处理：

- 逐项审计现有轻声词条和标准拼音显示；
- 确认三模式都能由同一轻声音节编码派生；
- 用户词库和反查保留轻声身份；
- 不因加入语流模块而把现有轻声改成普通本调。

这部分不是输入别名，而是规范读音层的既有能力。

### 6.2 语境轻读

语境轻读可能出现在：

- 结构助词、语气助词和某些后缀；
- 重叠式的后一个音节；
- `A不A`、动词重叠等固定构式；
- 高频口语词组中的弱读位置。

初步实现必须使用构式或词组清单，不能仅凭“高频虚词”或“非重读位置”全局改成轻声。

每条语境轻读记录必须回答：

- 候选文本是否不变；
- 规范读音是什么；
- 哪个音节轻读；
- 是否强制、常见可选或仅口语可见；
- 是否依赖重音、语速或句法结构；
- 是否允许作为默认输入别名。

### 6.3 轻声与变调叠加

“一、不”、上声变调与轻声可能同时出现在一个构式中。不得由多个模块无序重复改写。

需要统一的规则流水线和优先级：

1. 读取规范词条和结构边界；
2. 应用有词条证据的轻声或儿化身份；
3. 应用允许的变调规则；
4. 生成一个规范化语流读音；
5. 去重并派生三模式编码。

流水线顺序在实现前必须用反例验证，不能只凭直觉固定。

## 7. 模块三：儿化

儿化不仅改变读音，还可能涉及文本中是否写出“儿”，因此必须比变调更谨慎。

### 7.0 分阶段兼容策略

儿化先实现为“儿缀”，再可选实现为“融合儿化”。第一阶段复用既有轻声链，把经过审定的儿化词按
“基础音节 + `er5`”生成儿缀兼容输入，使朗读式、儿缀式或融合程度较弱的读法仍可稳定输入。该路径
是输入约定，不宣称 `er5` 就是实际儿化读音。

第二阶段根据同一来源记录中的基础音节、儿化附着位置和儿化韵类型，派生融合卷舌输入。融合路径不得
从扁平儿缀码猜测或删除音节，而要重新读取结构化特征，在基础音节的四音元组内完成等位替换。两种
输入路径可以长期并存并指向同一候选，以适应说话人的朗读习惯、口音和儿化融合程度差异。

统一来源数据库至少要区分：非儿化、独立 `ér`、儿缀兼容、融合儿化、文字未写“儿”的口语儿化提示
以及待定；同时记录基础音节索引、文字“儿”的位置、来源原始记号、正字法一致性、儿化韵类型、证据
位置和别名生成政策。单个 `is_erhua` 布尔字段不足以承载这些差异。

### 7.1 词汇化儿化

词典明确收录、意义或词性已经固定的儿化词，应作为有来源的完整词条处理：

- 规范文本是否带“儿”由词典和项目文本策略决定；
- 规范读音必须使用可逆表示，不能只保存听感近似拼音；
- 反查应能显示基础音节、儿化标记和最终输入编码；
- 三模式从同一儿化读音记录确定性派生。

### 7.2 能产儿化

临时、小称、口语色彩等能产儿化依赖词义、语体和地区习惯。初期不得对任意名词自动添加或删除
“儿”。

进入试验前必须先确定：

- 语流读音的内部表示，例如“基础音节 + 儿化特征”，而不是模糊字符串；
- 候选文本是原词、带“儿”文本，还是两个候选都存在；
- 输入儿化读音时是否只匹配显式审定的候选；
- 用户词库如何保存和导出；
- 备份恢复能否无损保留儿化身份。

### 7.3 儿化韵数据

传统语音描写中的儿化可能涉及韵尾变化、元音变化和卷舌特征；在音元模型中统一表示为既有位置内的
音质替换以及音质在时域中的延展或联结。第一阶段可以为经过审定的记录生成 `er5` 儿缀兼容码，
但不得把来源中的所有 `r` 无条件解释为 `er5`，也不得把兼容码冒充实际儿化读音。融合实现仍须建立
独立的结构化儿化韵数据。

需要先建立：

- 普通话儿化韵规范表；
- 基础韵到儿化韵的可逆或可追踪映射；
- 儿缀兼容路径与融合路径指向同一候选的交叉表；
- 特殊形式和不可自动生成清单；
- PUA 音元显示方案；
- 标准拼音、音元拼音和键位序列的显示约定。

在该数据格式完成前，不实现运行时儿化生成器。

## 8. 模块四：其他语境音变

### 8.1 语气词音变

重点包括语气词“啊”等受前一音节韵尾影响产生的读音变化，以及口语中已经形成不同书写形式的
“呀、哇、哪、啦”等。

这里必须区分：

- 同一个候选汉字的不同实际读音；
- 不同汉字但功能相关的语气词；
- 规范书写变体；
- 仅为语音过渡、通常不改变书写的变体。

输入法不得根据前一个音节擅自替换候选汉字。第一阶段只能建立“文本—规范读音—语流读音”的
显式审定记录。

#### 8.1.1 “啊”的顺行同化预案

语气词“啊”的实际读音主要受前一音节末尾音素影响，可先按顺行同化建立以下待审规则表。表中的
“常见书写”只描述材料中常见的文字对应关系；运行时仍必须匹配显式词语或构式记录，不得仅凭前字
读音自动把候选“啊”替换成“呀、哇、哪”。

| 前一音节末尾音素 | “啊”的语流读音 | 常见书写 | 准备期说明 |
|---|---|---|---|
| `a、o、e、ê、i、ü` | `[iᴀ]` | 呀 | 舌尖前、后元音另按下列专项规则 |
| `u` | `[wᴀ]` | 哇 | `ao、iao` 的末尾音素按 `u` 处理 |
| `n` | `[nᴀ]` | 哪 | 记录为后续音节首音位置的同化结果 |
| `ng [ŋ]` | `[ŋᴀ]` | 啊 | 文字通常不变，但语流首音发生变化 |
| 舌尖后元音 `-i [ʅ]`、`er` | `[ʐᴀ]` | 啊 | 卷舌类实现及其音标归并仍须专项审音 |
| 舌尖前元音 `-i [ɿ]` | `[zᴀ]` | 啊 | 文字通常不变，但语流首音发生变化 |

这组规则在四音元模型中表现为后续“啊”音节首音位置的等位替换，而不是给前一音节增码。现有首音
集合和布局应提前评估能否表达 `[ŋ]`、`[z]` 以及卷舌类 `[ɹ]`；其中 `[ɹ]` 与本表 `[ʐ]` 的工程归并
关系、名称和主要实现须在音元审音中确定。准备期只把它们登记为“语流派生首音候选”，不立即新增
正式音元 ID、PUA 字符或物理键位，也不把它们扩展为普通话规范音节的基础首音。

离线试算至少应证明：六类末尾条件互斥或具有固定优先级；零声母、拼音缩写和 `ao/iao` 的底层末音
分析一致；三模式从同一派生首音确定性生成；保留“啊”的候选和显式书写“呀、哇、哪”的候选不会
相互吞并或污染学习数据。

### 8.2 音节间同化

同化可能影响发音部位、发音方法、清浊、鼻化或其他语音特征，其中很多是连续、渐变且不改变
音系身份的自然发音。

只有同时满足以下条件才考虑输入别名：

- 在普通话中稳定、常见并有可靠资料；
- 能用离散、可重复的内部音节表示；
- 用户确实会据此形成不同键盘编码；
- 不会把个人口音或快速语流误当成规范规则；
- 候选收益大于新增重码。

否则只作为语音学研究记录，不进入键盘输入。

### 8.3 音节间异化

异化同样可能涉及词汇化、语境化或自由变体。处理原则与同化相同：

- 不建立无来源的全局音节替换；
- 优先收录固定词和高频构式；
- 保留规范读音；
- 与变调模块去重，避免同一现象在两个模块重复生成。

### 8.4 音质弱化、时域延展及其他口语缩约

音元模型不建立“增音”或“减音”操作。快速口语中听感上类似脱落、合音或缩约的现象，在本项目中
先分析为音质弱化或音质替换：相邻韵核音质可以延长并联结到相应时域，同时由该时域负载（承载）
并行的音高特征。四音元位置和音节结构始终不变；不能用这种方式解释的材料暂不进入编码模型。

只有在未来建立了可靠语料、规范化表示和明确用户需求后，才另立子项目；不得把模糊匹配、拼写
纠错或近音容错冒充语流音变。

## 9. 统一数据格式

版本 1 的格式真源为
[connected_speech_record.schema.json](connected_speech/connected_speech_record.schema.json)。阶段 0 可以
使用 JSON 记录，也可以使用以下 TSV 作为单来源观察的人工维护投影；数组和逐位置改写字段使用 JSON
文本保存，载入后必须通过同一 Schema 语义校验。

```text
yime_connected_speech_aliases.tsv
```

TSV 投影字段：

```text
schema_version
ruleset_version
record_id
record_revision
text
canonical_pinyin
source_observation_id
source_text_raw
source_reading_raw
source_policy
transcription_status
adjudication_status
compatibility_reading
surface_reading
underlying_tone
erhua_status
attachment_syllable_index
er_character_index
erhua_class
canonical_yinyuan_ids
compatibility_yinyuan_ids
surface_yinyuan_ids
rewrite_spec
feature_spec
candidate_text_policy
phenomenon
rule_id
scope
runtime_enabled
```

其中：

- `schema_version`、`ruleset_version`、`record_id`、`record_revision`：按收口包版本策略维护；
- `source_observation_id`：稳定指向不可变的原始来源记录和页码、条号或文件定位；
- `source_text_raw`、`source_reading_raw`：忠实保存来源词形和注音，不因工程判断而覆盖；
- `source_policy`：标识 pypinyin、万象、BCC、PSC、审音表等来源各自的符号和标调解释制度；
- `transcription_status`：区分原样转录、已校正转录、疑似错误和待复核；
- `adjudication_status`：使用 `approved_compatibility`、`approved_surface`、`experimental`、
  `research_only`、`deferred`、`rejected`，不与原始转录状态混用；
- `compatibility_reading`、`compatibility_yinyuan_ids`：保存轻声 `5`、儿缀 `er5` 等稳定兼容路径；
- `underlying_tone`：轻声可空的深层本调属性；未知时留空，不得为完成编码而猜造；
- `erhua_status`：区分非儿化、独立 `ér`、儿缀兼容、融合儿化、口语提示和待定；
- `attachment_syllable_index`、`er_character_index`：分别记录儿化附着的基础音节和文字“儿”的位置；
- `erhua_class`：融合儿化所用韵类和变换类别，儿缀阶段允许留空；
- `canonical_yinyuan_ids`、`surface_yinyuan_ids`：按音节分组的固定四音元 ID；
- `rewrite_spec`：位置、原音元、目标音元以及调级/音质变化；
- `feature_spec`：轻声身份、可空深层本调、儿化附着位置、儿化韵类型或派生首音等结构化特征；
- `candidate_text_policy`：候选文字保持、显式变体或暂缓，禁止仅凭读音自动增删“儿”或替换“啊”；
- `surface_reading`：供人工审校的语流读音说明，不作为键位生成真源；
- `phenomenon`：`tone_sandhi`、`neutral_tone`、`erhua`、
  `particle_allomorphy`、`assimilation`、`dissimilation` 等；
- `scope`：`lexical`、`construction`、`phrase`、`prosodic`；
- `runtime_enabled`：只有获批准且模块启用的记录才可能为真；隔离状态必须为假。

任何 `research_only`、`deferred` 或 `rejected` 记录不得进入运行词典。

阶段 0 的精确输出文件、字段和哈希约束以
[离线验收与回退](connected_speech/OFFLINE_ACCEPTANCE_AND_ROLLBACK.md)为准；清单、三模式覆盖、码长、
碰撞、排序影响、拒绝记录和前后基线哈希缺一不可。

## 10. 建议的构建链

```text
规范核心词典
    + 原始来源观察与转录校正
    + 语流音变审定源
    + 模块化规则与排除清单
    -> 规范四音元 ID
    -> 稳定兼容表示
    -> 可选语流调级/音质等位替换
    -> 固定四位置、来源与可逆性检查
    -> 当前布局键位投影
    -> 同一 codemode 规则派生三模式编码
    -> 等长模式逐音节四码不变量与变长/省键模式逐音节 2—4 码及码长增减报告
    -> 合入三模式 Rime 源词典的附加拼写
    -> 哈希、数量、碰撞与排序清单
```

实现包可命名为 `input_methods/yime/connectedspeech`。各现象使用独立子模块和规则 ID，不得在
候选输出、按键处理或语言栏回调中临时拼接语音规则。

## 11. 候选、学习与工具语义

### 候选注释

- 隐藏编码：不受影响；
- 标准拼音：始终显示规范读音；
- 音元拼音：显示当前方案实际命中的音元编码；
- 键位序列：显示当前方案实际命中的 ASCII 编码。

初期不为语流音变增加第五种候选注释，以免扩大候选框和设置面。需要解释时，优先在反查工具中
显示“规范读音 / 语流输入别名 / 现象类型”。

### 用户学习

- 通过语流别名选择候选，可以在该编码路径上学习排序；
- 不得把语流读音写回用户词库的规范拼音字段；
- 可再生别名不作为不可逆用户数据备份；
- 删除某个音变模块时，不得损坏规范词条和其他模块；
- 同一候选的多个语流别名应避免造成重复候选污染。

### 反查、词库与屏蔽词

- 默认反查以规范读音为主；
- 语流入口明确标注现象类型和适用范围；
- 词库管理器保存的源拼音仍是规范读音；
- 儿化文本是否带“儿”必须显式显示；
- 屏蔽词按候选文本统一生效，不要求重复屏蔽每条别名。

## 12. 从准备到实施的阶段顺序

准备阶段 P、阶段 0、阶段 1 与阶段 2A/2B 已完成。阶段 0 只增加离线数据格式、校验器、报告器和
临时目录审计入口；阶段 1 只审计既有词汇固有轻声链并固定反查的确定性；阶段 2A/2B 盘点“一、不”
现行三模式词典真值，并在临时 Rime 小词典试算两条读音及其回退。以上阶段都没有生成正式语境音变
运行词典，也没有改变安装产物或真实用户数据。

### 准备阶段 P：方案与门禁收口（已完成）

完成本方案的术语、数据模型、证据要求、排除边界、接口边界、试算指标、测试基线和回退设计。
本阶段只形成可评审材料，不新增程序包、生成脚本或运行产物。

审计同时记录 27 组既有同码关系；这些关系都保持相同调类，其中部分是 `e/o`、`me/mo`、`le/lo`
等音质差别，编码本身不能唯一还原。反查选择现已确定化，完整歧义集合写入报告，不得把确定性选择
解释为唯一规范读音。现已从原型规范读音真源生成带来源的“文本—编码—规范拼音”旁表，并接入

不生成语流音变候选。详见[同编码不同拼音反向映射](REVERSE_PINYIN_SOURCE_MAPPING.md)。

本阶段不增加语境轻读，也不把当前 `5`/三个中调乐音序列提升为表层音值模型或开展深层本调回填。

### 阶段 2：“一、不”审定别名（2A/2B 已完成，2026-08-09）

阶段 2A 使用 10 条小规模人工清单区分 4 条现行已覆盖读音、2 条直接词典路径缺失读音、3 条明确
排除项和 1 条延期项。既有链路审计完成 30 次三模式核对，运行别名生成数为零。

阶段 2B 修正了“增码即失败”的错误门禁：“一本 `yi4 ben3`”的变长首音节 `2→4`、省键首音节
`2→3` 都是四音元重新投影的有效结果。临时 Rime 包同时试验“不至于 `bu2 zhi4 yu2`”和“一本
`yi4 ben3`”，完成三模式直接词典输入、候选选择、提交、规范路径保留以及切换到仅含规范路径的
回退。真实基础词典的动态组句已经能够组成“不至于”，但不能组成“一本”，因此两条别名的收益不同。
试验别名不另造词频：三模式分别读取规范路径的既有词典权重，“不至于”沿用 `9342`，“一本”沿用
`2024`。三模式都没有精确规范词条时，记录为“保留 Rime 动态评分”，不物化成带臆造权重的静态
词条；只有部分模式缺失或三模式既有权重不一致才是生成失败。
全部产物仍只位于 `.tmp`，未合入三模式运行词典。详见
[阶段 2A 审定报告](connected_speech/STAGE2_YI_BU_ADJUDICATION.md)。

### 阶段 3：语境轻声

只处理有明确构式、表层证据和排除清单的高频现象；不得全局弱化虚词。表层输入别名必须与兼容码
并存，且不得回写基础 `*5` 码。

重码采用“码随实际读音变化”的工程原则：两个候选的已审表层读音相同且投影到同一编码时，不因重码
自动拒绝别名，而是把两个候选放入同一候选列，分别继承各自规范词条的原权重。该判决只批准候选桶
处理方式，不等于批准轻声表层规则本身；规则顺序依赖、连续轻声和无词内前驱的记录仍须经过各自门禁。

阶段 3-0 先把阴平、阳平、上声、去声语境后的轻声分别记录为五度值 `2、3、4、1`，并明确条件
读取前一音节完成其它音变后的表层调类。离线投影按音元目录执行 `5→高、4→中、3/2/1→低`，
因此四种语境事实压入低、中两个编码桶，但类别 ID 和前一音节条件仍完整保留。首轮覆盖 303 个现有
`*5` 音节、1,212 次语境投影和 132 条稳定音元 ID 替换；其中三个低调类别与同节质三声发生
837 次编码重码。全词典离线展开进一步覆盖 101,928 条轻声记录：96,855 条可投影，76,440 条会改变
输入码；三模式共形成 229,320 个新增映射，其中 3,729 个进入已有候选桶，归属于 1,243 个去重词条。
完整词条扫描得到 2,309 条先行规则依赖项；与竞争项合并为 3,532 条复核队列。阶段 3-1 从四个风险层
和四种前接调类抽取 10 条样本，真实 librime 已通过三模式表层输入、候选排序和整批回退。全部类别仍为
`research_only`，未生成正式运行时别名。详见
[阶段 3-0 轻声语境调值投影](connected_speech/STAGE3_NEUTRAL_TONE_CONTEXT_PROJECTION.md)。
[阶段 3-1 临时 Rime 试验](connected_speech/STAGE3_NEUTRAL_TONE_RIME_TRIAL.md)。

阶段 3-2 排除 1,905 条先行规则依赖后，生成 74,535 条简单轻声记录的 223,605 个三模式临时映射。
新别名彼此形成每模式 4,212 个候选桶，涉及 8,975 个去重词条；绝大多数桶宽为 2，最大为 7。三套
全量临时词典已通过真实 Rime 编译和高频样本查询，正式运行时别名仍为零。详见
[阶段 3-2 简单轻声全量离线候选包](connected_speech/STAGE3_NEUTRAL_TONE_FULL_BATCH.md)。

### 阶段 3-3：统一语境调层—质层假设模型（已完成第一版，2026-08-09）

先建立一套允许偏离语言事实、但能被证据逐条推翻和替换的工程模型，把韵律域与构式分支、上声、
“一”“不”、可选“七、八”、轻声身份与表层调值、儿缀/融合儿化分支以及三模式投影组织成偏序图。
每条规则对每个音节最多应用一次，全局最多一轮；三个以上连续上声、连续轻声链、融合儿化和可选
“七、八”目前均显式暂缓。构式轻声与“一、不”条件调值、轻声与非轻声上声、儿缀与融合儿化等
交叠由独立冲突表裁决，未决时拒绝投影而不猜造唯一结果。

本阶段只新增机器可读模型、冲突表、校验器、报告器和完整性测试，运行时候选生成数为零。它不是
普通话语流规律的定论，也不使阶段 3-2 的 74,535 条临时包自动获得正式资格；规则修改后须重新生成
临时包并复核。详见[统一语境调层假设模型](connected_speech/CONTEXTUAL_TONE_RULE_MODEL.md)。

质层（音质层）把“由音质特征变化引起的音元替换”分成六类：儿化、虚首音实际音值、语气词“啊”、
相邻音节末音—首音之间的同化或异化、音质弱化与时域延展以及其它待分类音变。前五类各有独立规则
槽位，第六类只能登记未知问题，不能直接生成编码。音元模型中不存在音元增减：弱化只形成既有位置
内的音质替换，相邻韵核音质可延展并联结到相应时域，由同一时域负载（承载）并行的音高特征。

### 阶段 4：词汇化儿化

先为明确词条生成 `er5` 儿缀兼容路径；完成儿化韵内部表示、显示约定和碰撞试算后，再从同一结构化
记录生成可选融合儿化路径。两条路径必须能够分别关闭和整批删除。

### 阶段 5：上声变调和能产儿化

必须有词界、构式或韵律边界证据，分别立项验证。

### 阶段 6：语气词音变

从“啊”的六类前接末音规则、固定构式和显式文本记录开始，先离线试算派生首音，再决定是否扩展
首音集合；不自动替换候选汉字。

### 阶段 7：同化、异化及其他音变研究

默认保持 `research_only`。只有证明用户会形成稳定不同编码且收益明确的现象，才申请进入别名层。

## 13. 离线报告要求

每个模块至少报告：

- 规范词条数量；
- 审定语流记录数量；
- 实际生成别名数量；
- 被排除、冲突、重复和无法编码的数量；
- 三模式编码是否一一对应；
- 每个音节替换前后是否都为四音元；
- 变长、等长、省键别名是否均未超过对应规范码长；
- 调级替换、音质替换及两者组合的数量；
- 新增编码映射到的不同文本数量；
- 首选候选和成句率变化；
- 删除模块后规范构建是否恢复原哈希；
- 规则版本、输入哈希和来源覆盖率。

报告不能只给“总命中率提高”，必须同时展示新增重码和规范路径回归。

## 14. 最低回归矩阵

| 维度 | 最低覆盖 |
|---|---|
| 音变模块 | 变调、轻声、儿化；其他模块启用时分别覆盖 |
| 四音元结构 | 音节数不变、每音节四位置、只替换不增删 |
| 输入方案 | 变长、等长、省键 |
| 码长 | 等长逐音节四码；变长和省键逐音节 `2—4` 码，允许因重新投影而增加、减少或不变 |
| 布局 | 默认布局和至少一个替代布局得到同一音元语义结果 |
| 输入路径 | 规范读音仍可输入、语流别名可输入、禁用模块后别名消失 |
| 兼容路径 | 轻声 `5`、儿缀 `er5` 始终可输入，可选表层模块关闭后仍保持 |
| 候选显示 | 隐藏编码、标准拼音、音元拼音、键位序列 |
| 句中位置 | 单词、句首、句中、句末、后接动态组句 |
| 用户数据 | 学习、用户词库、备份恢复、屏蔽词 |
| Rime | 源词典检查、真实 librime 构建、会话输入与提交 |
| Windows | 重建、安装、进程重启、至少一个 x64 与一个 x86 宿主 |

长期保留的反例：

- `第一`、`十一`等不能被简单相邻声调规则误改；
- `看一看`、`好不好`不由“一、不”变调模块擅自决定轻声；
- “七、八”在未审定前不生成全局变调别名；
- 未标轻声的虚词不因词频高而全部弱化；
- 找不到深层本调的轻声不得被猜造本调，已找到本调也不得因此删除 `5` 兼容码；
- 不带“儿”的任意名词不能自动变成带“儿”候选；
- 独立 `ér` 不得因词尾存在“儿”而自动归为儿缀或融合儿化；
- 融合儿化不得由扁平儿缀码删除 `er5` 产生；
- 语气词“啊”不能因前字韵尾而自动替换候选汉字；
- “啊”的六类末音条件必须覆盖 `ao/iao` 的末音 `u`，并区分 `[ŋ]`、`[z]` 和卷舌类派生首音；
- 同化、异化记录在 `research_only` 时不得泄漏进运行词典；
- 三模式别名集合一一对应，不允许缺一种模式；
- 任一语流规则不得改变音节数量或四音元位置数量；
- 任何码长变化都必须来自同一四音元记录的模式投影，不得人为追加音变标记；
- 禁用全部语流模块后，规范词典与原构建结果一致。

## 15. 回退与发布

每个音变模块必须可以独立关闭：

- 构建参数和清单记录启用模块；
- 模块关闭后不需要迁移规范词典；
- 可再生别名不成为用户数据恢复的硬依赖；
- 发现重码或排序回归时，优先禁用具体模块，不回滚三模式核心；
- 安装态验证必须核对运行词典确实来自声明的模块集合。

正式默认启用前至少完成：

- 离线碰撞评审；
- 三模式真实 Rime 回归；
- 用户学习与备份恢复验证；
- 安装后 x86/x64 宿主输入；
- 模块开关回退演练；
- 帮助和反查工具语义说明。

## 16. 给后续 AI 的检查表

本文件已经从长期备忘转为实施前准备方案，但这不等于程序实现已经开始。收到“支持语流音变”
“完善轻声”“增加儿化”或类似任务时，先核对 1.2 节的准备阶段退出条件，不要直接修改码表、
生成运行别名或接入运行链。

开始任何实现前必须回答：

1. 这是规范读音、词汇固有读音，还是语境音变？
2. 候选文本是否变化？若变化，依据是什么？
3. 现象属于变调、轻声、儿化、语气词、同化、异化还是其他模块？
4. 是强规则、审定别名，还是只能保留为 `research_only`？
5. 规则是否只在已知词条或已知构式内部生效？
6. 是否有来源、例外清单、规则 ID 和可回退开关？
7. 是否明确记录了四音元位置内的调级/音质等位替换？
8. 是否保持每个音节四个位置，并证明等长为四码、变长和省键处于 `2—4` 码？
9. 变长、等长、省键是否从替换后的同一四音元记录同时派生？
10. 音变规则是否独立于物理键位和具体布局？
11. 标准拼音、规范词典和用户词库真源是否保持不变？
12. 新增重码、首选变化和成句率是否有并列报告？
13. 是否先写了真实 Rime 回归，而不是只测试字符串替换？

任一问题没有答案，就保持运行链不变，只补充方案、数据审计或 `research_only` 记录。
