# 普通话语流音变处理 Plan（备忘）

> 状态：长期规划，尚未进入实现
> 记录日期：2026-07-29
> 进入阶段：开发路线图阶段 D；不得插入当前发行收口
> 总原则：规范读音是真源，语流音变是有来源、可撤销的附加输入路径

## 1. 目的

音元输入法使用带调音节编码。用户在连续说话或默念句子时，脑中出现的往往是语流中的实际读音，
不一定是词典记录的规范本调。支持常见语流音变，可以减少用户在输入前把实际读音还原为词典读音
的负担。

与普通拼音输入法不同，Yime 的语流音变不需要增加音节位置或追加特殊标记。每个规范音节已有
“首音—呼音—主音—末音”四个音元位置；变调、轻声、儿化及其他音变可表达为这四个位置内部的
音元等位替换，主要改变音元调级或音质。完整等长表示仍保持四个音元。

本 Plan 统一规划以下现象：

1. 变调；
2. 轻声；
3. 儿化；
4. 其他语境音变，包括语气词的音变、音节间的同化和异化等。

这是一项低优先级、可长期研究的增强功能。不做不会妨碍 Yime 的基本使用；实施不当却可能增加
重码、破坏规范拼音、混淆用户词库或让三种输入方案再次失去同步。因此必须先建立完整边界，
再按模块逐步试验。

《普通话水平测试大纲》把变调、轻声、儿化列为多音节语音能力，并在朗读中考查连读音变；
《汉语拼音正词法基本规则》则要求规范拼写一般保留本调。这两条共同构成本 Plan 的设计依据：
规范形式保持稳定，语流形式作为附加入口。

- [GB/T 16159—2012《汉语拼音正词法基本规则》](https://www.moe.gov.cn/ewebeditor/uploadfile/2015/01/13/20150113091717604.pdf)
- [《普通话水平测试大纲》](https://www.moe.gov.cn/srcsite/A18/s3133/200310/t20031017_78537.html)

## 2. 三层数据模型

### 2.1 规范读音层

规范读音层继续承担唯一真源职责：

- 核心候选的规范数字标调拼音；
- `yime_pinyin_codes.tsv` 的音节编码映射；
- `pinyin_normalized.json` 和“标准拼音”候选注释；
- 三模式系统词典、用户词库、学习迁移和反查的稳定身份；
- 词典哈希、来源证据和可重复构建。

任何语流音变功能都不得直接修改这层数据。

### 2.2 语流读音层

语流读音层描述某个已知词或短语在特定条件下可以怎样读：

- 每条记录必须指向规范文本和规范拼音；
- 必须标明音变类型、适用范围、规则或来源；
- 必须区分词汇固有读音、常见语境读音和自由口语变体；
- 不确定、地域性或强烈依赖语气的读音不得默认启用；
- 涉及词界、句法或韵律边界时，必须显式记录边界条件。
- 面向机器的最终表示不是任意拼音字符串，而是规范四音元到语流四音元的等位替换。

### 2.3 输入别名层

输入别名层把审定后的语流读音转换为 Yime 可接受的附加编码：

- 别名必须绑定到完整词或短语，不得改写单字基础编码；
- 同一候选始终保留规范读音编码；
- 每个音节的语流等长表示仍为四个音元，只允许替换，不允许插入或删除位置；
- 别名必须从替换后的四音元记录同时派生变长、等长、省键三套编码；
- 任何语流别名在三种模式中都不得比对应规范编码更长；
- 别名权重原则上低于规范路径，具体惩罚值由碰撞报告决定；
- 删除输入别名层后，核心词典和用户数据仍应正常工作；
- 语流规则不能进入按键解释逻辑，不得让按键含义随上下文改变。

### 2.4 四音元等位替换层

语流音变的核心中间表示为固定四位置元组：

```text
[首音, 呼音, 主音, 末音]
```

规则作用于元组中的一个或多个位置：

```text
规范四音元
    -> 按上下文替换指定位置的音元调级/音质
    -> 语流四音元
```

基本不变量：

- 输入和输出的音节数相同；
- 每个音节输入和输出都恰好有四个位置；
- 规则只能替换位置内容，不能插入第五个音元或删除既有位置；
- 首音若发生同化，也只能在首音位置等位替换，不能破坏音节边界；
- 每次替换必须记录位置、原音元、目标音元、改变的属性和规则 ID；
- 调级替换与音质替换可以组合，但必须有固定顺序和冲突检查。

规则应作用于稳定的音元 ID 和属性，而不是直接作用于当前 QWERTY 键。当前布局仍有部分音质、
调级语义通过 ASCII 键组表达；正式实现前应完成“稳定音元 ID/属性—可替换键位投影”的边界，
避免布局变化改变音变规则。

三模式派生顺序固定为：

```text
规范四音元
    -> 语流音变等位替换
    -> 布局键位投影
    -> 等长/变长/省键派生
    -> 码长与碰撞门禁
```

等长模式天然保持每音节四码。变长和省键必须从替换后的四音元重新派生，并逐条验证结果不长于
对应规范模式编码；不满足该性质的规则只能保留为 `research_only`。

## 3. 不可回退的总边界

1. 不把语流音变写回核心等长词典真源。
2. 不修改 `yime_pinyin_codes.tsv` 中规范音节到编码的一一对应关系。
3. 不把语流读音显示成“标准拼音”。
4. 不为同一个单音节建立依赖后续按键的基础编码。
5. 不先接通某一种 schema，再把另外两种留作以后补齐。
6. 不把词汇固有轻声推广成任意语境轻读规则。
7. 不把带“儿”字的文本和不带“儿”字的文本无条件互换。
8. 不把语气词的实际读音直接当成候选汉字替换规则。
9. 不把渐变、可选或地域性的同化、异化现象默认转换成键盘别名。
10. 不在缺少来源、碰撞报告、真实 Rime 回归和安装态验证时默认启用新模块。
11. 不使用 LLM 在运行时猜测词界、语气、韵律或实际读音。
12. 不用增码、附加后缀或额外分隔符表示语流音变。
13. 不绕过固定四音元层直接把“语流拼音字符串”翻译成临时键码。
14. 不把音质或调级规则绑定到不可替换的物理键位。

## 4. 统一术语

| 术语 | 本 Plan 中的含义 |
|---|---|
| 规范读音 | 词典、规范拼音和核心词典记录的稳定读音 |
| 语流读音 | 连续言语中受相邻音节、词法、句法、语气或韵律影响的实际读法 |
| 词汇固有 | 已成为具体词语读音组成部分，应由词条明确记录 |
| 语境音变 | 只有满足上下文条件才出现的读音变化 |
| 输入别名 | 不改变候选文本和规范读音，仅增加一条可接受编码 |
| 等位替换 | 在四音元固定位置内替换调级或音质，不增删音元位置 |
| 强规则 | 条件明确、例外可列举、可确定性生成 |
| 弱规则 | 可选、渐变、地域性或依赖语气，只能审定收录或用于研究 |

## 5. 模块一：变调

### 5.1 “一、不”变调

这是最适合首先试验的强规则模块。

初始可审定规则：

- “一”在四声前可接受 `yi2` 语流别名；
- “一”在一、二、三声前可接受 `yi4` 语流别名；
- “不”在四声前可接受 `bu2` 语流别名；
- 其他情况保持规范读音，除非审定清单明确列出。

第一版只使用完整词或短语的显式审定清单，不自动处理：

- 单念、词尾或数字串中的“一”；
- 序数“第一”等保持本调的结构；
- “看一看”等可能轻读的重叠结构；
- `A不A` 中可能轻读的“不”；
- 跨词、跨分句和依赖重音的情况。

### 5.2 上声变调

上声变调比“一、不”更依赖词界和韵律边界，应独立立项：

- 先覆盖词典明确的双音节词；
- 三个及以上连续上声必须记录韵律切分，不得只看相邻数字声调；
- 不跨未知词界自动生成；
- 不改变标准拼音注释；
- 必须验证变调别名不会压低规范路径的首选稳定性。

### 5.3 “七、八”等可选变调

“七、八”不得与“一、不”按同一优先级处理，也不得建立“第一声遇四声一律变二声”的全局规则。

若后续加入，只允许：

- 有规范语音资料或人工审定依据的固定词；
- 作为低权重、可删除的词组级别名；
- 单独统计使用收益和新增碰撞；
- 证明有价值后再扩大范围。

### 5.4 语法、重音和语气引起的调值变化

焦点重音、语气强调和句末语调可能改变实际调值，但不一定改变音系声调类别。初期不得把调值连续
变化离散成新的数字标调音节。此类现象先保留为研究数据，不进入编码别名。

## 6. 模块二：轻声

轻声必须拆成两类。

### 6.1 词汇固有轻声

词典明确的轻声属于规范词条的一部分，可继续使用数字调 `5` 或项目既有的无调标记处理：

- 逐项审计现有轻声词条和标准拼音显示；
- 确认三模式都能由同一轻声音节编码派生；
- 用户词库和反查保留轻声身份；
- 不因加入语流模块而把现有轻声改成普通本调。

这部分不是输入别名，而是规范读音层的既有能力。

### 6.2 语境轻读

语境轻读可能出现在：

- 结构助词、语气助词和某些后缀；
- 重叠式的后一个音节；
- `A不A`、动词重叠等固定构式；
- 高频口语词组中的弱读位置。

初步实现必须使用构式或词组清单，不能仅凭“高频虚词”或“非重读位置”全局改成轻声。

每条语境轻读记录必须回答：

- 候选文本是否不变；
- 规范读音是什么；
- 哪个音节轻读；
- 是否强制、常见可选或仅口语可见；
- 是否依赖重音、语速或句法结构；
- 是否允许作为默认输入别名。

### 6.3 轻声与变调叠加

“一、不”、上声变调与轻声可能同时出现在一个构式中。不得由多个模块无序重复改写。

需要统一的规则流水线和优先级：

1. 读取规范词条和结构边界；
2. 应用有词条证据的轻声或儿化身份；
3. 应用允许的变调规则；
4. 生成一个规范化语流读音；
5. 去重并派生三模式编码。

流水线顺序在实现前必须用反例验证，不能只凭直觉固定。

## 7. 模块三：儿化

儿化不仅改变读音，还可能涉及文本中是否写出“儿”，因此必须比变调更谨慎。

### 7.1 词汇化儿化

词典明确收录、意义或词性已经固定的儿化词，应作为有来源的完整词条处理：

- 规范文本是否带“儿”由词典和项目文本策略决定；
- 规范读音必须使用可逆表示，不能只保存听感近似拼音；
- 反查应能显示基础音节、儿化标记和最终输入编码；
- 三模式从同一儿化读音记录确定性派生。

### 7.2 能产儿化

临时、小称、口语色彩等能产儿化依赖词义、语体和地区习惯。初期不得对任意名词自动添加或删除
“儿”。

进入试验前必须先确定：

- 语流读音的内部表示，例如“基础音节 + 儿化特征”，而不是模糊字符串；
- 候选文本是原词、带“儿”文本，还是两个候选都存在；
- 输入儿化读音时是否只匹配显式审定的候选；
- 用户词库如何保存和导出；
- 备份恢复能否无损保留儿化身份。

### 7.3 儿化韵数据

儿化可能涉及韵尾脱落、元音变化和卷舌特征。不得把所有儿化简单处理成在原拼音后追加 `r5`。

需要先建立：

- 普通话儿化韵规范表；
- 基础韵到儿化韵的可逆或可追踪映射；
- 特殊形式和不可自动生成清单；
- PUA 音元显示方案；
- 标准拼音、音元拼音和键位序列的显示约定。

在该数据格式完成前，不实现运行时儿化生成器。

## 8. 模块四：其他语境音变

### 8.1 语气词音变

重点包括语气词“啊”等受前一音节韵尾影响产生的读音变化，以及口语中已经形成不同书写形式的
“呀、哇、哪、啦”等。

这里必须区分：

- 同一个候选汉字的不同实际读音；
- 不同汉字但功能相关的语气词；
- 规范书写变体；
- 仅为语音过渡、通常不改变书写的变体。

输入法不得根据前一个音节擅自替换候选汉字。第一阶段只能建立“文本—规范读音—语流读音”的
显式审定记录。

### 8.2 音节间同化

同化可能影响发音部位、发音方法、清浊、鼻化或其他语音特征，其中很多是连续、渐变且不改变
音系身份的自然发音。

只有同时满足以下条件才考虑输入别名：

- 在普通话中稳定、常见并有可靠资料；
- 能用离散、可重复的内部音节表示；
- 用户确实会据此形成不同键盘编码；
- 不会把个人口音或快速语流误当成规范规则；
- 候选收益大于新增重码。

否则只作为语音学研究记录，不进入键盘输入。

### 8.3 音节间异化

异化同样可能涉及词汇化、语境化或自由变体。处理原则与同化相同：

- 不建立无来源的全局音节替换；
- 优先收录固定词和高频构式；
- 保留规范读音；
- 与变调模块去重，避免同一现象在两个模块重复生成。

### 8.4 弱化、脱落、合音及其他口语缩约

快速口语中的弱化、音素脱落、合音和缩约可能显著偏离规范音节。它们暂不属于初步实现范围。

只有在未来建立了可靠语料、规范化表示和明确用户需求后，才另立子项目；不得把模糊匹配、拼写
纠错或近音容错冒充语流音变。

## 9. 统一数据格式

建议新增人工维护的源文件：

```text
yime_connected_speech_aliases.tsv
```

建议字段：

```text
text
canonical_pinyin
surface_reading
canonical_yinyuan_ids
surface_yinyuan_ids
rewrite_spec
phenomenon
rule_id
scope
status
source
```

其中：

- `canonical_yinyuan_ids`、`surface_yinyuan_ids`：按音节分组的固定四音元 ID；
- `rewrite_spec`：位置、原音元、目标音元以及调级/音质变化；
- `surface_reading`：供人工审校的语流读音说明，不作为键位生成真源；
- `phenomenon`：`tone_sandhi`、`neutral_tone`、`erhua`、
  `particle_allomorphy`、`assimilation`、`dissimilation` 等；
- `scope`：`lexical`、`construction`、`phrase`、`prosodic`；
- `status`：`canonical`、`enabled_alias`、`experimental`、`research_only`；
- `source`：规范、词典、语料、人工审定记录或专项研究编号。

任何 `research_only` 记录不得进入运行词典。

建议生成：

- `yime_connected_speech_manifest.json`；
- 三模式逐项覆盖报告；
- 新增编码碰撞和候选排序报告；
- 未知音节、规则冲突和边界不明报告；
- 各现象模块的启用状态与规则版本。

## 10. 建议的构建链

```text
规范核心词典
    + 语流音变审定源
    + 模块化规则与排除清单
    -> 规范四音元 ID
    -> 调级/音质等位替换
    -> 固定四位置、来源与可逆性检查
    -> 当前布局键位投影
    -> 同一 codemode 规则派生三模式编码
    -> 三模式均不增长的码长门禁
    -> 合入三模式 Rime 源词典的附加拼写
    -> 哈希、数量、碰撞与排序清单
```

实现包可命名为 `input_methods/yime/connectedspeech`。各现象使用独立子模块和规则 ID，不得在
候选输出、按键处理或语言栏回调中临时拼接语音规则。

## 11. 候选、学习与工具语义

### 候选注释

- 隐藏编码：不受影响；
- 标准拼音：始终显示规范读音；
- 音元拼音：显示当前方案实际命中的音元编码；
- 键位序列：显示当前方案实际命中的 ASCII 编码。

初期不为语流音变增加第五种候选注释，以免扩大候选框和设置面。需要解释时，优先在反查工具中
显示“规范读音 / 语流输入别名 / 现象类型”。

### 用户学习

- 通过语流别名选择候选，可以在该编码路径上学习排序；
- 不得把语流读音写回用户词库的规范拼音字段；
- 可再生别名不作为不可逆用户数据备份；
- 删除某个音变模块时，不得损坏规范词条和其他模块；
- 同一候选的多个语流别名应避免造成重复候选污染。

### 反查、词库与屏蔽词

- 默认反查以规范读音为主；
- 语流入口明确标注现象类型和适用范围；
- 词库管理器保存的源拼音仍是规范读音；
- 儿化文本是否带“儿”必须显式显示；
- 屏蔽词按候选文本统一生效，不要求重复屏蔽每条别名。

## 12. 分阶段实施顺序

### 阶段 0：数据格式与离线审计

不改变运行词典，只建立统一 TSV、现象分类、来源字段、冲突检测和报告。

### 阶段 1：既有轻声链审计

先证明现有词汇固有轻声在三模式、标准拼音、反查、用户词库和真实 Rime 中一致。这一步不增加
语境轻读。

### 阶段 2：“一、不”审定别名

使用小规模人工清单验证规范路径不变、语流路径可输入、三模式齐全和碰撞可控。

### 阶段 3：语境轻声

只处理有明确构式和排除清单的高频现象；不得全局弱化虚词。

### 阶段 4：词汇化儿化

完成儿化韵内部表示和显示约定后，只接入明确词条。

### 阶段 5：上声变调和能产儿化

必须有词界、构式或韵律边界证据，分别立项验证。

### 阶段 6：语气词音变

从固定语气词和显式文本记录开始，不自动替换候选汉字。

### 阶段 7：同化、异化及其他音变研究

默认保持 `research_only`。只有证明用户会形成稳定不同编码且收益明确的现象，才申请进入别名层。

## 13. 离线报告要求

每个模块至少报告：

- 规范词条数量；
- 审定语流记录数量；
- 实际生成别名数量；
- 被排除、冲突、重复和无法编码的数量；
- 三模式编码是否一一对应；
- 每个音节替换前后是否都为四音元；
- 变长、等长、省键别名是否均未超过对应规范码长；
- 调级替换、音质替换及两者组合的数量；
- 新增编码映射到的不同文本数量；
- 首选候选和成句率变化；
- 删除模块后规范构建是否恢复原哈希；
- 规则版本、输入哈希和来源覆盖率。

报告不能只给“总命中率提高”，必须同时展示新增重码和规范路径回归。

## 14. 最低回归矩阵

| 维度 | 最低覆盖 |
|---|---|
| 音变模块 | 变调、轻声、儿化；其他模块启用时分别覆盖 |
| 四音元结构 | 音节数不变、每音节四位置、只替换不增删 |
| 输入方案 | 变长、等长、省键 |
| 码长 | 三模式语流别名均不长于对应规范编码 |
| 布局 | 默认布局和至少一个替代布局得到同一音元语义结果 |
| 输入路径 | 规范读音仍可输入、语流别名可输入、禁用模块后别名消失 |
| 候选显示 | 隐藏编码、标准拼音、音元拼音、键位序列 |
| 句中位置 | 单词、句首、句中、句末、后接动态组句 |
| 用户数据 | 学习、用户词库、备份恢复、屏蔽词 |
| Rime | 源词典检查、真实 librime 构建、会话输入与提交 |
| Windows | 重建、安装、进程重启、至少一个 x64 与一个 x86 宿主 |

长期保留的反例：

- `第一`、`十一`等不能被简单相邻声调规则误改；
- `看一看`、`好不好`不由“一、不”变调模块擅自决定轻声；
- “七、八”在未审定前不生成全局变调别名；
- 未标轻声的虚词不因词频高而全部弱化；
- 不带“儿”的任意名词不能自动变成带“儿”候选；
- 语气词“啊”不能因前字韵尾而自动替换候选汉字；
- 同化、异化记录在 `research_only` 时不得泄漏进运行词典；
- 三模式别名集合一一对应，不允许缺一种模式；
- 任一语流规则不得改变音节数量或四音元位置数量；
- 任一运行别名不得在任何模式中增加码长；
- 禁用全部语流模块后，规范词典与原构建结果一致。

## 15. 回退与发布

每个音变模块必须可以独立关闭：

- 构建参数和清单记录启用模块；
- 模块关闭后不需要迁移规范词典；
- 可再生别名不成为用户数据恢复的硬依赖；
- 发现重码或排序回归时，优先禁用具体模块，不回滚三模式核心；
- 安装态验证必须核对运行词典确实来自声明的模块集合。

正式默认启用前至少完成：

- 离线碰撞评审；
- 三模式真实 Rime 回归；
- 用户学习与备份恢复验证；
- 安装后 x86/x64 宿主输入；
- 模块开关回退演练；
- 帮助和反查工具语义说明。

## 16. 给后续 AI 的检查表

收到“支持语流音变”“完善轻声”“增加儿化”或类似任务时，先阅读本 Plan，不要直接修改码表。

开始任何实现前必须回答：

1. 这是规范读音、词汇固有读音，还是语境音变？
2. 候选文本是否变化？若变化，依据是什么？
3. 现象属于变调、轻声、儿化、语气词、同化、异化还是其他模块？
4. 是强规则、审定别名，还是只能保留为 `research_only`？
5. 规则是否只在已知词条或已知构式内部生效？
6. 是否有来源、例外清单、规则 ID 和可回退开关？
7. 是否明确记录了四音元位置内的调级/音质等位替换？
8. 是否保持每个音节四个位置且没有增加任何模式的码长？
9. 变长、等长、省键是否从替换后的同一四音元记录同时派生？
10. 音变规则是否独立于物理键位和具体布局？
11. 标准拼音、规范词典和用户词库真源是否保持不变？
12. 新增重码、首选变化和成句率是否有并列报告？
13. 是否先写了真实 Rime 回归，而不是只测试字符串替换？

任一问题没有答案，就保持运行链不变，只补充方案、数据审计或 `research_only` 记录。
