# YimeCore 原生回退证据采集编排

2026-09-08，影响产品：YimeCore。本轮新增从备份、故障控制器到前后观察的源码编排，以及独立的原始子进程退出、备份内容和数据指纹检查。入口默认只生成静态计划；本轮未运行实际备份、UAC、安装、回退、恢复或卸载，也未读取真实用户配置、学习数据和文本。已安装 local.12、正式 Rime/PIME 和默认输入法均未改动。

入口是 `tools/yimecore/invoke-native-rollback-collection.ps1`。省略 `-Execute` 时，仅根据明确的 32 位小写十六进制 attempt ID 构造固定路径与步骤，不读取安装目录、用户状态、注册表或候选包，也不调用包内维护脚本的 Plan。它不提供任意包路径、SID 或执行提供程序覆盖参数。`ready_to_execute=false` 继续保留，静态计划不是本机维护许可或原生验收。

未来显式执行路径按以下顺序工作：

1. 保留普通权限、同 SID、从 Explorer 启动的原生 Windows PowerShell 5.1 父进程。PS7 可运行源码回归和静态计划；真实编排要求 PS5，因为现有 Runtime 普通权限启动器核验该父进程映像与创建时间。
2. 打开固定 local.13 普通/故障公开归档的输入租约，检查本次输出、备份、目标安装目录及终态文件未被占用，并核对旧安装公开 manifest。
3. 通过普通候选的备份入口，以明确的旧 `InstalledPackageRoot` 启动备份。备份 helper 还会使用经过其校验的旧安装 auditor、停止脚本及 launcher，不能将执行来源描述为只有新候选代码。
4. 观察创建时持有的原始子进程句柄，取得 OS 退出码 0 后，再验证完整备份。备份中的 `passed=true` 写入早于 helper 的 Runtime 重启清理，因此单独读取该字段不足以放行。
5. 把备份数据和 runtime-config 快照重新绑定已验证的清单，并与当前状态比较；备份会重启 Runtime，进程基线在备份退出后重新采集。
6. 直接通过 UAC 启动固定故障包的 `Manage-YimeCoreTrial.ps1`，显式传递 initiating SID、StateRoot、`StandardUserInitiator=PID:FILETIME`、attempt 和终态路径。继续保留普通权限 PS5 父进程，供控制器恢复普通权限 Runtime 使用。
7. 原始控制器退出后，将 OS PID、创建时间和退出码传入严格终态读取器，再核对独立注册表、数据/config 和 Runtime/Broker 进程观察。

等待不重开 PID、不重定向标准输出，也不等待后代持有的管道 EOF。五分钟软预算超时会使本次尝试失去继续资格；父进程仍等待原始子进程退出，随后停止后续步骤。异常路径同样保留父进程直到子进程结束。工具不强制终止安装器、不自动恢复数据，也不在失败后启动第二次维护。

编排固定传入旧 local.12 manifest 哈希 `9b3366b350ef2b23fd285fc9d97d876bf1ae6e2fc0f8613c647640f01184502e`；备份读取器将 74 个列明载荷加 manifest 与安装标记的 76 个文件绑定该预期身份，并验证完整状态清单和固定数据子集。它在本次验证期间持有文件与目录句柄，拒绝重复 JSON 键、非字面真值、额外或遗漏文件、重解析点、硬链接和命名数据流。验证结束释放租约，不能据此声称随后整个维护窗口的成员集合不变。

数据观察只产生路径、长度、哈希及文件身份；不解析或返回用户内容。备份采用只读共享；正在运行的 Runtime 状态采用显式 ReadWrite/Delete 共享，以兼容实际 journal 写入。两者均进行同句柄两次哈希及成员复核，但不声称原子、静止或连续保护。比较 API 可区分 runtime-config、文件内容及同根文件身份变化；当前编排比较备份与维护前后状态的跨根内容/config，不将跨介质文件 ID 差异判为失败。

测试与精确来源哈希见[结构化证据](../testing/l6/2026-09-08-native-rollback-collection.json)。子进程测试只启动自有小进程；文件测试只使用仓内新建合成树；编排顺序使用模块内私有替身，实际备份和故障控制器从未被调用。组合 CI 使用相同脚本分别在外部 PS5 和同一 PS7 进程执行，以覆盖模块加载及类型污染问题。

目录句柄回归实际复现了只有 `READ_ATTRIBUTES` 时仍可改名，新增提供程序已改用 `LIST_DIRECTORY | READ_ATTRIBUTES` 并验证拒绝改名；允许新建瞬态成员的事实原样保留。目录清单绑定来自备份读取器的实际枚举，不冒称是仅记录文件的原 manifest。两个文件提供程序使用本次模块私有随机类型，不能复用预装同名辅助类型。

本机实际执行了 CI 的 11 脚本组合，PS5/PS7 各 1,010 项通过；既有进程观察脚本在 CI 运行的是 47 项合成范围，不借用此前原生产品证据。结构化记录固定 21 项来源和 26 份原始文件引用。新来源基线为 185 个声明路径加 7 个锁定依赖，192 项哈希一致，68 项纯内存合同测试通过，8 个 pending 保持不变。

完成这一采集序列最多可得到 `collection_completed=true`，仍不能提升 `rollback_acceptance`、`independent_data_restore_verified`、`deferred_delete_absence_verified`、`independent_system_visibility_verified`、`startup_verified`、`runtime_ready_verified`、L6 或产品就绪字段。现有类型化注册表观察未包含延期删除队列；进程存在、映像哈希和普通权限身份也不等于桌面会话启动或 Runtime 就绪。加载的控制器代码身份仍未认证。

下一步需要补齐延期删除与独立系统可见性、启动/Runtime 就绪证据，再在获得相应实际维护授权的原生窗口取得回退、恢复、卸载重装与宿主验收。既有 [local.13 候选](YIMECORE_LOCAL13_OUTCOME_CANDIDATES_2026-09-08.md)身份和仓外归档保持原样；本轮工具在仓内，不宣称已被纳入候选包。Rime/PIME 的可信候选、独立目标、DP1-U 实际事务以及 DP2/DP3 不借用本轮 YimeCore 合成结果关闭。
