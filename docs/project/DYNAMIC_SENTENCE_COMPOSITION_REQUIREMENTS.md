# 动态组句模型需求与验收规范

> 文档性质：YimeCore 动态组句的产品语义、实现边界与验收基线
> 适用范围：自研 YimeCore 引擎、Broker 状态和试验版候选 UI
> 初始案例：连续输入“知识分子问题”
> 核心原则：单字兜底、词语优先、语境调优、动态调频

## 1. 目的

动态组句应根据用户逐键输入的音码、已经选择的内容和已有词典记录，从左到右持续生成可解释、
可局部修正且不会提前提交的整句预览。

本规范解决以下错误切分：用户准备输入“知识分子问题”，连续输入变长模式编码
`7J9LKJ[va6L=ucztlkj`，模型却优先得到“之｜十分｜子问题”。该路径虽然能够覆盖全部编码，
但违背输入顺序和词语优先原则。对当前词典和该编码，预期基础切分为：

```text
知识｜分子｜问题
```

如果同码词典中存在覆盖前四个音节的内置词“知识分子”，则应进一步优先得到：

```text
知识分子｜问题
```

模型不得为了得到示例结果而硬编码“知识分子问题”，也不得虚构词典中不存在的词语。

## 2. 术语

- **音码**：一个汉字音节在完整、变长或省键模式下的键序列。
- **当前音节**：用户正在输入、可能尚未完成的最后一个音节。
- **内置词语**：当前启用的系统词典或经审核词库中存在稳定记录的多音节候选。
- **句子路径**：按原始输入字节范围连续排列的一组词典分段。
- **完整路径**：除显式分隔符外，所有已输入编码均被分段覆盖。
- **临时预测**：最后一个音节只输入部分编码时，由真实词典前缀得到的候选或句子预览。
- **活动分段**：用户在候选 UI 中正在查看或改选的句子分段。
- **结构优先级**：由本规范确定的切分顺序，优先于静态词频和用户频次。

所有 `{start, end}` 范围均指向原始 ASCII 输入的字节位置，不得使用显示汉字下标代替。

## 3. 规则优先级

模型按以下顺序决策，后面的规则不得推翻前面的规则：

1. 已选择分段和显式边界约束；
2. 单字阶段与当前输入音节数；
3. 精确内置词语和从左到右的词语优先；
4. 已登记的构式、框式或其他语境规则；
5. 用户频次、上下文频次和系统静态频次；
6. 稳定、确定性的末级排序。

排序必须可重放。相同词典、相同用户模型和相同输入事件序列必须产生相同结果。

## 4. 单字兜底

### 4.1 首音节阶段

从首音开始，到第一个音节的最后一音为止，如果用户尚未开始输入第二个音节：

- 候选列表只列单字候选，不列双字或更多字的词语；
- 单字按用户频次、上下文频次、系统频次和稳定末级键排序；
- 输入 `7` 或变长模式下完整的 `7J` 时，首选为高频单字“之”是合理结果；
- 用户若要选择“知”，应从同码单字候选中选择，后续可由动态调频提升；
- 单字候选必须支持完整分页，不能因高频多字同码项占据索引前部而丢失低频单字。

首音节边界必须来自正式音节编码规则、索引元数据或等价的可验证信息。不得长期依赖 UTF-8
字符数、固定码长或“遇到任意同码记录即算完成”等不稳定猜测。

### 4.2 局部打散后的单字阶段

用户点击一个词语要求打散重组时，目标范围的第一个音节重新进入单字兜底：

- 首步只显示覆盖该音节的单字；
- 选择单字后才能继续向右组合；
- 目标范围之外已选择的前缀和后缀必须保持不变；
- 改选过程不得提交宿主 composition。

## 5. 词语优先

### 5.1 逐键扩展

一旦用户在完整前一音节后输入下一音节的首音，模型进入多音节词语阶段：

- 优先查找覆盖当前已涉及音节数的内置词语；
- 最后一个音节可以只输入部分编码，但候选必须来自真实词典前缀；
- 输入涉及几个音节，就优先显示覆盖这几个音节的词语；
- 没有对应内置词语时不得合成一个伪词候选；
- 当前音节完成后仍无多音节词语，才回退到左侧已完成词语或单字，再继续组合右侧。

例如，完整输入“知”的 `7J` 后继续输入“识”的首音，候选应优先出现“知识”等真实双音节
词语，而不应继续以“之”作为整句首选。继续输入“分”“子”“问”“题”时，同一原则逐音节
扩展。

### 5.2 从左到右比较句子路径

两个完整句子路径竞争时，采用词长序列的字典序比较：

1. 比较第一个分段覆盖的音节数，较长者优先；
2. 第一个分段等长时，比较第二个分段，以此类推；
3. 所有对应分段等长时，分段更少者优先；
4. 切分结构相同时，才比较用户、上下文和静态频次。

因此，只要存在“知识｜分子｜问题”，就不能因为“之”“十分”“子问题”的静态频次总和更高，
把“之｜十分｜子问题”排在前面。

精确覆盖全部输入的内置整词或短语可以作为单个分段优先，但必须与当前编码完全匹配。只匹配未来
尚未输入音节的更长词条不能压过当前已覆盖音节数正确的候选。

## 6. 语境调优

### 6.1 默认前向路径

默认解码顺序是从用户最先输入的位置向右扩展。只要存在满足词典、边界和用户选择约束的前向
完整路径，就不得仅凭后部高频词改用逆向切分。

### 6.2 回退路径

只有前向搜索没有有效完整路径时，才允许在保留已有选择的前提下考虑：

- 从后向前的词典切分；
- 单字兜底与后部词语组合；
- 经审核并登记的构式或框式规则。

“合理”必须转化为可测试条件，至少包括：完整覆盖输入、所有分段有词典来源、边界连续、已选择
分段不被改写。不能只在代码中使用不可验证的“语义更通顺”判断。

### 6.3 构式与框式

构式规则用于普通前向词语优先仍不能表达的局部结构，例如：

```text
把｜文档｜保存［在｜目录｜中］
在｜游泳池｜中｜游｜一回｜泳
```

构式规则必须显式登记适用范围、锚点、槽位和反例，并有独立回归测试。不得因单个例句在解码器中
加入不可复用的短语特判。

### 6.4 已选择内容

用户对某个分段作出选择后，该选择成为当前 composition 的硬约束：

- 后续输入只重算受影响的右侧路径；
- 不得静默替换已经选择的左侧分段；
- 点击首段、中段或末段改选时，其余分段及原始编码范围保持稳定；
- 只有用户明确提交整句时才整体上屏。

## 7. 动态调频

用户选择单字、词语、局部分段或最终整句时，应更新现有用户模型：

- 同码候选后续按使用次数获得可解释的用户增益；
- 可记录前一已提交文本形成上下文增益；
- 句内相邻分段采用有方向的词级二元关系 `前段 -> 后段`；仅记录 `后段 -> 前段` 的逆序关系不得提升正序路径；
- 二元关系只重排词典 lattice 中结构优先级相同的已有路径，不生成词典边、分段或候选文本；
- 句首使用上一已提交文本作为左上下文，句内使用当前路径的前一分段；上下文增益必须封顶并在解释结果中单列；
- 局部分段选择立即约束当前 composition，但只暂存在会话内，不能提前写入用户模型或提交整句；
- 最终整句提交同时学习最终分段序列、相邻分段搭配和整句身份；
- 分段与整句学习必须作为同一 mutation 原子持久化，只能全部生效或全部不生效；
- `Clear`、`Reset`、`Esc`、退格改变原始输入或宿主非计划终止 composition 时，未提交的局部分段学习必须丢弃；
- 学习写入必须支持 Broker mutation ID 幂等，重试不能重复计数；
- 用户必须能够通过现有管理工具忘记已学习候选或清理学习数据。

动态频次只在不违反结构优先级时决定顺序。高频单字不能因为用户增益重新压过一个有效的左起
多音节内置词语路径。

不得另建与现有 Yime 用户模型或 Rime 用户词典冲突的第二套不可管理学习数据。原生 Rime 会话仍由
Rime 自身负责学习；本节的 Go 模型规则只适用于自研 YimeCore 会话。

## 8. 候选 UI 契约

动态组句通过独立句子行展示，普通候选仍位于其下：

```text
句：［知识］［分子］［问题］
⇧1  ……
⇧2  ……
```

- 句子行每个单元对应一个词典分段，不得按显示汉字强制拆栏；
- 分段单元只显示预览文字，编码只作为内部稳定映射；
- 当前活动分段使用候选窗选中颜色或等价的可访问状态；
- 点击分段发送其原始 `{start, end}`，不得移动宿主插入点或抢走焦点；
- 点击候选只替换活动分段，非活动分段保持不变；
- UI-less 宿主保留 `Ctrl+Left` / `Ctrl+Right` 分段导航和键盘选词路径；
- raw input 非空但没有候选或句子时，自绘候选窗显示不可选择的“无匹配候选，按退格修改”，TSF 候选数仍为 0；
- `Esc` 取消当前 composition 并丢弃未提交的局部分段校对；
- 横排、竖排、高 DPI 和多显示器下，句子行与候选列表必须保持稳定几何关系。

候选序号固定为 `⇧1` 至 `⇧9`。裸数字始终是组成音码，不得增加裸数字选词模式或按上下文切换
数字语义。

## 9. 架构边界

- 自研动态组句在 YimeCore 的句子 lattice、稳定候选 ID 和 `State.Sentence` 上实现；候选 UI 不得
  自己复制一套分词器或语义排序器。
- Broker 只传递候选、句子、分段和活动范围，不根据显示文本重新切分。
- 不得通过 Go 侧候选切片改变原生 Rime 会话的可见候选数或分页；原生 Rime 继续拥有分页。
- 不得修改规范词典文本、规范拼音、音元 ID、基础音节码或生成词典来掩盖解码器错误。
- 不得从生成后的 Rime 词典反推上游拼音或音元语义。
- 不得把宿主编辑区 composition 点击恢复为动态组句入口；鼠标交互只发生在输入法自有候选窗。
- 所有分段必须保留来源、原始编码范围和稳定身份，以支持解释、改选、学习和回放。

## 10. 验收场景

### 10.1 核心示例

使用当前正式 variable 索引逐键输入 `7J9LKJ[va6L=ucztlkj`：

1. 输入 `7`、`7J` 时，候选只包含单字，“之”可以按静态频次领先“知”；
2. 开始第二音节后，存在真实词典前缀时，句子预览优先扩展为“知识”；
3. 后续词典存在“分子”时，预览形成“知识｜分子”；
4. 完成输入后，预编辑句必须为“知识分子问题”；
5. 当前词典没有同码“知识分子”整词时，分段为“知识｜分子｜问题”；
6. “之｜十分｜子问题”可以保留为解释器中的备选路径，但不得成为首选；
7. 整句提交前，宿主编辑区不得出现部分提交文本。

### 10.2 路径排序

使用合成歧义图同时提供：

```text
知识｜分子｜问题
之｜十分｜子问题
```

即使后一条路径每个词的静态频次都更高，前一条仍必须因左起词语优先成为首选。交换相同切分
结构中的同码词时，用户频次和静态频次仍应正常生效。

### 10.3 局部改选与学习

1. 生成至少两个分段的句子；
2. 点击首段并选择非首选同码词；
3. 确认本次 composition 未提交，后续分段未改变；
4. 先用 `Clear`、`Reset` 或 `Esc` 取消并重新输入相同编码，确认改选词没有获得用户增益；
5. 再次改选并明确提交整句，确认最终分段、相邻搭配和整句同时获得用户增益；
6. 模拟持久化失败，确认分段和整句均未产生部分学习；
7. 使用相同 mutation ID 重试，整笔学习的 generation 只能增加一次；
8. 从 journal 恢复后，分段、搭配和整句必须同时存在；
9. 忘记该候选后，排序恢复为静态或剩余上下文结果。

### 10.4 回归矩阵

自动化测试至少覆盖：

- 完整、变长、省键三种模式的等价真实索引案例；
- 首音节部分码、完整码、第二音节首码和后续逐码状态；
- 首音节单字候选跨页；
- 精确整词、词典前缀、无词回退和无效输入；
- 左起长词与后向高频短词的冲突；
- 正序二元搭配提升同结构路径、逆序搭配不反向生效，以及封顶后的二元增益仍不能推翻左起词语优先；
- 首段、中段、末段反复改选及最终原子提交；
- 用户模型保存、重开、幂等重试和忘记；
- Broker 序列化后的句子、分段、活动范围和稳定 candidate ID；
- 裸数字组码、`⇧1` 至 `⇧9` 选词和原生 Rime 分页守卫。

如果修改候选窗协议、布局或交互，还必须重新运行 x86/x64 C++ 契约测试和注册后宿主测试。只修改
引擎内部排序且状态协议不变时，至少运行 YimeCore、Broker 和候选包装器测试。

真实索引逐键解码的 $P95$ 和 $P99$ 应保持在项目当前规定的 $50\,\text{ms}$ 门槛内。测试报告必须
记录索引来源 ID、输入码、最终句子、分段范围和延迟。

## 11. 非目标

本阶段不要求：

- 引入神经语言模型或联网语义服务；
- 生成词典中不存在的新词；
- 自动插入、删除或替换候选汉字；
- 改写规范读音或实现新的语流音变规则；
- 改变原生 Rime 的分页、学习或 composition 所有权；
- 用单个示例宣称已经解决所有中文语义歧义。

需要更强语义模型时，应先定义离线模型来源、隐私边界、性能预算、确定性降级和可解释接口，再作为
独立阶段评审。

## 12. 完成定义

只有同时满足以下条件，才能声明动态组句任务完成：

- 四项核心原则均有对应实现和自动化回归；
- 核心示例在真实 variable 索引上得到“知识｜分子｜问题”；
- 三模式边界和逐键候选经过真实索引验证；
- 局部改选不会提前提交，且学习结果可保存、幂等和撤销；
- 候选 UI、裸数字、Shift 序号和分页守卫没有回归；
- 性能门槛通过，错误路径仍可通过解释器追踪；
- 若涉及安装态文件，已重新构建、打包、安装并在目标 x86/x64 宿主中验收，不能用源码测试代替。
