# 阶段 4B：融合儿化可解释反查

## 1. 结论

阶段 4B 为已经进入三模式运行附加词典的融合儿化路线增加独立反查旁表。用户在反查工具中查询
“一阵儿”等试点词条时，可以同时看到：

- 保持不变的儿缀兼容拼音；
- “显式词汇化儿化”的读音身份和 PSC 儿化来源；
- 融合所附着的原音节；
- 融合附着音节的基础四音元元组；
- 逐位置施加卷舌/鼻化特征后的派生儿化音元 ID；
- “基础音元 + 特征 → 派生儿化音元 ID → 物理键”投影；
- 等长、变长、省键三种融合输入编码。

反查只解释已经生成的融合输入别名，不从按键反猜唯一音值，不改写规范词典、标准拼音注释、候选
文字或候选排序。

## 2. 数据边界

生成器写出 `yime_erhua_reverse_source.tsv`。当前文件为 1 行标题加 131 行数据，恰好对应三种运行
附加词典中实际获得可追踪权重的 131 个显式儿化词条：65 条继承核心权重，66 条继承 PSC 低频外围
层固定权重 `1`。

旁表明确排除：

1. 任何尚未获得音元特征规则的记录（当前数量为 0）；
2. 任何仅因词尾有“儿”或拼音含 `r` 而推测的能产儿化；
3. 任何没有显式附着韵母证据、无法匹配已审音元特征规则的记录。

因此，旁表的存在不会扩大可输入候选集合，也不会把研究态记录伪装成已实现能力。

## 3. 文件格式

每行包含 12 列：

| 列 | 含义 |
|---|---|
| `record_id` | 显式儿化记录 ID |
| `text` | 保持不变的候选文字 |
| `source_kind` | 来源类型，当前为 `psc_erhua` |
| `compatibility_numeric_pinyin` | 儿缀兼容数字标调拼音 |
| `feature_rule_id` | 选用的音元特征改写规则 ID |
| `attached_syllable_source` | 被儿化附着的原音节 |
| `source_yinyuan_ids` | 儿化前的基础四音元元组 |
| `derived_yinyuan_ids` | 特征替换后的派生儿化音元元组 |
| `key_projection` | 基础音元 + 特征到派生 ID、再到物理键的可解释投影 |
| `full_code` | 等长融合码 |
| `variable_code` | 变长融合码 |
| `shorthand_code` | 省键融合码 |

该文件由 `yime-erhua-mixed-derive` 与三种附加词典一起生成；文件 SHA-256 和行数写入
`yime_erhua_mixed_manifest.json`。不得手工维护或脱离同一生成过程单独改写。

## 4. 运行与回退

独立反查工具从共享运行数据目录读取旁表，普通系统词典反查仍走原链路。旁表缺失时按旧版本兼容
处理：普通反查继续可用，只是不显示融合儿化解释。显式旁表存在时，不再同时展示由单字共享码拼出
且可能误读（例如把“儿”反解为 `ren2`）的“逐字拼接”结果。旁表发生变化时反查缓存自动失效。

Rime 用户数据刷新会复制旁表，但它不参与 Rime 候选生成。删除旁表只能关闭融合解释；删除三个
`yime_erhua_mixed_*.dict.yaml` 的 schema 依赖才能关闭融合候选。两种回退边界彼此独立。

## 5. 完整性门禁

- 反查行数必须与实际继承权重并导出的词条数相等，当前均为 131；
- 每条必须具有记录 ID、显式来源、兼容拼音、附着音节、特征规则、变换前后两套音元元组、键位投影和三模式码；
- 旁表哈希必须与生成清单一致；
- 三模式反查必须返回各自的融合码；
- 普通反查不得因旁表缺失而失败；
- UI 只在融合结果的详情区追加解释，不新增候选窗注释类别。

## 6. 下一步

1. 继续复核 131 条派生解释，发现语音或键感问题时按规则类修订，不逐词暗改；
2. 观察 `ã˞`、归并 `ɤ̃˞` 和 `u˞` 三组试行键位的安装态输入与反查结果；
3. 安装新构建后，在反查工具中用“刀刃儿”和“一阵儿”分别核对 PSC 低频、核心权重两种来源的
   三模式融合编码和完整详情。
