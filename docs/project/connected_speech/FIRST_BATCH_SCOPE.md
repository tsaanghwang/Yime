# 第一批实施范围：阶段 0 离线基础设施

## 目标

第一批只实现可重复的离线数据读取、结构校验和报告生成，以证明后续规则有安全入口。它不生成运行
别名，不修改 Rime 源词典，不导入用户词库，也不改变按键、候选、语言栏或宿主行为。

## 输入

1. 版本 1 的结构化审定记录；
2. 来源政策目录和来源文件 SHA-256；
3. 当前规范 `yime_syllable_decomposition.tsv`、布局和模式转换规则；
4. 项目自制回归样例，不包含外部材料全文。

## 建议文件范围

阶段 0 后续实施任务只允许新增或修改：

```text
go-backend/input_methods/yime/connectedspeech/model.go
go-backend/input_methods/yime/connectedspeech/validate.go
go-backend/input_methods/yime/connectedspeech/report.go
go-backend/input_methods/yime/connectedspeech/*_test.go
tools/audit-connected-speech.ps1
```

报告只能写入 `.tmp/connected-speech-audit/`。不得修改
`go-backend/input_methods/yime/data/`、安装包输入、PIME/Rime 会话代码或用户目录。

## 实施顺序

1. 读取并验证 `schema_version`、状态枚举、来源观察和四音元元组；
2. 强制隔离 `research_only`、`deferred`、`rejected`；
3. 将每条批准记录从同一语义四音元派生三种模式的试算结果；
4. 输出覆盖、码长、碰撞、排序影响、拒绝原因和输入哈希；
5. 禁用全部模块后重新计算规范基线哈希并比较；
6. 仅在报告全部通过后，提出阶段 1 的独立实现任务。

## 四音元人工复核样例

以下 ID 来自现行 `yime_syllable_decomposition.tsv`，用于证明逐位置改写可以直接审查；它们不构成
运行词典改动。

| 现象 | 音节 | 规范四音元 | 语流四音元 | 逐位置改写 |
|---|---|---|---|---|
| “一”在去声前变调 | `yi1 -> yi2` | `[N23,M01,M01,M01]` | `[N23,M03,M02,M01]` | 呼音 `M01→M03`；主音 `M01→M02` |
| “不”在去声前变调 | `bu4 -> bu2` | `[N01,M04,M05,M06]` | `[N01,M06,M05,M04]` | 呼音 `M04→M06`；末音 `M06→M04` |
| 词汇轻声兼容 | `zi5` | `[N13,M20,M20,M20]` | 同规范兼容表示 | 无表层改写；`5` 身份保持 |
| 儿缀兼容 | `er5` | `[N12,M23,M23,M23]` | 同规范兼容表示 | 融合儿化另从结构化记录派生 |

融合儿化、具体轻声表层调值和语气词“啊”的派生首音在正式目标 ID 未审定前，只能出现在报告的
`research_only` 区，不得使用占位 ID 生成键码。

## 明确排除

- 不批量把无调音节判为轻声；
- 不把来源末尾 `r` 全部转换为 `er5`；
- 不恢复或猜造所有轻声的深层本调；
- 不自动增删“儿”，不自动把“啊”替换为“呀、哇、哪”；
- 不增加 `[ŋ]`、`[z]`、卷舌类首音 ID 或布局键位；
- 不实现能产儿化、上声全局规则、同化或异化运行规则；
- 不改变标准拼音注释、规范候选权重和用户学习记录。

## 验收

- 相同输入连续运行两次得到逐字节一致的报告和清单；
- `research_only` 等隔离状态的运行输出数量为零；
- 三模式记录集合按 `record_id` 一一对应，任何模式不得缺项；
- 等长模式保持每音节四码；在首音（包括虚首音）不省略的前提下，变长和省键模式按音变后的
  四音元重新投影，每音节均须满足 `2 ≤ len ≤ 4`，码长允许增加、减少或不变，并须逐项报告变化；
- 报告列出所有新增碰撞和潜在首选变化，第一批不允许实际首选变化；
- 阶段 0 运行前后规范数据文件哈希完全一致；
- 测试不得访问已安装 PIME、用户 Rime 目录或外部版权材料。
