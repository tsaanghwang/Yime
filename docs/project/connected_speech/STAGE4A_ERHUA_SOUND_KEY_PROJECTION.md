# 阶段 4A：儿化音元与键位多对一投影

## 1. 结论

阶段 4A 把“儿化后实际存在的音元”和“用户按下的物理键”拆成两个层次：

1. 派生儿化音元保存音质、鼻化、卷舌和调级等语音属性；
2. 键位类只保存一次输入动作的调级类别；
3. 多个不同的派生音元可以投影到同一个键位类；
4. 键位类再借用现有 `M22/M23/M24` 的布局位置，不把这些载体 ID 冒充为所有派生音元的实际音值。

因此，工程可以继续增加和修订儿化音元，而不必为每个新音值增加一个物理键，也不必重排现有布局。

## 2. 当前试点边界

当前显式儿化来源包共有 131 条记录：

- 29 条为 `dual_route_ready`，同时具有儿缀兼容和融合儿化路线；
- 102 条为 `suffix_only_encoding_pending`，只保留儿缀兼容路线；
- 29 条双路线记录中，15 条能够从三种规范词典继承相同权重并进入运行附加词典；
- 14 条因三模式既有词典均无权重而延期；
- 正式运行产物保持每模式 30 条路线、三模式合计 90 行。

本阶段没有新增或删除运行词条，没有改变任何候选文字、权重或编码。用户已在安装态验证过“一阵儿”
的融合路线；其余宿主和反查行为仍按既定回归计划继续验证。

## 3. 音元与键位结构

机器真源为 [erhua_sound_key_projection.json](erhua_sound_key_projection.json)。当前登记：

| 类别 | 数量 | 状态 | 用途 |
|---|---:|---|---|
| 口腔中央卷舌音元 `[ɚ]` | 3 | `runtime_pilot` | 高、中、低三个调级，供当前 4 类融合儿化使用 |
| 后部 `[ɑ]` 鼻化卷舌音元 | 3 | `research_only` | 为部分 `-ng` 儿化讨论预留，禁止导出 |
| 弱央元音鼻化卷舌音元 | 3 | `research_only` | 为弱化的 `-ng` 儿化讨论预留，禁止导出 |
| 输入键位类 | 3 | 布局载体 | 高、中、低分别借用 `M22/M23/M24` 的键位 |

当前 4 个融合表层类为：

- `ERHUA-ORAL-ER`：三个韵母位置均投影为中央卷舌音元；
- `ERHUA-ORAL-UER`：保留第一位置的 `u` 类音元，后两位置投影为中央卷舌音元；
- `ERHUA-ORAL-I-ER`：保留第一位置的 `i` 类音元，后两位置投影为中央卷舌音元；
- `ERHUA-ORAL-UMLAUT-I-ER`：保留第一位置的 `ü` 类音元，后两位置投影为中央卷舌音元。

研究态的两组鼻化卷舌音元目前只证明数据结构可以容纳“不同音元共用同键”，不构成普通话儿化
语音事实的最终裁决，也不能被运行派生器引用。

## 4. 派生门禁

`yime-erhua-mixed-derive` 在写出词典前必须完成以下检查：

1. 音元 ID、键位类、表层类和调级均唯一且完整；
2. 每个键位类至少接收两个不同音元，证明模型不是把音元和键位换名后一一绑定；
3. 所有载体 ID 和保留位置 ID 均存在于当前 `yime_yinyuan_layout.json`；
4. 逐条把所有路线、所有模式的 Yinyuan ID 重新投影成键位字符串，并与来源包中的编码一致；
5. 29 条融合路线必须全部投影成独立音元元组；
6. 运行试点只能引用 `runtime_pilot` 音元，任何 `research_only` 音元进入导出即失败；
7. 融合路线在变长、等长、省键任一模式中都不得比儿缀兼容路线更长；
8. 候选文字、显式来源授权、三模式权重继承和禁止能产类推的既有门禁继续有效。

生成清单记录投影源文件与布局文件的 SHA-256，并报告 9 个音元、3 个共享键位类、4 个试点表层类
和 29 条已投影记录。运行词典内容哈希与阶段 4A 前保持一致。

## 5. 后续顺序

1. 可解释反查已在阶段 4B 完成：显示兼容拼音、儿化身份、派生音元和最终键位，不从键位反猜唯一音值；
2. 对 14 条缺权重记录补齐规范候选来源后，重新经过三模式权重门禁；
3. 逐类审定 102 条待决融合记录，禁止由词尾“儿”或拼音 `r` 自动类推；
4. `-ng` 鼻化卷舌类只有在音质映射、来源词条和三模式碰撞报告均通过后，才可从 `research_only`
   申请进入试点；
5. 能产儿化、自动增删“儿”和未写“儿”的口语提示仍不属于本阶段。

## 6. 回退

删除三个 `yime_erhua_mixed_*.dict.yaml` 的 schema 依赖即可整批关闭融合试点；删除融合路线时仍保留
规范词典和儿缀兼容输入。音元—键位投影文件是构建时来源，不由 PIME 在运行时读取，也不修改用户
词库或学习数据。

阶段 4B 见[融合儿化可解释反查](STAGE4B_ERHUA_REVERSE_LOOKUP.md)。
