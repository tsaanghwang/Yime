# 阶段 6A：语气词“啊”离线末音分类审计

阶段 6A 只建立可复算的离线范围、校验器和报告器，不生成或接入运行时候选。

审计器保留“候选文字以‘啊’结尾且末音节解码为 `a5`”的既有六类分类基线，同时新增按每个“啊”
出现位置生成的 `position_inventory.tsv`。位置政策不再把字符串末尾当作音变条件，而是检查同一显式
候选中是否存在明确的前接音节：

- 词首或独立“啊”没有可确定的前接末音，保持来源规范读音，由说话人按语境选择；
- 句中或句末的“啊/a5”只要有明确前接音节，均按其末音归入六类；
- 所有有前接音节的音变路线都采用双轨制：规范未音变 `a5` 路径永久保留，顺同化结果只能成为并行别名；
- `A啊A` 等固定构式即使从普通词语同化角度分析，表层结果也与语气词顺同化相同，统一放在本模块；
- 有前接音节但规范读音不是 `a5` 的记录保持原样，不借本规则改写。

程序读取前一音节在物化音节分解表中的规范韵母，按固定优先级归入六类：`u`、`n`、`ng`、
舌尖前元音、舌尖后元音或 `er`、其余元音尾。

本阶段坚持以下边界：

- 候选文字始终保持原样，不自动把“啊”替换为“呀、哇、哪”；
- 六类范围全部为 `research_only`、`runtime_eligible=false`；
- 本阶段只做分类，不论目标首音是否已有正式 ID，均不做三模式投影；N26/N27 后来正式接入后由阶段 6B 承接；
- 不建立跨词边界的全局相邻音节类推；
- 位置清单只登记显式候选内部的“啊”，词首项不得因未知外部上文生成同化别名；
- `position_inventory.tsv` 必须把有前接音节的 `啊/a5` 标成 `parallel_alias_keep_canonical`，不得替换规范路径；
- 输入词典、规范码表和音节分解表在审计前后的 SHA-256 必须一致；
- 报告必须完整列出已分类记录、六类计数和未决项，运行时别名计数必须为零。

运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\audit-stage6a-particle-a.ps1
```

输出位于 `.tmp/particle-a-stage6a-audit/`。当前实算共见 6,754 个“啊”位置：20 个没有前接音节；
6 个虽有前接音节但不是 `a5`；其余 6,728 个“啊/a5”有明确前接音节，其中句中 71、句末 6,657。
阶段 6A 是分类与位置政策基线，不能因为后续首音 ID 已正式化而变成运行时生成器；当前阶段 6B
仍只投影原有句末 6,657 条，句中 71 条须由后续独立扩展保持可回退性。
