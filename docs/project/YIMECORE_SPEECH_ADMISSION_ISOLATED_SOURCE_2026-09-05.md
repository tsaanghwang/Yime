## 本轮发现并修正的具体问题

前两轮完整运行未通过，原始 FAIL 保留。定位到 `full / T3-5B-003 / alias / 第 8 键`：模块尚未启用时就超过原有 50 ms 请求门限。核心 FileEngine 与 core-only Bundle 对照均约 76.51–78.04 ms，因此不是新语流模块引入的回归，也不推断用户已在日用中遭遇该问题。

该路径的一个尾部前缀有 3,102 条记录，却只有 4 个单字候选；为保持既有筛选语义，扫描窗口依次扩大至 4,096。旧线性插入 TopK 在此接近二次排序成本。源码修正仅将 `limit > 64` 的前缀 TopK 改为最差根有界堆，最后仍按原 `betterFileRecord` 排序；没有改分词、过滤、候选数量或超时。

- 6,418 条合成记录、81 个 prefix／limit 组合，未缓存／缓存输出逐项等价独立旧算法；另有随机顺序直接堆比较，索引内容及来源身份不变。
- 同一组 8,480 次逐键测量复跑，超过 50 ms 为 0 次，最大 4.1711 ms；原失败点降至约 2.09–4.17 ms。
- 随后以全新目录完整运行并通过上述 7 个 Broker 阶段。**修正仅在本轮新源码和隔离二进制中，尚未更新安装版。**
