# TEST-PC YimeCore 完整真实宿主测试矩阵

更新：2026-09-10。目标机器：`计算机`（较旧的主流 x86-64 测试机）。当前产品：`0.1.0-local.13`，manifest SHA-256 `133c91fe205fcae911fa701a278465dad040e7dadce006b541697b656e50405a`。

## 判定边界

- “真实宿主”必须是实际桌面应用、实际注册 TSF、用户物理选择当前 **音元拼音** 后的键盘操作；源码测试、合成 registered-host 和交叉编译不能代替。
- DLL 加载证据与人工输入结果分别记录。加载当前 DLL 不自动证明 profile 已激活或输入通过。
- 不更改系统默认输入法，不读取正文、窗口标题、剪贴板、命令行、用户词库或学习数据。只使用临时空白文档和固定合成测试串。
- 历史名称 **Yime 自研栈试验版** 不属于当前产品，不能用于本矩阵。
- 自动化无法控制任务栏输入法时，由开发者本人进行物理选择与按键；只把该情况记为自动化限制，不记作产品失败。

## 每个“宿主 × 模式”的固定检查

1. 打开新的空白测试面，物理选择任务栏中的当前 **音元拼音**；不改变默认输入法。
2. 输入 `tf-cN`，确认出现组合和候选；按 `Space` 正常提交。
3. 再输入 `tf-cN`，确认候选序号显示为 `⇧1` 等 Shift 标签；按 `Shift+1` 提交首候选。
4. 输入裸数字 `2`，再输入 `3`，确认两者继续进入组合而不是选择候选；按 `Esc` 取消。
5. 用可产生多页候选的固定合成输入，执行下一页、上一页并提交；记录方向键/翻页键是否正常、页数和每页候选数，不记录候选正文。
6. 输入 `tf-cN` 但不提交，切到另一个空白测试宿主再切回：原预编辑被取消，不固化原始 ASCII，不自动选汉字，不删除较新的组合；之前已提交的固定测试文本保留，并可继续输入。
7. 点击语言栏左键两次，确认模式可切换并回到原状态；打开右键菜单后关闭，确认宿主不退出、菜单不是静默无响应。若操作候选数菜单，设置值、重开显示值和实际页大小必须一致。
8. 正常关闭并重开宿主，重新物理选择 **音元拼音**，确认可继续组合和提交。
9. 同一项连续执行 3 轮；任何失败都保留轮次和现象，不以随后成功覆盖。

## 结果字段与通过规则

每项人工结果只允许 `pass`、`fail`、`not_run` 或 `unavailable`，并记录：宿主、架构、模式、轮次、是否物理选择当前 profile、组合提交、裸数字、Shift 标签、Shift+1、翻页、失焦取消、已提交文本保护、切回恢复、语言栏、重开恢复。不得从一句“没问题”补造未逐项确认的布尔值。

最终通过要求：四个必需宿主的 3 种模式、每种 3 轮全部 `pass`；进程均精确加载当前安装根中匹配架构的 `YimeTextServiceExperiment.dll`；默认输入法和生产 Rime/PIME 未被测试改变。任何缺少的宿主或未执行项保持 `unavailable/not_run`，矩阵不得标为完成。
