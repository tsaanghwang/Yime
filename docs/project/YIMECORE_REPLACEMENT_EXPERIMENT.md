# Yime 自研栈并行替换试验

> 状态：E0 最小内核与合成烟雾已通过；真实词典和 Rime 对照尚未开始，未批准切换任何生产组件  
> 试验分支：`codex/yimecore-replacement-experiment`  
> 原则：先并行、后比较；逐层验收；失败即保留现状

## 1. 目的

本试验验证 Yime 能否逐步建立一套更适配四音元语音编码体系的自主实现：

1. `YimeCore`：词典索引、编码切分、候选搜索、排序、用户学习和语流音变路径；
2. `YimeBroker`：会话、进程隔离、协议、用户数据和运行维护；
3. `YimeTextService`：只负责 Windows TSF/COM、按键转发、预编辑、候选呈现和提交。

试验不是一次性重写，也不以复刻 librime/PIME 内部结构为目标。现有 Rime/PIME 链是生产基线和回退路径；只有全部门禁通过后，才允许逐项改变默认实现。

## 2. 当前、试验和目标结构

当前生产结构：

```text
PIMETextService.dll
    -> PIMELauncher / Go server.exe
    -> Yime Go TextService
    -> nativeBackend / cgo
    -> librime (C++)
```

试验期结构：

```text
现有 PIME/TSF 与 Go TextService（默认不变）
    -> CandidateEngine
       |- RimeAdapter -> librime       [生产基线]
       `- YimeCore                     [试验]
```

目标结构仅在试验全部成功后成立：

```text
YimeTextService.dll (C++，薄 TSF/COM 层)
    -> IPC
YimeBroker.exe (Go，会话、协议、进程和用户数据)
    -> CandidateEngine
       |- YimeCore                     [目标默认]
       `- RimeAdapter                  [迁移期回退]
    -> 只读静态索引 + 独立用户学习库
```

词典构建是旁路，不进入按键热路径：

```text
仓内规范真源 + YIME_LEXICON_EXTERNAL_ROOT 下的锁定来源
    -> Python 离线清洗、证据审计、音变派生
    -> Go 索引构建器
    -> 带版本和哈希的只读运行索引
```

## 3. 不可跨越的试验边界

- 不读取 `Yime-python-prototype`、`Yime-prototype` 或其他原型仓库。
- 不把大型词库、用户库、编译缓存或外部归档复制进 Git。
- 不逐函数翻写 librime/PIME；自主组件依据 Yime 需求、公开算法和黑盒行为契约实现。
- E0 至 E4 不替换或重构 TSF/COM 文本服务。
- 未通过切换门禁前，不删除 librime、不改变安装包默认后端、不迁移真实用户数据。
- 原生 Rime 会话继续拥有原生分页权，`nativeBackend.UsesBackendCandidatePaging()` 保持为 `true`。
- Base 数字键始终是编码键；候选直选仍由表层解释为 `Shift+1` 至 `Shift+9`。
- 语流音变继续从规范四音元记录派生；不得在按键回调中猜造词界、语气或韵律。
- 任何试验数据写入 `.tmp/yimecore-experiment/` 或独立外部目录，可完整删除回退。

## 4. 中立引擎契约

`CandidateEngine` 不依赖 PIME 请求类型、Rime session、Windows 句柄或具体词典文件格式。契约只描述：

- 编码输入、退格、清空；
- 当前原始输入和候选快照；
- 通过稳定候选 ID 选择并提交；
- 引擎能力声明，例如分页、句中光标、遗忘和用户同步；
- 可重放、可比较的确定性状态转换。

候选窗口标签、语言栏命令、TSF composition 和 IPC 都属于契约外的适配层。RimeAdapter 与 YimeCore 必须通过同一批中立轨迹测试，但允许对明确记录的产品改进产生不同候选排序。

## 5. 分阶段实现细目

### E0：边界、基线和最小内核（本分支启动项）

- 新增不依赖 PIME/Rime/Windows 的 `engineapi` 包。
- 新增纯 Go `yimecore`，只实现小型内存索引、前缀/整码查询和会话状态。
- 数字必须按普通编码字节进入 raw input。
- 新增固定轨迹、候选确定性、提交清空和错误边界测试。
- 新增合成词典性能烟雾工具；输出 p50/p95/p99/max 和正确性检查到 `.tmp`。
- 生产 `createRimeBackend` 工厂保持不变。

E0 只证明接口和最小热路径成立，不证明完整词典、组句或替换资格。

### E1：只读编译索引

- 设计版本化索引格式：文件头、模式、来源清单哈希、记录数、分区和校验和。
- Go 构建器只读取仓内合规真源或 `YIME_LEXICON_EXTERNAL_ROOT`。
- 运行时优先使用连续字节区、整数偏移和惰性文本解码，避免百万 Go 对象常驻。
- 完成变长、等长、省键三种模式的同源构建和交叉完整性检查。
- 对同一锁定输入连续构建两次，索引哈希必须一致。

### E2：切分和动态组句

- 将连续编码表示为候选格图，不从生成词典反推规范读音或音元语义。
- 先实现确定性动态规划或 beam search，再引入上下文评分。
- 对每个候选保留输入区间、词典来源、规范路径和可选别名路径。
- 固定长句、歧义切分、退格、句中改选和连续提交轨迹。

### E3：排序与用户学习

- 分离系统静态分、上下文分和用户学习分，所有分值可解释、可版本升级。
- 用户库独立于静态索引，支持遗忘、备份、恢复、损坏隔离和原子升级。
- 先使用轻量统计方法；神经重排器若出现，只能是有时限、可关闭的可选层。
- 建立与现有 Rime 学习行为的并行观察，不直接迁移运行中锁定的 `*.userdb`。

### E4：语流音变原生路径

- 复用现有“规范四音元 -> 等位替换 -> 三模式投影”的唯一方向。
- 将已审定词/短语别名表示为同一候选的多条输入路径，避免重复候选污染。
- 只有在来源、边界和排除清单可验证时，才试验跨词或构式级动态规则。
- 与现有 Rime 附加词典逐阶段比较收益、碰撞、排序、延迟和回退结果。

### E5：自研中层 / Broker

- 在 YimeCore 已可用后，才冻结版本化 IPC 协议。
- Broker 运行在普通用户权限下，负责会话、超时、崩溃隔离、索引切换和用户数据。
- 安装、注册和升级提权仍由安装器处理；Broker 不成为提权代理。
- 先让现有文本服务连接新 Broker，同时保留现有 server.exe 回退。

### E6：自研表层 / TextService

- 最后实现薄 C++ TSF/COM 层，不承载词典、音变、排序和用户学习。
- 以现有 PIMETextService 为黑盒行为基线，重新验证 x86/x64、候选窗、语言栏、失焦、应用退出和重启路径。
- 新旧文本服务不得共享注册标识或安装目录进行破坏性覆盖；采用并列试装和独立卸载。

### E7：切换与退役

- 只有 E0 至 E6 全部门禁通过，并完成签名安装包真实宿主验收，才提交默认切换提案。
- 默认切换与删除旧组件必须是两个不同发布阶段。
- 至少一个稳定发布周期保留 RimeAdapter 和旧安装包回退证据。

## 6. 比较矩阵与成功门禁

所有比较必须使用同一机器、同一锁定词典快照、同一输入轨迹和相同候选上限。

| 维度 | E0/E1 门禁 | 最终切换门禁 |
|---|---|---|
| 正确性 | 固定轨迹状态转换 100% 通过 | 三模式、长句、改选、学习和音变验收 100% 通过 |
| 确定性 | 同输入结果和构建哈希一致 | 安装前后索引及行为证据一致 |
| 延迟 | 记录 core p50/p95/p99/max，不据合成数据切换 | 真实轨迹 p95 不比 Rime 基线慢 10% 以上，p99 不慢 20% 以上 |
| 卡顿 | 合成重放无错误和非预期分配增长 | 100,000 次真实轨迹重放无单次引擎处理超过 50 ms |
| 内存 | 记录索引构建和查询分配 | 启动完成 RSS 不比当前基线增加 20% 以上 |
| 恢复 | 删除 `.tmp` 即回退 | 引擎、Broker、文本服务均有独立回退开关和安装包 |
| 数据 | 只用小夹具或锁定来源 | 不读原型仓库、不提交大词库、用户数据升级可逆 |

相对阈值只能在取得第一份真实基线前调整；取得基线后，任何放宽都必须单独评审，不能为了让试验通过而修改。

## 7. 证据目录

每轮试验写入独立目录：

```text
.tmp/yimecore-experiment/<stage>/<timestamp>/
    manifest.json
    correctness.json
    latency.json
    memory.json
    source-hashes.json
    comparison.json
```

证据必须记录 Git commit、dirty 状态、Go 版本、OS/架构、索引来源 ID/哈希、轨迹 ID/哈希和引擎实现 ID。合成 E0 烟雾不能冒充真实 Rime 对照结果。

## 8. 当前退出条件

本分支首轮只有在以下条件同时满足时才算 E0 完成：

1. 中立契约和最小 YimeCore 不导入 PIME、Rime、cgo 或 Windows 包；
2. 数字编码、退格、清空、精确优先、稳定排序、提交清空测试通过；
3. 合成重放产生结构化性能证据；
4. 现有 Rime 默认工厂和原生分页守卫未改变；
5. `go test` 稳定集通过；
6. 文档明确标记“未批准切换”。
