# YimeCore 本机独立产品实施计划

日期：2026-09-02。目标：将已经可用的自研栈试验版整理为开发者可在 MYCOMPUTER 原生 x64 日常使用、独立安装和维护的产品，然后再评审其他机型适配。

本文是实施计划，勾选项及阶段记录才表示实际进度。2026-09-04：用户明确批准本机 WOW64 x86 应用宿主解冻，与 x64 L5/L6 同步推进；ARM64、其他实体机、老旧 x64 和硬件模拟仍冻结。x86 采用当前产品身份重新源码构建，旧 x86 载荷继续只读保留，详见 [x86 解冻计划](YIMECORE_X86_RESUMPTION_PLAN_2026-09-04.md)。2026-09-03：`local.8` 固定恢复、自身完整卸载重装、两次任务栏可见性、安装态 x64 registered-host、真实 Word、Edge 和重启后加载 local.8 DLL 的 VS Code 通过；卸载间隙用户 TIP 子树完全不存在，重装后为 DWORD `Enable=1`。当时冻结的 x86、默认输入法、生产组件及用户数据保持不变。`local.9` 朱红色 profile 图标候选已完成 native x64 构包、隔离验证和原位安装；正常重启后 Runtime/Broker、Shell-Core 9707/9708、系统 Run/COM/profile、用户 TIP、71 文件清单和默认输入法保护通过，用户确认系统图标“已红”，并在加载 local.9 x64 DLL 的新 VS Code 进程中确认组合提交、裸数字组字和 `Shift+1` 三项通过。L4 当前候选验收完成。包内 CMD 未显示结果即退出的可用性缺陷在工作树以通用 `PASS/BLOCKED`、退出码和交互暂停修复，描述版本升至 `local.10`，不新增版本号专用日常运行文件，也不要求仅为此提示改动再次安装。长期日常使用确认和新的本机 x86 门禁仍待完成，未批准公开发布。

## 1. 本阶段的终点

2026-09-03 过程更新：`0.1.0-local.5` 完成“音元拼音”新 CLSID/Profile 的本机原生 x64 迁移；安装后的冻结用户 TIP 已由固定证据修复。该修复封装为 [local.6](../YIMECORE_LOCAL_PRODUCT_LOCAL6_2026-09-03.md) 并完成原生升级、实际备份恢复和失败升级回退。local.6 自身卸载重装遗漏新身份当前用户 `Enable` 的假 PASS 已撤回，local.8 完成长期修复和实际重验；Word、浏览器、开发工具及 local.9 后续登录启动已经通过。长期日常使用确认仍待完成，因此尚不标记 `local_product_ready=true`。

身份迁移已于 2026-09-03 获用户批准并完成注册验收：活动 x64 使用独立 CLSID/Profile 和名称“音元拼音”，冻结 x86 继续保留旧 CLSID/Profile、旧名称和原始 payload。真实宿主仍按 L4 单独验收，不反向否定已经通过的身份与注册保护证据。

产品显示名为 **音元拼音**，仅限本机使用。满足以下条件才标记 `local_product_ready=true`：

- 一个有版本、来源和完整 manifest 的自包含 x64 安装包，可以从仓库外目录安装、升级、备份、恢复、诊断和卸载；安装后不需要 `C:\dev\Yime`、Go、CMake、Python 或旧试验包帮助其运行和维护。
- 输入运行链仅为自研 TSF、Broker、YimeCore 与包内静态数据，不使用 Rime/PIME 作为运行依赖。生产版可以继续安装并作为用户可选择的回退路径；“独立”不等于必须删除生产版。
- 三模式输入、设置、学习和用户词库在本机真实应用可用；普通权限宿主可正常输入。管理员权限仅用于确有需要的注册/安装步骤，日常运行不要求管理员窗口。
- 试验版到独立开发版的数据继承、实际升级失败恢复、产品自身卸载后保留数据重装，以及最终候选版本的登录自启动均有本机证据。
- 已有核心/宿主验收可以继承，但必须说明对应的二进制、数据和测试范围；修改影响的部分需要重验。没有数据丢失、宿主崩溃、持续无法输入或安装回退失效的已知阻塞。
- 开发者完成约定的日常试用并确认能作为本机常用输入法。建议至少两个正常工作日，覆盖登录、切换应用、长文本和重开宿主；这是拟定验收窗口，不自动创建后台监控任务，也不自动修改默认输入法。

本机可用、公开发行、生产版退役是三个不同状态。签名及冻结机型不作为本阶段未完成事项反复阻塞，但不能被标为通过。

签名证书正在申请，等候审批，暂缓相关事项。

可继承的基线：

- 当前已安装包：`yimecore-e6c-4bfa828009d1-324e46fc`；manifest SHA-256 `324e46fc5c930d79de713b1fe8d4a0c7cefa884c88b25721dec50cb3c2ed4431`。`yimecore-e6c-45b389e530c0-8d48953a` 仅因冻结 x86 注册引用继续保留，不表示该架构已恢复为活动目标。
- HEAD 为 `45b389e530c02d12924beeadcc5b8fd9543a3821`，工作区存在本阶段修改和未跟踪文件。不能仅以 HEAD 冒充全部当前源码身份，也不能为发布清理或丢弃用户修改。
- [原生数据与回退闭环](../YIMECORE_NATIVE_LOCAL_CLOSURE_ACCEPTANCE_2026-09-02.md)已通过：两份备份、实际恢复、失败升级回退，302 个归档文件及生产注册等均复核通过。
- [登录自启动](../YIMECORE_REBOOT_AUTOSTART_ACCEPTANCE_2026-09-02.md)和已有 Word/记事本物理输入证据有效；不再把这些旧包通过项当作尚未完成。
- 当前本机性能记录：正确性、交互预算和内存预算通过，严格学习相对开销比值仍是非阻塞告警，不要求转成 C++。

必须开发，而不是只改显示名称的缺口：

1. `Upgrade-YimeCore-Trial.cmd` 当前要求已有试验安装，`run-e6c-package-experiment.ps1` 从既有包复制起步。新产品的构包与首装不能靠旧安装存在。
2. 最近的恢复/回退及编码保护在仓库脚本中执行；安装目录内维护脚本并非当前同一版，辅助脚本还含仓库和 `.tmp` 假设。
3. 历史 E6-C 包与通用维护器仍有多架构必需载荷/注册假设；`NativeX64Rehearsal` 仅是故障演练专用，不能直接拿它充当正常 x64 产品安装模式。
4. 当前产品名称、路径、工具和证据沿用试验约定；需要固定产品契约、版本与唯一入口，而不是同时留下多套各自修复的维护代码。
5. 现有 E7 面向生产切换，不能用删除其发布门槛来证明开发者本机版就绪；需要独立的本机验收汇总。

## 3. 设计默认值与不做事项

### 3.1 尽量原位晋级，不制造无必要迁移

活动本机产品的 x64/x86 TSF 表面共同使用 CLSID `{E40FA752-BB96-461D-A51D-F40EB437EC65}` 和 Profile `{126F54C6-E9B1-4E22-8652-03224CBD49F9}`。旧 CLSID `{41EC6C9B-E8D2-4E1E-9E7C-5CA3DAF0F66B}` 与 Profile `{607895A8-9504-4A2E-9BB1-2C159E3A1757}` 保留给历史封存试验。升级事务先完整保存旧 machine/user TIP 子树及 payload 引用，再按包描述符移除当前身份注册并注册“音元拼音”；不得改写或执行旧身份二进制。

现有数据目录、日志 source ID、学习命名空间和稳定内部文件名继续保留；目录或内部名称含 Trial/Experimental 不代表运行依赖 Rime。产品描述集中管理显示名称、活动 GUID、冻结旧 GUID、程序相对路径、数据版本和支持范围。本次只迁移显示身份，不迁移用户数据命名空间。

第一包可以保留已验证的二进制文件名，先解决自包含和维护一致性，不以全仓重命名作为验收要求。

### 3.2 新包本机 x64/x86 TSF 与冻结旧身份注册兼容

正常本机产品载荷包含 x64 Runtime/Broker/工具以及由当前源码和身份构建的 x64、x86 TSF 表面；x86 只服务本机 WOW64 32 位应用。ARM64 仍不构建、不执行。旧试验包归档中的旧身份文件继续原样保留并带来源哈希。

当前冻结 x86 注册可能仍引用旧安装根：原位晋级不能把该根当作普通旧版本删除。维护计划必须静态枚举引用，标记为受保护的兼容保留根；本阶段不修改冻结注册，也不执行冻结注册工具。留存不等于支持或测试通过。

为新产品定义单独、严格的本机双 TSF 架构清单契约，不通过删除旧 E6-C 的文件检查来让残缺包“通过”。除 `x86/` 下三个 TSF PE 必须为 I386 外，Runtime、Broker 和工具仍必须为 AMD64；未知清单、漏列文件、越界或重复路径、错误架构和哈希错误一律拒绝。

### 3.3 本轮明确不做

- 不卸载生产 Rime/PIME，不更改默认输入法；默认切换与生产退役须另行明确请求。
- 不改核心实现语言，不重做已通过的核心算法研究；不为非阻塞微基准比值反复优化。
- 不扩大语境音变规则范围，不把已有受审定功能全部重写；已有能力按当前范围保留。联网自动同步、额外离线同步产品功能不进入本轮；备份恢复不是同步功能。
- 不采购/租用机器，不恢复 ARM64、老旧 x64、其他实体机或硬件模拟；x86 仅指已批准的本机 WOW64 应用宿主。
- 不关闭系统签名检查或修改应用权限以运行未签名包；本机如被安全策略实际阻止，报告准确限制。

## 4. 实施顺序与验收出口

依赖顺序：L1 → L2 → L3 → L4 → L5 → L6。每一步有明确产物，失败只退回受影响步骤，不从 E0 重来。

| 阶段 | 实施内容 | 完成出口 |
|---|---|---|
| L1 固定身份与源码基线 | 产品描述、兼容身份清单、源码内容哈希、版本约定、功能保留清单 | 能明确“构建了哪份源码、使用哪些数据、管理哪些注册项”；用户工作区修改未丢失 |
| L2 自包含 x64 构包 | 从空 staging 构建 TSF/Broker/工具，显式获得索引/资源，打包全部维护依赖 | 不读取已安装试验包也能生成完整产品包，依赖审计和 x64 测试通过 |
| L3 产品安装维护入口 | 首装/升级/卸载、原位晋级、备份恢复、系统视图校验、权限分离 | 仓库外运行包内命令可维护产品；不存在“必须运行仓库新版脚本才能修好”的缺口 |
| L4 候选包实机验收 | 固定 RC，完成受影响功能、迁移/回退、自身重装、登录自启动 | 新产品版本对应的本机验收证据完整，生产与用户数据保留 |
| L5 日常使用与有限宿主扩展 | 在本机常用应用持续使用，只修实际阻塞及回归 | 开发者确认可日常使用，已知限制与复现方式明确 |
| L6 本机版本封存 | 冻结包、源码身份、数据版本、帮助与恢复介质，汇总本机就绪结果 | `local_product_ready=true`；公开发行仍单独判定，其他机型仍待解冻审批 |

## 5. 开发者参与和重测节奏

L1–L3 以代码、包内夹具、静态审计和自动测试推进，不反复要求用户升级重启。L4 形成完整候选包后安排一次原生维护窗口，统一完成安装及相关维护验收；最终候选再做必要的正常重启。真实任务栏操作或 UAC 需要人工时才明确请求。

不能自动操作独立任务栏不是产品阻塞；新开宿主未选择 Yime 也不是失败。物理可用与自动化限制必须分开记录。发生 DLL 占用不强杀 Explorer、不强删锁定 DLL。

每次发现数据变化、生产注册改写、错误 SID、无法恢复旧包或无法输入时立即停止该轮，保留归档、原件与准确阶段；修复后只重新生成受影响的候选和证据。

## 6. 其他机型的恢复条件与建议顺序

只有 L6 通过、开发者确认本机可用并明确批准解冻后，才制定新范围配置。拟议顺序为：其他当前主流 x64 实体机 → 有明确需求的 ARM64 → 再评估 x86 是否仍值得支持。老旧 x64 不自动恢复为支持目标。

这只是后续顺序建议，不是现在开始适配、采购或云测试的授权。联网同步与新增语境音变能力再按独立产品版本路线单独排期。
