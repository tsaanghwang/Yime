## #68: confirmed API rejection recovery

The client previously disconnected after every event error. A 129th composition character was rejected without mutation, but Backspace/Clear could no longer be sent. Recovery is now restricted to HTTP 400/409 rejections with the current session identity, non-decreasing authoritative revision, valid state/modes, and no commit. A 400 must retain the requested base revision. The state is rendered without replaying the rejected event or a previous commit; the connection indicator explains that editing can continue. Transport uncertainty, expiry, authentication errors and incomplete/untrusted error envelopes still disconnect.

Regression evidence: the new client test failed before the fix, then passed. It covers queued Backspace, selection and Clear after rejection, revision synchronization, distinct event IDs, and no duplicate commit. A Go HTTP test reaches the real engine's 128-character limit, verifies the unchanged rejection envelope, and successfully shortens then clears the composition. Local prototype validation passed 24 Python and 42 JavaScript tests; the lab Go package passed.
