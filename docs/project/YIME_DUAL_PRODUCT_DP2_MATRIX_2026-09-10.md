# DP2：双产品安装及维护验收矩阵

影响产品：YimeCore、Rime/PIME。2026-09-10 继续双产品制包计划，先将 DP2 的必需覆盖固定为可自动检查的规格，再进入三选一入口。此步骤不改变安装准入，不执行安装器。

## 46 个必需场景（v2）

机器可读来源为 [acceptance-matrix.json](../../tools/dual-product/acceptance-matrix.json)。v2 按初始安装顺序分别追踪两个产品的维护，共 46 个场景；原 28 行规格遗漏的先装产品维护和保留数据重装已补齐：

| 目标产品 | 另一产品状态 | 安装顺序 |
| --- | --- | --- |
| YimeCore | 不存在并保持不存在 | 仅 YimeCore |
| Rime/PIME | 不存在并保持不存在 | 仅 Rime/PIME |
| YimeCore | 已安装并保持不变 | Rime/PIME → YimeCore |
| Rime/PIME | 已安装并保持不变 | Rime/PIME → YimeCore |
| Rime/PIME | 已安装并保持不变 | YimeCore → Rime/PIME |
| YimeCore | 已安装并保持不变 | YimeCore → Rime/PIME |

单产品环境各 8 项；共存环境中后装产品各 8 项、先装产品各 7 项，共 46 项。操作为首装、升级、失败升级回退、备份和实际恢复、重启登录、自身 x64/x86 注册及真实宿主、卸载、保留数据后重装。先装产品的首装发生在 peer 不存在时，由单产品安装行覆盖，不能编造“后装产品已经在场”的首次安装。其余共存维护必须按初始安装顺序分别验证。重装必须绑定此前卸载证据和保留数据，并实际验证设置与学习重新可用。当前规格对应 x64 Windows 与 x86 WOW64 宿主；不代表 ARM64 原生验收。每个场景均绑定实际机器、发起 SID、架构、目标包和源码身份、另一产品包或明确不存在、前后状态及原生证据摘要。

对另一产品保护注册、载荷、进程身份、设置学习、Run 和卸载记录；默认输入法也不得改变。卸载只移除目标产品的已批准文件和注册，保留用户数据和独立恢复介质。失败回退要求恢复原注册及值类型、原包和配置、原运行状态和原数据。重启场景明确要求 Shell 登录事件和当前 PID/映像/开机/所有者相互匹配。

安装顺序不能互相代替，单产品证据不能代表共存；合成测试、静态清单和仅有进程启动不能代表原生事务或真实宿主通过。现有 YimeCore 本机结果作为既有证据保留，本工具未导入或重判它们。

## 工具及验证

运行 `python tools/dual-product/acceptance_matrix.py` 输出完整待办。该工具只读取规格并输出 JSON，不读取安装、注册、进程或用户数据；不是批准生成器，也不是原生结果验证器。

共 13 个回归方法，包括逐项删除证据要求、删除保护维度、缺失反向安装顺序、重复环境、伪布尔值、漏掉机器/包绑定、计划冒充执行授权或验收通过的负例。本机全部通过，并接入 CI 独立步骤；新增覆盖两种顺序中先装产品不可遗漏、重装前后状态、顺序合法性、唯一场景 ID 和旧 schema 拒绝。v2 场景 ID 包含初始安装顺序，旧 v1 记录不自动迁移为已通过证据。`plan_valid=true` 只表示矩阵规格完整，执行授权、安装验收和三选一入口准入始终为 false。
