## 已确定并修复的问题

当前 Control Panel 引用名称为 `0804:{35F67E9D-A54D-4177-9697-8B0AB71A9E04}{3F6B5A12-8D44-4E71-9A2E-6B4F9C1D2A30}`，REG_DWORD。它与 YimeCore 引用分别存在。旧精确匹配表只包含带 `0x0804:` 的形式，输入本次真实名称会重现 `Ambiguous mixed Control Panel profile reference`。

已在源码允许这一完整 CLSID/Profile 配对；不允许任意 GUID、不 trim、不拆分混合引用。回归覆盖真实 DWORD 名称路径、大小写、旧形式、独立 peer 名称、混合字符串、空白、错误语言和错误 Profile。PS5/PS7 通过，现有 registration ownership 22 项全部通过，新回归已加入 maintenance CI。

该证据是当前名称观察，不能冒充失败瞬间的原名称日志；但旧代码对该名称的误判已可复现并修复。它解释回滚阻断，不解释 Register 中 YimeCore TIP 消失。

## 当前状态与恢复顺序

YimeCore 机器 COM/InprocServer32/TIP/Profile 键仍存在，但本次只枚举键和名称，不等于所有内容、DLL 路径都已验真。用户 TIP 根、具体 Profile 与 Enable 仍缺失；不能把返回 2 当作 Enable=0，也不能以机器键存在声明输入功能正常。

测试端本轮补证任务已完成，无需继续重复采集或整理旧日志。当前暂停安装和自主恢复，由开发端继续准备限定恢复实现：

1. 以唯一事务 `9fe7f28d-0889-4828-85b5-1f481431b43a` 的原授权、prepared、票据、包和安装前 peer 快照为边界，验证摘要、SID、机器身份和当前状态。恢复工具必须单独发布和验证，不能直接替换旧包内的脚本绕过封存摘要。
2. 修复后的引用判断用于清除本事务 Rime/PIME 残留的限定回滚路径；保留对未知注册、混合引用及其他产品的拒绝。不得调用固定旧事务的 finalizer，不能手写终态。若发现额外变更，停止并保存，而不是扩大清理。
3. YimeCore 用户 TIP 按验证过的安装前快照精确恢复，包括原值种类；只允许已证明缺失的本产品子树。任何既存但冲突状态都不得覆盖。将这一步放在可能触发 Windows TIP 更新的候选注销之后，并重新检查机器注册、用户 TIP、默认输入和 peer 状态。不能用全量语言列表重写作为修复。
4. 安装/回滚动作需要逐步骤观察并同时保留原始异常与 finally 保护异常。隔离回归验证失败边界和恢复路径，再交付可执行恢复命令；恢复后才安排用户物理输入确认和必要的登录验收。
