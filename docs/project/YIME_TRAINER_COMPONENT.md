# Yime 音元指法练习组件

## 定位

练习器是 Yime 主仓库内的独立 Win32 工具，生成
`go-backend/yime-trainer.exe`。它由“工具箱 → 指法练习”启动，但不进入
PIME、TSF、Rime 会话或候选窗口进程。

原独立 Python 原型提供的三类题型和 JSON 课程边界已经迁入。发布版本不依赖
Python，也不再维护第二套拼音到编码映射。

## 数据来源

- 课程：`go-backend/input_methods/yime/data/trainer/*.json`
- 教学分组：`trainer/yinyuan_groups.json`（只保存稳定音元 ID）
- 音元键位：当前有效的 `yime_yinyuan_layout.json`
- 三模式音节编码：当前有效的 `yime_pinyin_codes.tsv`
- 字词与短句：只读安装目录中的 `yime_full.dict.yaml`

如果用户已经应用完整的个人布局覆盖，练习器从用户目录读取布局和编码；课程
本身仍从只读安装目录加载。题目只保存稳定的音元 ID 或规范数字标调拼音，不
保存派生的变长、等长、省键目标码。

## 当前题型

### `keymap`

必填 `yinyuan_id`。运行时从当前布局解析物理键。

界面显示为“音元练习”，覆盖当前目录中的 60 个音元，并沿用原型的发音部位与音质分组：
噪音分为唇音、齿背音、龈音、龈腭间音、硬腭音、软腭音和语流派生首音七组；乐音分为
`[i]`、`[u]`、`[ü]`、`[a]`、`[o]`、`[e/ê]`、`[舌尖i]`、`[er]`、
`[m]`、`[n]`、`[ng]` 十一组。界面使用“音元类别 + 分组”两级联动选择，
一次只循环练习一组。

分组文件不复制物理键。练习器每次启动都按当前有效的导入布局，把 57 个稳定
音元 ID 解析为 57 个目标键，因此用户换布局后无需再维护第二份练习键表。

### `syllable_composition`

界面显示为“分段练习”，并提供“音节分段：首音／干音”。选择“首音”时复用
音元练习的七组噪音音元，但在结构意义上统一显示为“首音”；一次练习一组。

选择“干音”时，从当前 `yime_syllable_decomposition.tsv` 读取呼音、主音、末音
三个稳定音元 ID，并按韵音的“主音音质 + 末音音质”归类。原型关系共有 19 类，
练习排除 `[m+m]` 后保留 18 类；每类再按高高高、低中高、低低低、高中低四种
干音调型分组。比如 `[a+n]` 类包含 `an / ian / uan / üan`，四种调型各四个，
合计 16 个。`ong` 与 `ueng` 映射到相同三音元序列，不重复占题，但不得省略
任何一种形式：题面明确标为 `ongN（与首音相拼时） / uengN（独立成音节时，
对应 wengN）`。这项条件关系由练习生成器显式补齐，不依赖当前词典是否恰好收录
某个 `weng` 声调实例。

干音题及其三键答案全部从当前规范分解表和当前导入布局动态生成。对于规范表中
不存在的声调形式（如某些独立鼻音的一声），练习器不自行虚构音节或编码。

### `syllable_practice`

界面显示为“编码练习”。基础课程不再另设只有 `yi1 / yi2 / yi3 / yi4` 四题的
“标准拼音与音元联想”，而是把这四题自然地纳入完整练习。选中后显示“首音”
下拉列表，以稳定首音 ID 将正式
音节编码表分为 25 个有规范音节实例的首音组；`N23` 的 `[j]` 与 `N25` 的 `[ɥ]` 分列，
仅供语流条件实现的 `N26/N27` 保留在音元键位练习中，不虚构规范音节实例。
用户选择一个首音后，逐项练习该首音与干音构成的全部正式编码音节。

每道题沿用原型最后一版较易理解的两段式流程：先把标准拼音切成首音段和干音段，
再分别显示“首音标签 → 一个首音音元”和“干音标签 → 呼音、主音、末音三个
乐音音元”，最后显示合成后的完整音元拼音。输入者据此敲入所选变长、等长或
省键方案的完整编码；流程不把整个音节直接解释成四个无中间依据的音元。

题目不在课程 JSON 中复制音节或编码。练习器以当前
`yime_pinyin_codes.tsv` 中与原型物化清单一致的 **1733 个音节**为范围，再用
`yime_syllable_decomposition.tsv` 取得每个音节的标准拼音、首音、干音和稳定
音元 ID；答案按当前导入布局和所选变长、等长、省键方案生成，并逐项与正式
编码表互证。只存在于分解来源表而尚未进入正式运行码表的 `guai2`、`ra4`、
`tin4` 不进入本练习。

旧课程格式仍可使用 `syllable_association` 或 `syllable_contrast` 保存少量指定
音节题；基础课程只显示动态的“编码练习”，避免三个名称相近的题型重复。

### `word_practice`

界面显示为“字词练习”。每次启动练习器时，程序只读扫描随安装包发布的完整
系统运行库，从高频部分按音节数分别随机抽取五题。界面分组顺序固定为：
双音词语、三音词语、四音词语、单音节字。训练项必须是纯汉字，字数须与
运行库编码中的音节数一致，并且每个正式等长音节码都能映射到当前三模式码表。

抽样结果只保存在本次进程内；切换变长、等长、省键方案时只重新投影答案，
不重新抽题。再次启动练习器才会取得新一组题目。

### `sentence_practice`

界面显示为“短句练习”。程序先从系统运行库高频部分取得一至四音节的组句部件，
再对五至十二音节的短句候选执行与动态组句相同的逐音节覆盖检查：候选的全文和
正式编码都必须能由至少两个高频部件连续、无遗漏地组成。每次启动从通过检查的
候选中随机抽取五句，并在题目详情中显示实际分段路径。

这里验证的是系统运行库数据上的动态组句可达性，不开启真实 Rime 会话，也不读取
用户词典或学习频次。这样既避免人工挑例句，也不会为了练习而产生新的学习记录。

### `common_words`（兼容旧课程）

必填 `text` 和逐字对应的 `syllables`。课程加载时校验字数和音节数，运行时
生成连续输入编码。

## 输入与安全边界

练习输入框只对自身解除输入法上下文，以便接收原始键串；它不切换系统输入法，
不写入 PIME 安装目录、Rime 用户目录或学习数据。运行库随机抽题只打开安装目录
中的系统词典进行顺序读取；当前随机题组只保存在本次进程内。聚合成绩保存在独立
的 `YimeTrainer` 目录，不记录使用者实际提交的按键文本。

键位练习初期默认显示当前音元的目标键。用户在输入框敲入物理键后按 Enter
确认，程序立即判定并自动进入本组的下一个音；末项确认后回到本组首项。“跳过”
按钮只用于跳过当前音，不代替 Enter 确认。

## 显示设置

练习器提供“常规、中等、大号、特大”四档字号，以及“柔和灰、暖米色、灰蓝”
三种低亮度背景。新用户默认使用“中等 + 柔和灰”；选择结果保存在
`%APPDATA%\PIME\YimeTrainer\yime_trainer_preferences.json`，不写入 PIME
安装目录、Rime 用户目录、Rime 配置或学习数据。

固定标签和题目文字不作自动折行；课程详情中由数据明确给出的换行仍按原分行显示。
各行宽度按当前字体和最长课程文字测量，按钮与标签保留文字内边距，客户区宽度和
高度再由横排控件总宽与纵排控件总高推导。切换字号后，控件和主窗体同步重新计算，
避免较大字号下出现文字截断或标签只显示半行。

候选实战已经以隔离模拟器加入。它不创建 Rime 会话，固定保持裸数字为组成键，
候选序号只接受 `Shift+1` 至 `Shift+9`，并覆盖分页、选择句中分段、改选后恢复
整句提交。x64 Notepad、Codex IDE 和 x86 SysWOW64 charmap 三种宿主配置使用同一
状态机回归；安装后的真实宿主测试仍作为发布前人工验收。

## 教学闭环

- 判错按答案单元进行编辑距离对齐，定位第几个音节及首音、呼音、主音、末音；
- “显示答案”在答错后依次给出错误音节、错误音元、完整答案三级提示；
- 独立学习记录保存新题、学习中、待复习、已掌握状态以及反应时间；
- “全部题目／只练错题／今日复习”使用错题、到期时间、覆盖率和近期重复约束排序；
- 阶段路线及 90% 默认门槛来自 `trainer/curriculum.json`，熟练使用者仍可直接跳转；
- 学习报告按题型、音元／首音／干音／音节标签、输入方案和错误位置聚合，并可导出；
- 清空记录只删除 `YimeTrainer/yime_trainer_progress.json` 和本地导出的
  `yime_trainer_report.txt`，不枚举或删除同目录的其它文件。

当前布局的 57 个物理键全部动态映射到左右手、具体手指和基准键。代表音频保持
可选：程序报告已声明和实际可用的覆盖率，但在获得自制或明确授权资源前不伪造
语音、不打包来源不明的材料。

“音元练习 → 指法专项”另提供相邻键、同指换键和左右手交替三组动态练习；题目
仍从当前导入布局生成，换布局后无需维护第二份按键表。
