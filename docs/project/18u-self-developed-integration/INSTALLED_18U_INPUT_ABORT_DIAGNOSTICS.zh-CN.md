# 已安装 18u 首次 input 中止诊断候选

基线：`bb7cc136c284a5d5ee3a764749119b0b423da482`，安装测试版 test.2。

## 已知事实与目标

MyComputer 已报告安装成功并重启。本轮自有宿主输出 `connected: true`，随后 `engine input` 返回 `0x80004004`（E_ABORT），未形成最终读回证据。连接成功发生在严格 Windows profile/provider/DLL 检查之后；它不证明后续动作仍保有原焦点，也不证明首次输入请求已被 Broker 接受。不得由此声称根因已确定、输入通过或需要再次卸装。

本候选只增加失败诊断：DLL Action/Poll 的拒绝分类与既有状态、传输/Broker 的固定原因分类、宿主抛出原失败前的脱敏响应摘要。保持既有返回码、身份/焦点门、消息泵、超时、单次请求及不重放约束。注册、安装、卸载、用户数据及恢复策略不变。

## 数据边界

诊断只写独立结构化 stderr；原成功 stdout 协议不变。仅记录程序定义的固定分类、HRESULT、数字世代及必要布尔状态。不得写正文、候选、键码、词典、完整请求/响应、任意异常文本或用户文件路径。未知字符串映射为 unknown，不把未知字符串原样复制。输出错误不得替换原失败或使诊断路径抛出异常。

## 证据解释

- 入口拒绝：可区分路由/线程管理器/键盘焦点状态，不据此推断物理操作原因。
- 目标/世代拒绝：记录失败的既有检查，不通过增加激活、等待或重试来使它通过。
- 传输失败：保留固定阶段分类；不声称已恢复底层系统错误的全部细节。
- Broker 拒绝：固定白名单原因，不以空 stderr 反推请求成功。
- 宿主失败摘要：保留原 HRESULT，响应中的安全字段分别标注存在/类型/枚举；没有响应不等于没有发生编辑。`localEditOutcome` 是本次路由记录，不替代独立宿主读回。

## 验证及交付限制

本轮只开发侧离线验证，不运行 Windows 激活、注册或安装，不发布、制包或替换 MyComputer 文件。纯 helper 测试与静态接线检查不能代替 MSVC 编译或实际 TSF 行为验证。若后续批准发布/构建，须明确新源码和包身份；任何新的本机运行另行安排，不自动重跑旧测试。

现有 formalhost Windows 测试的旧 `formalFailureSummary` 只理解旧失败 schema，遇到新增诊断行可能将简短摘要降为 `diagnostic unavailable`；原始 stderr 仍需保留。此次不放宽该解析器，也不修改成功 stdout 合同。同步、有限的失败日志仍有输出开销，不能承诺观测完全不影响时间；没有增加等待、激活或重试策略。日志丢失或输出失败时不能由“无日志”推导“无拒绝”。

不同进程的 stderr 不建立全局事件顺序；只可按各自记录和状态关联，不能由文件合并顺序推定系统因果。开发侧通过的是两个生产诊断 helper 的严格 C++17/NDEBUG 及 UBSan 测试程序，和五项 Python 静态接线检查；五项 Go helper 测试已写但本环境无可用 Go 编译器，未执行。完整 Windows DLL/宿主 JSON 适配及真实失败复现尚未编译/执行，不将 helper 通过等同于产品验证通过。

原生诊断 `resultKnown=false`/`result=0` 表示该检查未采集 HRESULT，不代表 S_OK。当前显式结果均为失败码；若将来需要记录真正 S_OK，须改为显式 known 参数。phase 数字沿原枚举：0 None、1 Open、2 Action、3 Edit、4 Complete；世代仅本进程计数，不含会话 token。
