# 18u ARM64 测试版可信维护入口设计（未启用）

状态：设计审查与离线模拟。`Setup.ps1` 的 ARM64 安装与卸载门均继续拒绝；本文不授权安装、提权、注册或卸载。

## 信任边界

- 系统级 PowerShell 7 是测试机前提，固定候选位置为 `%ProgramFiles%\PowerShell\7\pwsh.exe`。PATH、用户目录和下载目录不能作为提升后的 shell 来源。验证官方 ARM64 MSI 的来源、签名与批准版本；每次维护再检查受保护目录、PE、签名、版本及实际 `IsWow64Process2` 结果。官方 shell 本身不认证 Yime 的脚本。
- 测试阶段选定的 Yime 信任根是：由管理员预置于受保护位置、哈希经独立渠道核准的原生 ARM64 启动器。核准记录必须单独位于管理员可写位置，不能由候选包、其自带清单或普通用户写入。启动器、核准记录和所有父目录的 ACL 与重解析状态都需要核验。当前没有已核准的启动器哈希、预置记录或安装操作授权，故不能启用提升。
- 非管理员包目录只作为不可信输入。已提升的原生入口先验证包来源、完整清单与脚本／模块字节，再复制到仅管理员可写、无重解析路径的暂存位置；从该位置重新核验并执行。校验和执行间不得重新读取用户可写源。临时位置、安装目录、入口及其父目录均须验证所有权和写权限；失败则停在任何产品变更前。
- 管理员进程在变更前再次验证原生 ARM64、管理员令牌、与发起者相同的 SID、包身份和受保护暂存。注册工具仍须通过包内 PE／哈希检查及自身原生进程门。检查值只用于拒绝，不接受包内自称的发布者身份。
- 设置页 `UninstallString` 必须指向受保护安装目录中的产品原生维护入口，而不是 `pwsh.exe -File`、`Setup.cmd` 或用户可写脚本。该入口每次重新验证系统 shell 和受保护的已安装脚本／模块；缺失、替换、损坏或占用时停止并保留安装与用户数据。不能回退到仿真 PS5。

## 测试版前提与未定项

系统 PowerShell 7 可单独安装用于 ASUS 测试，但这不是自包含交付。Yime 信任根已选为预置受保护入口加独立核准哈希；仍需决定批准的 PS7 版本／签名策略、预置和暂存的具体位置与 ACL、独立核准渠道、更新时如何轮换入口和哈希。预置并验证前 ARM64 维护门关闭，不能通过已有自带清单哈希放行。

## 手动管理员 PS7 最小候选（尚未启用）

实际打包脚本为 `tools/yimecore/assemble_installed_18u.py` 和 `tools/yimecore/package_installed_18u.py`；后者生成完整 ZIP。`tools/yimecore/make_arm64_manual_approval.py` 只在输入由独立交付渠道取得的 ZIP SHA-256 后，核对完整 ZIP、路径、重复名及固定 18u ARM64 身份，输出**待核准草稿**，列出每个文件的字节数与 SHA-256。草稿不能自行成为信任根。管理员须从独立渠道复核源提交、ZIP 哈希、目标用户 SID、完整文件清单和 Yime 入口代码哈希，签认版本并单独保存核准记录；包提供者或普通用户不能修改该记录。固定提交是 `2bc222d92321daa29cea9951761cc1063db5f045`。

测试机管理员预置时，先从官方来源核验并系统安装原生 ARM64 PowerShell 7；记录核准版本和发布者证书身份。然后由管理员把经独立核准的完整包解压到固定的、仅 SYSTEM／管理员／TrustedInstaller 可改的目录，把入口及其依赖模块放到单独的受保护目录，把核准记录放到另一受保护目录。不得从用户下载目录、PATH 或临时目录提升执行。以上路径及其每一级父目录都须是本地普通目录、非重解析点，所有者与可写 ACE 仅限上述管理主体；路径不存在、额外文件、哈希不符、身份不同或文件被占用都应停止。更新必须生成新的独立记录并原子切换受保护版本，旧版记录和包保留用于审计；不得原地覆盖后继续使用旧核准。

管理员手动启动固定 `Program Files\PowerShell\7\pwsh.exe`，使用 `-NoProfile -NonInteractive` 和经核准的固定入口。进入维护代码前应清除或拒绝会改变模块、程序集、脚本及 DLL 搜索的用户环境（包括 `PSModulePath`、`PATH`、`PSHOME`、`DOTNET_STARTUP_HOOKS`、`DOTNET_ADDITIONAL_DEPS`、`DOTNET_SHARED_STORE` 和当前目录），以绝对路径加载已核准模块，禁止相对导入及自动模块解析。正式入口还需核验自身和模块在受保护位置的核准哈希、系统 shell 的有效官方签名／核准版本／ARM64 PE、当前进程 `IsWow64Process2` 为原生 ARM64、管理员令牌及预先核准的同一用户 SID；使用其他管理员账户明确失败。

现有 `Product.psm1` 中的 `Assert-Arm64FixedPackage` 是**候选只读核验函数**：拒绝错误包／核准路径、非管理员、SID 不同、受保护路径检查失败、清单身份错误、逐文件大小或哈希不符以及多余文件。独立核准记录必须在调用前已由可信入口确认，回调式路径检查仅供故障注入；它本身不能认证调用它的模块。`Setup.ps1` 的 ARM64 `Install`／`Uninstall` 拒绝门保持关闭，故当前没有可执行的安装或维护流程。候选函数也没有消除读取后替换的窗口；真正开放前须用受保护目录的固定句柄／文件身份和最终执行文件重新核验，且先完成可信入口、环境隔离、系统 PS7 发布者验证和设置页卸载入口。不能将模拟测试解释为这些安全性质已通过实机验证。

## 验证顺序

1. 离线状态机测试逐项注入：缺少 shell、错误版本／签名／架构、Yime 入口来源未知、脚本或模块损坏、重解析／可写路径、SID 不同、非管理员、占用文件；均必须拒绝且不产生产品变更。x64 路由保持原样。
2. 原生入口编译、PE／签名／受保护路径核验及无 UAC 的故障注入；观察被提升内容只从受保护暂存读取。此阶段不得以模拟结果替代真实 UAC。
3. 经单独授权后才做真实 UAC、安装、注册、设置页卸载和恢复。分别记录两个进程及注册工具架构、同一 SID、用户数据不变、另一产品不变。x64 实机回归独立完成。

真实符号链接测试、x64 实机回归、ARM64 实机 TSF 输入均保持未验证。
