# 自研内核双键位方案：18u触摸接入实施计划

日期：2026-11-01。基线：main `f605d1acf9f9a20986c3ec3d6490da3e2d5c15ac`。本地工作分支 `codex/18u-yimecore-session-bridge-20261101`。用户已授权分阶段实现和本地验证；新代码发布/CI另行确认。不是安装指令。

## 1. 产品矩阵与非目标

| 产品/方案 | 持续定位 | 本阶段边界 |
| --- | --- | --- |
| Rime/PIME | 保留独立产品与必要维护 | 不修改、不作为自研依赖或自动回退 |
| 自研标准键位 | 标准实体键盘输入及其对应触摸前端 | 保留行为、数据和注册身份；不声称对应触摸前端已完整交付 |
| 自研专用键位 | 以18u屏幕盘面替代当前无法制造的专用实体键盘 | 主动开发方向；不是标准方案的覆盖升级 |

共享规范语义来源、引擎算法及适用会话契约；布局投影、派生词典/索引、会话身份、包和验收分别绑定。保持18u基线，17u/23u冻结。标准数据和注册身份不改。不能把实验编码送入标准索引，不能用可见盘面相同推断编码一致。

不在本阶段处理混合笔指疑难、a837诊断退出异常、四机全量测试、性能封版、正式签名、用户数据迁移或安装器重写。旧包与原记录保留，不继承它们的实机验收。

## 2. 已有源码接口与断点

```text
当前专用18u：触摸UI -> previewSessions/keyboardlab.Event
 -> keyboardlab.Runtime（校验实验manifest/投影/三模式词典）
 -> yimecore.FileEngine -> keyboardlab.Response.Commit
 -> preview.emit -> 明确绑定目标的SendInput，或窗口内previewEditor

当前正式自研：标准键盘TSF -> SurfaceSession/Broker
 -> engineapi + 标准索引 -> CompositionEditSession -> 宿主文本
```

实际入口：`go-backend/cmd/yime-touch-keyboard/preview.go`、`host_windows.go`、`platform_windows.go`；`go-backend/internal/keyboardlab/runtime.go`/`session.go`；`go-backend/input_methods/yime/yimebroker/protocol.go`；`YimeTextServiceExperiment/CompositionEditSession.cpp`。

现有`keyboardlab.Runtime`已经用自研引擎，不需重写解码器。它校验实验布局/词典并建立临时索引；正式Broker请求则是独立的version/sequence/session_id契约。现有UI的Unicode发送不是TSF接入。正式TSF的RequestEditSession返回排队成功也不等于DoEditSession实际写入完成。

## 3. 最小目标及阶段门

**第一个可执行产品目标：单x64、单自有Windows宿主中的18u输入→候选→实际文本提交闭环。** 先从不安装的隔离验证开始，不把自有宿主通过扩为Word/Edge或系统安装通过。

| 阶段 | 交付 | 依赖/验证/退出条件 |
| --- | --- | --- |
| S1 会话与提交边界（当前） | 本计划；加法式、未接入现有产品路径的会话适配器；匹配专用布局的自研引擎测试 | Linux自动验证输入/候选/普通翻页/退格取消及身份、焦点、过期候选、提交实际确认、未知结果不重放；仅合同/隔离引擎证明，不宣称Windows TSF通过 |
| S2 x64自有TSF宿主 | 复用已有自有窗口/直接DLL TSF测试设施，接上S1合同并实际读取宿主文本 | 需要Windows原生工具链与可用测试环境；只访问测试自建进程/窗口，不安装注册；排队/实际完成、失焦、拒绝写入、断连、重复请求均有反例。必须实际DoEditSession及宿主读回，SendInput或模拟sink不算通过 |
| S3 18u前端最小接线 | 复用已验UI，连接专用会话和TSF宿主路径，形成可识别的独立候选包 | 启动/输入选字/普通翻页/退格/取消/恢复/正常退出；单架构、单宿主先验；此前需确定正式激活方式和产品/profile并存策略，不复用或覆盖标准注册身份 |
| S4 平台与安装交付 | 再接ARM64/ARM64X、完整包和首台可回退安装验收 | 保留x64/x86标准回归，单独核对ARM原生证据；现有installer/simple可复用但须审查新身份/载荷；签名及最终包验证另列，不把哈希当签名 |

每阶段实现后本地测试、独立审阅、固定diff与提交。需要远端构建时先提供准确分支和内容申请发布。用户机器安装/注册、默认输入法及真实宿主操作不包含在本地授权中。原生Windows环境缺失时交付明确未执行项，不能借模拟结果跨过S2阶段门。

## 4. 会话/数据与安全合同

- 数据绑定：布局标识、投影与资源身份、模式同一会话内固定；可信创建方必须实际验证资源，客户端声明相等不是数据真实性证明。复用keyboardlab既有manifest检查，不增加读取其它产品/目录的fallback。
- 所有权：一个前端会话只操作一个明确拥有的宿主上下文；不让前端自报身份冒充其他进程。阶段S1的传输中立对象不是IPC认证方案；S2必须把宿主身份绑定真实测试对象，S3再设计跨进程信任。
- 焦点世代：失焦、销毁、重新绑定使旧token失效；恢复须显式创建/绑定新上下文，不把旧候选送到新宿主。UI最小化不保留未提交组合的承诺。
- 候选：选择必须匹配同一会话和快照revision/稳定候选ID，翻页或编辑后的旧候选不能提交。
- 提交：区分产生文本、请求排队、实际应用、拒绝/未知。只有宿主实际完成确认才能报告提交成功；不把等待/请求返回/发送计数当正文成功。
- 不重放：未知结果、断连、部分失败后不自动重试不可逆提交；旧commit token不可再次消费。已发出待确认写入不能靠本地取消宣称宿主未写入，记录为未知并停止。
- 关闭：会话、临时索引与自有宿主生命周期明确；错误停止后续动作，不清理用户应用/其他产品或旧证据。

## 5. 回归与结果分层

S1至少运行新合同测试及`keyboardlab`、`touchkeyboard`、现有touch-keyboard命令测试；检查标准codemode与yimecore受影响的测试，diff确认标准数据、Rime、注册身份和原运行入口未改。全量或原生未跑必须列明，不以选中测试代替完整产品回归。

结果分别报告：源码静态审阅、Linux合同/引擎自动测试、Windows交叉编译、原生自有TSF宿主、真实用户宿主、安装态验收。当前前两项可做，后几项不得推断。任何布局身份错配、跨上下文写入、重复提交、未知结果重放、标准版回归都是阶段停止项；不放宽测试来通过。

## 6. 近期执行与下一决定

先完成S1并保留实际验证记录。之后审阅S2最小接线：复用现有TSF写入层与测试自有text store，而非引入另一套正式引擎。正式产品/profile身份及标准/专用方案在用户界面的切换方式在S3前明确；当前无需提前改注册表或选择用户测试机。
