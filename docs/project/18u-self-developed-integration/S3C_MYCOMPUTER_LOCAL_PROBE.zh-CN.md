# S3c：MyComputer 本地专用注册／激活小工具——阶段 1 设计与阶段 2 交付验证

**当前状态：本提交提供阶段 2 的独立 x64 编译／无注册测试／打包 CI 与源码。Windows 构建、只读测试及包的实际结果以本提交 exact SHA 对应 CI 和 artifact 为准，不能从文档预先推定通过。未在 MyComputer 执行本轮注册。** 本文件不是可直接执行的安装说明，不提供未核实的命令。

## 1. 三阶段授权分别成立

| 阶段 | 内容 | 当前授权与完成边界 |
|---|---|---|
| 1 | 默认只读的小工具；独立显式注册入口、限定账本恢复及只读核验；本地测试与差异审阅 | 已获准开发与测试；不操作用户电脑、不发布、不安装、不触发 CI |
| 2 | 固定 x64 小包：独立 DLL、工具、manifest、逐文件 SHA-256、签名状态、README 与恢复说明 | 已获准本阶段源码发布、独立构建／无注册测试／打包 CI；实际结果以 exact SHA CI 为准，未执行结果不能写为通过 |
| 3 | MyComputer 先运行固定包只读检查；条件满足后再单独确认一次管理员注册、激活、撤销与核验 | 未授权执行；只读与写入分开确认，不能从阶段 1 或旧云端授权推导本机注册许可 |

此前云端注册、语言盘点和环境准备的授权均不是 MyComputer 操作许可。实际 Windows 主机名、OS、CPU／进程架构等尚须在获准的本机只读阶段独立核对；“MyComputer”只是用户确认的设备称呼，不通过别名或手工填写伪造匹配。

## 2. 本轮仅解决什么

小工具验证独立 18u 身份的 **profile 注册／自有进程内激活／撤销**。TSF 焦点与激活过程可能初始化其他已安装 TIP，自有进程不是隔离沙盒；不应把“没有主动修改其他输入法”解释为“不会加载其他输入法”。成功证据应包括真实 DLL 激活成功、实际活动 profile 身份、完整操作账本及清理后只读核验；单有 API 返回成功或活动 profile 查询不能替代完整证据。

这不是专用 Broker 连接、真实引擎输入、正文提交与读回，也不是 Word／Edge 兼容性、用户文档或物理指笔验收。原来未注册的 7 个集成场景失败记录必须保留；不得用本工具成功覆盖它们，也不得将待接的完整输入主流程标为完成。

默认只读入口与显式写入口必须物理分离到不同参数模式。参数缺失、未知模式或不满足条件只能只读或拒绝，不能降级进入旧云端自动注册路径。工具不得自动提升权限、循环重试、加载组件或启动全套安装器。

## 3. 安全事务与停止边界

- 仅允许编译固定的独立 18u CLSID、profile、语言和类别组合；不接受任意 GUID 或其他产品身份作为输入。
- 只读预检不得写注册项、启用 profile、激活 TIP、修改默认输入法或语言设置。存在的中文条件由当前真实进程观察，不主动切换线程或系统语言来达标。
- 任何预存目标 GUID／profile／本身份的类别关联记录，包括不完整、跨视图、API 与注册表矛盾或查询不确定，均阻断写入；不覆盖、不“修复”、不删除旧记录。
- 写入口需要明确模式及本轮新的账本；在每次可能写入前持久化身份、初始不存在证据、owner PID／创建时间及操作归属。旧账本不得复用为新注册机会。
- 正常结束仅撤销本轮确实创建且归属可验证的项；独立恢复必须先确认原 owner 已结束。账本缺失、损坏、身份不符、owner 生死不明或归属不确定时，停止并报告，不能按 GUID 猜测删除。
- 本地模式不使用宽泛的服务 `Unregister` 作为兜底；若精确清理后仍有不能安全归属的服务空壳，保守保留并报告残留／`cleanup-failed`，不能扩大删除范围换取通过。
- 恢复不是通用卸载。不得卸载／禁用其他 TIP，不改默认输入法、用户语言、显示语言、系统区域、网络或安全策略，不下载／安装组件，不注销／重启。
- 部分失败、超时、进程中断或清理不确定不能当作未写入或通过；保留证据，不自动再次注册。残留项只能依照本轮可验证账本处理，不借助通用注册／卸载命令绕过边界。

## 4. 阶段 1 验证要求

本地应分别核验：默认路径不写入；未知参数不进入事务；已有身份阻断；一次事务与归属账本；owner 活着／状态未知时拒绝恢复；损坏账本拒绝；清理与只读核验结果不能相互冒充。

Linux 静态／模拟测试只支持设计与防误用结论，不证明 Windows API、管理员权限、真实 profile 激活或本机清理已通过。未运行的 MSVC／Windows 原生测试须列为未验证；阶段 1 不执行系统注册或 CI；现阶段 2 仅新增获准的构建／无注册负例／打包 CI，不因此开放系统注册。

实现复用并隔离既有 probe 的受限事务，而不是复制成全安装器或展开虚拟机工程。当前已冻结以下**开发审阅接口**，不是本机执行指令；实际源码仍须完成审阅，当前没有交付 EXE。

| 模式 | 参数规则与边界 |
|---|---|
| 无参数／`--preflight` | 默认只读，不创建账本；可选 DLL 绝对路径及其小写 64 位 SHA-256 配对参数，用于核对固定文件；未具备完整证据不能称注册条件已满足 |
| `--register-once` | 必须提供 DLL 绝对路径、`--sha256` 与新的 `--ledger`（固定文件名 `registration-ledger.dpapi`，加密二进制，不是旧云端的 JSON 账本）；只允许显式一次事务。此接口存在不等于本机写权限已获准 |
| `--recover` | 只接本轮原账本；不注册、不覆盖、不按缺损账本猜测归属 |
| `--verify` | 只读核验本身份不存在；不执行恢复或注册 |

未知、重复或缺少必需参数均拒绝（exit 3），不退回旧注册命令。统一 scope 为 `mycomputer-registration-activation-only`。

只读结果区分 `checked` 与 `blocked`；`checked`／exit 0 仅表示采集完成，**不等于 `prerequisitesSatisfied=true`**。结果包含 `prerequisitesSatisfied`、可为未知的前置条件、实际主机名、真实语言与 DLL 哈希。调用方给出的 SHA 只证明“与提供的期望值一致”，**不建立发行者信任**；当前 `publisherTrust=not-established`，不能冒充已签名可信包。

注册模式即使 profile API 与本轮清理完成，当前仍返回 **`activation-unconfirmed`／exit 4**，`actualDllActivationVerified=false`，不是整体验证通过。开发侧已提供纯离线 `validate_local_activation_evidence.py` 及测试：仅核对 native 19 字段、exit 4、唯一 DLL 成功标记、独立只读核验等证据的一致性，不启动任何 EXE，也不包装自动注册。其 `sourceAuthenticityVerified=false`、`sameInvocationProven=false`；一致性通过不能证明日志来自真实来源或同一次运行。阶段 2 仍需固定包与可信执行／日志采集，不能仅靠 API 返回、stdout 状态或自行拼接的文件认定实际 DLL 激活。恢复／只读不存在核验的 `pass`（exit 0）仅表示该操作范围通过，不能补造此前激活成功；恢复归属未知时 `writesStarted=null`，不宣称未写入。

以上接口仅用于本地代码审阅；本文件故意不提供组合后的可复制注册命令。

## 5. 后续交付必须保留的信息

阶段 2 已获准，但必须先完成 Windows 编译验证、清理负例及超时进程回收边界审查，而不是产出源码后立即让本机运行。包必须固定源码提交、目标 x64 架构和独立产品身份，逐文件列出 DLL／工具／README 的哈希及实际签名状态。未签名必须明示，不等同于签名有效；不得通过关闭安全检查来运行。

阶段 3 获准的只读报告应记录实际机器与包身份、原生／进程架构、当前语言、目标身份是否已存在、查询完整性及阻断原因。只读结果符合条件仅支持提出一次写入申请，不自动触发注册。写入申请须明确管理员范围、一次事务、清理与失败恢复边界。

本文件当前不修改旧 CI、队列、PR87 固定包、c27 运行器、旧验收记录或任何机器设置。阶段 1 的输出为可审阅源码与测试记录，不是已安装或已验收产品。


## 6. 阶段 2 独立 CI 范围（待执行）

限定步骤：

1. MSVC x64 构建独立 DLL、stage1 EXE 和 portable policy 测试，不运行注册模式。
2. 运行 portable policy、源码／离线证据／打包／只读采集器模拟测试；另运行两个真实 Windows Job 子树测试，禁止跳过冒充通过。
3. 执行六项原生只读或必定无效的负例：默认预检、显式预检、只读不存在核验、无效参数、缺失账本恢复、固定垃圾账本恢复。绝不传有效恢复账本或调用注册模式。若普通 CI 主机先因主机身份门拒绝，明确记录较早阻断，不声称覆盖了后面的 DPAPI 分支。
4. 通过仓库 checked PS5 入口只读查询两个 PE 文件的实际 Authenticode 状态与哈希，不加载或执行 DLL。未签名会如实保留，哈希不等于签名或发行者信任。
5. 打包独立 DLL、工具、默认只读采集器及其 Job helper、manifest 和 README；固定源码 SHA、文件哈希、签名观察及 ZIP 哈希。包还须通过下一步包内采集器的真实只读检查，之后才上传包 artifact；日志证据在失败时也保留。
6. 将实际生成 ZIP 解到独立新目录，使用外部固定 manifest SHA 调用包内只读采集器一次，核对源码／载荷／输出哈希、子树已停止和无超时，并要求原生 `checked`、`writesStarted=false`、`prerequisitesSatisfied=false`。普通 CI 主机不要求注册条件满足；这是固定包只读采集链验证，不是 MyComputer 就绪结论。

这批 CI 不会证明注册、实际 DLL 激活、完整输入主流程或用户机器兼容性通过。旧七场景失败仍保留。只读采集器仅收集固定包预检结果，不包装注册，也不建立此前离线激活日志的同一次执行证明。阶段 3 的本机只读与之后的管理员写入仍需按各自边界确认，不能因取得包自动运行。
