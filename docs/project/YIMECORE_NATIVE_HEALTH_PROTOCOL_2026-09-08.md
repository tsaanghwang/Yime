# YimeCore 无会话只读健康协议

2026-09-08，影响产品：YimeCore。Runtime/Broker 源码现有独立健康端点和 PS5/PS7 原生客户端，用于后续新候选的维护观察。本轮完成源码、隔离回归和跨语言管道互通，没有重构产品候选、运行安装器、读取真实产品端点或改动已安装 local.12。既有候选、仓外封存和回退采集 v2 保留原身份；它们没有自动获得健康协议。

健康请求使用独立管道和两个专用连接槽，不经过输入协议 dispatcher，不创建引擎或输入会话，不占用普通输入连接/操作配额，不读取配置、设置或学习。普通 Broker 启动仍执行原有初始化；这里的只读边界只描述健康请求路径。Broker 的 `serving` 表示普通管道锚点尚处于服务生命周期，不保证一次普通输入请求能够完成。

Runtime 只在监管主循环刷新 Broker PID、创建时间与单调时间戳。身份来自启动时保留的原始进程句柄，关闭或退出后不能重新按 PID 冒认；启动、退出、重试和停止路径撤销旧快照。超过两秒未刷新即返回 `starting`，健康线程读取不能自行刷新时间。这能检测过期监管快照，不能证明引擎执行、配置已被采用或真实登录启动。

协议固定为一次 48 字节请求和一次 80 字节响应。请求含角色、32 字节新鲜随机 nonce 和零保留位；响应回显 nonce，并给出自身 PID/创建 FILETIME、角色、状态及 Runtime 所观察的 Broker 身份。普通管道名只能派生固定 `.health-v1` 与 `.runtime-health-v1` 后缀，拒绝远程、路径穿越、非法字符与过长名称。服务端拒绝短帧、错误角色、非零保留位和已缓冲的额外字节；稍后到达的字节也不会触发第二次处理。客户端要求严格 80 字节后 EOF，拒绝多字节、截断、错误 nonce/身份或非 serving 状态。

服务端要求同 SID 客户端并持有本地管道首实例锚点。锚点本身不能阻止同 SID 冒充；客户端还核对操作系统返回的管道服务端 PID、持有的进程句柄及原生创建时间。PowerShell 包装器只接受原进程观察模块登记的活引用，调用前后复核原始 Runtime/Broker 身份和关系，不接受序列化快照或调用者改写的 evidence。加载健康模块不会以 Force 重载原观察模块，已有租约保持有效。C# 源文件哈希仅绑定本轮读取的源码，不认证进程中实际执行的所有代码。

每个服务端连接读写共用一秒截止时间；客户端两角色交换合用一秒协议预算，之后取消、关闭并等待未完成 I/O 清理，退出时检查无遗留 I/O。清理耗时不承诺硬实时一秒上限。服务端快照回调只允许迅速返回可信内存数据，不声称能够强制中止任意阻塞回调。

验证结果及原始文件哈希见[结构化记录](../testing/l6/2026-09-08-native-health-protocol.json)：

- 实际 CI 维护检查体包含 15 个脚本，外部 Windows PowerShell 5.1 与同进程 PowerShell 7 各 **1503 项通过**，共 30 份结果。新增健康模块各 73 项，其中各 22 个原生自有管道用例覆盖身份、帧格式、超时和清理；完整进程租约组合仍使用私有提供程序。
- 三个相关 Go 包在 x64 和实际 x86 WOW64 上分别 **124 个测试通过事件、0 失败**，计数包含子测试；各有一个默认跳过的显式互通辅助测试，由下一项独立执行。三个包的 `go vet` 通过。
- PS5、PS7 分别连接两个自行启动的 Go 测试进程，每版完成两轮新鲜角色对交换，原始子进程均自然退出 0。这里直接使用实际 Go 服务端和 C# 客户端；两进程是同一测试启动的兄弟进程，不是实际 Runtime 创建的 Broker。它验证线协议和 OS 管道身份绑定，不验证完整产品进程租约集成。
- ARM64 只交叉编译 Broker 库和 Runtime 命令的测试二进制，没有原生执行或平台验收。
- 双产品基线 **219 项源码（212 项声明及 7 项锁定依赖）、68 项合成测试通过，8 项待办保留**。维护检查与互通已接入 CI；本地验证不冒充远端 CI 运行结果。

互通脚本的后续审查补齐了子进程提前登记、异常路径输出读取收尾和就绪文件完整写入等待。首次环境恢复复跑中，PS7 的线协议通过，但外层断言发现 `GOCACHE` 未恢复原状；该失败单独保留。脚本现按环境变量原存在性明确删除或恢复，最终两版 PowerShell 另行验证环境还原，旧成功线协议记录不被重写为整条验证通过。

客户端只提升 `health_service_responsive`、`nonce_verified`、`pipe_server_identity_bound` 和保留进程复核等窄范围结果。`runtime_ready_verified`、`runtime_consumed_config_verified`、`startup_path_verified`、E7、真实回退/恢复/卸载、L6、local/public 和执行授权保持 false。健康协议不承担 Rime/PIME DP1-U、DP2/DP3 的验收，既有 DP1 诚实关闭字段不变。

后续先从审查过的源码重新构建独立候选并封存，再把精确候选身份接入维护编排。采集 v2 仍绑定此前不含健康服务的固定候选，因此本轮没有静默插入探测或把旧候选标成支持新协议。新候选的实际 Runtime/Broker 组合、引擎响应、配置采用及完整原生维护、恢复、卸载重装、重启登录和宿主验收仍需各自证据；普通 local.12 日用与用户已经确认的 L5 不重做。
