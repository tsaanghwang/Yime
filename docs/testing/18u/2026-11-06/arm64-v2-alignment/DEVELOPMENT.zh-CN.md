## 配套合同

- Go 前端与 v2 管道支持原生 ARM64，使用 `IsWow64Process2` 将编译架构与本机架构绑定；仿真和混架构拒绝。前端仍按正文 PID/TID 连接专用 TIP，保留 profile、线程焦点、context、generation、sequence 和实际编辑完成确认。
- C++ TIP、注册维护、安装证明和独立检查宿主支持 ARM64。旧 DOWN、候选和迟到结果不能转移到新正文；提交结果未知保持锁定，不重放。
- 新 ARM 完整包版本 `0.2.0-18u-arm64.6`，目标 `windows-arm64`，六个 PE 为原生 ARM64。DLL/维护/检查宿主在 `arm64/`，共享前端在 `frontend/`。安装 descriptor 使用主线 `installed-18u-product-v1` 九字段、`native-arm64`、`autostart:false`；前端另有 v2 协议元数据和双二进制标记校验。
- ARM 源产品描述从共享描述派生，只允许 `scope.architecture` 不同。三模式资源仍由既有锁固定，不新造键位或编码源，不混入标准产品字典。
- `build_installed_18u_arm64.py` 从精确干净提交在全新输出中重建完整配套组件、读取签名并制包；不运行产品、注册或安装。CI 的 ARM job 在 x64 runner 交叉构建，不能作为原生运行证据。

## 旧 .5 正常升级

旧安装清单 v2 与 Frontend v2 是不同版本概念。新安装入口只接受新合同；旧十字段 v2、完整能力列表、20 载荷、资源锁和安装锚只可通过明确的旧安装维护路径。

PowerShell 和 native `check-owned`/注销路径共同核验旧 ARM 安装；注册新产品与正常前端不接受旧清单。正常升级先注销旧 profile/COM，再移除属于旧包的 `bin` 前端、复制新完整包并注册。旧 Run 项只有在外部 `StdRegProv` 读回与旧 Runtime 路径、安装根和清单哈希完全匹配时才移除；陌生值或读取失败停止维护。新版本按共享主线从 `frontend/Start Installed Touch Keyboard.cmd` 显式启动，不建立常驻或开机启动。

保留用户数据和校准文件。默认适应屏幕与实测毫米模式分开验证；旧标尺结果不继承。发生占用、身份不符或维护失败时保留现场，不覆盖已加载 DLL，不强杀文档宿主。保留旧完整包供后续正常回退；本次没有执行升级或回退。
