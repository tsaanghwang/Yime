# ASUS 18u 量尺与记事本绑定修复

本轮接续已安装的 46dd5896 / `0.2.0-18u-arm64.1`，仅针对 ASUS 内置屏量尺及一次手指中文选词。标准 YimeCore 与 Rime/PIME 保持各自固定版本；不扩展到笔、重启或其他架构宿主。

## 首次真人观察

用户报告内置屏 3840×2400、Windows 缩放 250%、实体尺精度 1 mm。标称 100 mm 参考线实测 57.5 mm，盘面完整。绑定时提示不能绑定，预期正文“你”，实际正文为空，停止于绑定。用户填写的 PID 字段是中文文字，不作为进程标识使用。

这次尺寸尚未校准，手指正文输入没有通过。原始报告及只读采集保留于 `raw/first-binding-failure-observation.json`；此前 18/18 是已安装前端的软件检查。标准版安装器维护修复后仅复验 ARM64/full，旧三模式×三架构 9/9 保留其原执行时间与范围。

## 当前诊断证据

实际运行的记事本 PID 28936、版本 11.2607.14.0，映像及进程均为原生 ARM64，Medium、非提升、非 AppContainer。此前模块快照只有 MSCTF，未见安装目录中的 18u DLL；单张快照不能证明其从未加载，也不能确定绑定失败原因。系统注册指向正确 ARM64 DLL，profile 和启用状态正确。当前范围内没有对应的 CodeIntegrity 或 Application 加载错误记录；没有事件不等于加载成功。原始日志与修正过 Unicode 路径声明的采集器记录分别保留。

在当前已安装 46dd DLL 上，新检查宿主完成一次冷加载激活：激活前 DLL 未加载，Windows `ActivateProfile(FORPROCESS)` 加载后核对实际 profile、provider、vtable 所属模块的文件身份，停用成功。没有注册变更、文本输入或新 Broker/GUI；既有记事本和三进程身份保持。这补齐普通桌面宿主首次加载检查，不能替代记事本激活和真实正文输入。

## 校准修复

旧 GUI 默认按 597.73 mm 屏宽计算像素比例。用户的原始参考尺读数应一次性修正为 `100 / 57.5`，不与旧校准复合。按该读数算得键区宽 3832 px；原来两侧固定 10 px 外留白使总宽 3852 px 超过屏宽。

新实现仅收紧触屏窗口外留白至可容纳的范围；当前算例为左右各 4 px、总宽 3840 px。18u、19.05 mm/u 键距、编码与 Windows 250% 缩放不变。若键区本身超屏仍拒绝，不自动缩小。

显式 `--save-ruler-observed-mm` 操作核对已安装身份后，将基准参考线的真实实测值原子保存到当前用户 `%LOCALAPPDATA%\YimeCore 18u Touch\display-calibration`。记录绑定显示器接口、物理像素分辨率及基准屏宽；正常 Runtime 后续启动读取。缺少记录保持原行为，错误或不匹配记录不套用，失败保存保留原记录。保存不启动第二个键盘，也不意味着实体尺复测通过。

源码候选版本为 `0.2.0-18u-arm64.2`。必须完成同源 CI、固定完整包交付及实际安装后，才对本机保存测量值和验证新运行。当前安装结果与后续正文/量尺结果会另行追加，不以源码测试替代。

## 后续单次检查

记事本使用独立新建空白页，原有标签内容保留。须在该应用实际选中“音元拼音·18u触摸”、正文有光标，然后绑定。仅在绑定成功后，全码依次输入 N08、M03、M03、M03（`niii`），点候选“你”一次，并检查实际正文。工具无法访问任务栏输入法选择器时，需要用户完成选择；自动化点击与真人手指结果分开记录。

新校准应用后的 100 mm 参考线仍由用户实体尺复测；不预设未经确认的尺寸公差。每次失败保留第一次观察，修复与针对性复验分别记录。
