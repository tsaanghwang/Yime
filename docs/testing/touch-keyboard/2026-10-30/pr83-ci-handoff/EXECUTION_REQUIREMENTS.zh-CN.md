# PR #83 新CI包执行要求

适用ARM64原生Windows与主流x64台式机。固定包、下载链接和SHA-256以同目录 `CI_DELIVERY.zh-CN.md`、`package-identity.json` 为准。使用本次省略号候选包，不沿用PR #82包；旧包、旧记录及本机宏碁笔29项/手指10项均保留原身份，不复制为接收机器通过。

## 1. 接收和环境记录

1. 把ZIP保存在包外独立目录，例如 `C:\dev\Yime-deliveries\pr83-20261030`，分别解压到新的 `arm64` 或 `amd64` 子目录，结果放在旁边的 `records`。不覆盖原包、不把结果混进旧结果目录。
2. ARM机使用 `windows-arm64` 包；64位Intel/AMD台式机使用 `windows-amd64` 包。记录机器、Windows版本、系统/键盘进程架构、屏幕、缩放、触控能力、笔型号及宿主进程架构。ARM上的x64仿真结果单列，不能替代ARM64键盘原生运行。
3. 对照交付表核对ZIP和 `YimeTouchKeyboard.exe` SHA-256、manifest架构、`sourceCommit`、`sourceChanges:false`。若用PowerShell核验，遵守仓库规则，通过 `python tools/powershell/run_checked.py --edition ps7 --command "Get-FileHash -LiteralPath '实际文件绝对路径' -Algorithm SHA256"` 执行；完整独立包本身不要求安装Python，可用系统已有哈希工具。
4. 在新解压包运行 `Check Package.cmd`，保存新产生的 `package-check.json` 到包外records；先保存原ZIP与manifest。Check Package是资源/内存三模式检查，不是物理触控、真实宿主输入或省略号专项验收。
5. 用 `Start Touch Screen Preview.cmd`，核对98键触屏视图（84主体＋14控制）。它应启用 `--preview --touch-ui --theme dark --key-sound click`。不要误用普通完整100键预览入口。
6. 每台屏幕独立用尺检查参考线、调整自己的校准并记录；不要复制微星屏的58.8参数或97mm结果。防回弹试验保持默认0；不要为通过测试调整全局音频设备、安装输入法或默认设置。

## 2. 基础冒烟 B00—B03

| ID | 操作 | 预期与记录 |
|---|---|---|
| B00 | 身份/架构核对与Check Package | 身份一致，检查成功；保存报告。ARM键盘进程确为ARM64。 |
| B01 | 首次启动、正常退出后重新启动，各按3次字母键 | 键面完整，上下档不被裁切；声音开时首次及重启后均有明确按键声，不需先最小化。记录实际输出与声音。 |
| B02 | 打开帮助，下一页、上一页、返回；打开设置并返回 | 用该输入方法可触发、关闭并返回，程序可继续输入；不把鼠标成功算手指/笔成功。 |
| B03 | 最小化，从任务栏恢复，再正常退出/重启 | 不锁死，任务栏可找回；恢复后输入/声音正常。最小化、退出本身无敲击声属于既定行为。 |

有触屏时，手指、每支可用笔分别执行B01—B03并分别记录；无触屏的台式机可先用鼠标做功能检查，将手指/笔标为设备不可用，不以鼠标模拟代替硬件验收。基础异常先记录，暂不展开后续批次。

## 3. 真实宿主省略号 E01—E12

基础通过后，正常退出预览，再启动 `Start Touch Screen Keyboard.cmd`。先在Edge使用PR #83的[固定测试框源码](https://github.com/tsaanghwang/Yime/blob/7136cba1c9cececc339fb19da2d81e6789b14617/docs/testing/touch-keyboard/2026-10-29/edge-host/test-textarea.html)，下载HTML后在本机打开；页面直接显示正文码点。不要修改HTML来凑预期。

统一为CN、变码、键面ID、标点入口关、Shift/Ctrl/Alt及选择状态关闭。每项独立清空、点入空白文本框并显式“绑定”，先用主区数字输入 `12`；正文保持12后再开始。**每个中点都重新点一次Shift，再点N25**，Shift为一次性。前三/六次期间不自动选择。每项选定后组合及暂存应清空，不得重复补出旧省略号。

| ID | 操作 | 正文与关键预期 |
|---|---|---|
| E01 | 3个中点，点第一候选 | `12…`；末尾一个U+2026。前两次暂存1/2，第三次才显示两候选；选择前正文12。 |
| E02 | 3个中点，点第二候选 | `12⋯`；末尾一个U+22EF。 |
| E03 | 6个中点，点第一候选 | `12……`；末尾两个U+2026。 |
| E04 | 6个中点，点第二候选 | `12⋯⋯`；末尾两个U+22EF。 |
| E05 | 3个中点，主区退格一次，再补1个中点，选第一候选 | 退格后候选消失、暂存2；补点后候选恢复；最终 `12…`，不删除12。 |
| E06 | 3个中点，点键盘取消；重新输入3个，选第二候选 | 取消后正文12、暂存0；新组第一次从1计，最终 `12⋯`。 |
| E07 | 3个中点，Shift熄灭后点主区数字1 | `12…`，无额外数字；不用侧数字区。 |
| E08 | 6个中点，点右空格 | `12……`，无额外空格。 |
| E09 | 3个中点，CN→EN→CN；观察清理后重新输入3个，选第二候选 | 切换后旧候选/暂存消失、正文12；旧候选不恢复；新组最终 `12⋯`。过程中不重新绑定。 |
| E10 | 6个中点，设置内变码改全码并返回；重新输入3个，选第一候选 | 模式切换清理旧候选/暂存、正文12；新组最终 `12…`。过程中不重新绑定；结束恢复变码。 |
| E11 | 3个中点，最小化/任务栏恢复；先观察，再定位并重新绑定；新3个选第二候选 | 恢复后正文12、暂存清空、旧绑定失效；重新绑定后最终 `12⋯`，无旧组重放。 |
| E12 | 6个中点，帮助→下一页→上一页→返回；先观察，再定位并重新绑定；新3个选第一候选 | 返回后正文12、暂存清空、旧绑定失效；重新绑定后最终 `12…`，无旧六点重放。 |

手指和各支笔分别执行；没有相应硬件则明确未测。宿主定位允许鼠标辅助，但要如实记录，不能称纯手指/笔定位。每次只交付2—4项待反馈，不要求接收者一次提交所有结果。异常时记录项号、输入方法、实际正文/码点、组合/计数、绑定、声音和截图；先停止该项，保留状态，不自动重试或补记尝试次数。

码点判定以诊断行实际U+2026/U+22EF为准：字体可能把U+2026也显示在中线，不因字形居中就改判为U+22EF；也不只凭字形宣布码点正确。

## 4. Word与32位宿主 W01—W02

Edge核心通过后，在Word两个新的空白未保存文档分别复测E01、E04，验证显式绑定、输出和可见光标。只在一次性测试文档中操作，不改用户现有文档；码点没有读取就标未测，不能凭外观写入码点通过。宿主进程是ARM64、x64还是WOW64需明确。

“x86台式机”若指通常的Intel/AMD台式机，应先确认系统是否x64；当前CI只交付amd64和ARM64键盘包，**没有32位键盘exe包**。若目标是32位应用，则在已识别x64 Windows上运行amd64键盘，针对已有Firefox/Notepad++等32位宿主重复W01/W02（E01/E04），记录该宿主确为32位/WOW64；不存在这些应用时记未测，不安装新软件、不新增32位Windows硬件路线。64位宿主结果不继承为WOW64通过。

## 5. 提交结果与后续范围

复制对应 `RESULT_ARM64_TEMPLATE.json` 或 `RESULT_AMD64_TEMPLATE.json` 到records填写，所有条目初始pending。逐条使用passed/failed/not-run并附原因、实际结果和证据，设备/笔/宿主分别新增记录，不混算。提交身份、环境、包检查报告、基础结果，再逐组推进E01—E12和W01/W02。

包通过SHA/CRC/manifest核验不等于设备兼容或物理验收。并发/混合触点、微星笔剩余项目及重复稳定性另列；不因本轮点选测试正常扩大到全部按键或全部场景。两台机器无需同时完成，源码分支与已安装产品保持隔离，不安装或改变默认输入法、用户数据、系统字体。更换包/过期重新下载新构建时，重新固定源码和哈希，不沿用本次身份。
