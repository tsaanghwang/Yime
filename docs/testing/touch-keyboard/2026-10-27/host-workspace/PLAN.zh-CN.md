# 优先解决宿主可见空间

2026-10-27。用户反馈F1–F12暂时用不上，键盘几乎占满屏幕，宿主正文不可见且应用难以操作。该问题已影响真实宿主验收，应先收束当前阶段，再调整可用视图，之后恢复剩余逐键/手指/笔测试。

本轮原包下手指P10共250项、CN余150项，两支笔各400项待测。声音修复仅在最新实际预览中收到三次清楚的定向反馈；不同包和视图的结果不自动继承。保留全部记录，无须先把受阻的全量矩阵硬做完。

按既有1800px屏高与最新1442px窗口渲染估算，键盘约占八成屏高；这不是新物理测量。仅隐藏F1–F12不能直接消掉整行，因为同排还有Esc、CN/EN、Layout、Pause/Break。将整行及其后间隔折叠，估算可回收约195px；再精简300px高的常驻预览/控制区，才能进一步给宿主留空间。

推荐先实现同源的可折叠屏幕视图：原18u宽度、58.8参数和完整100键视图保留；折叠功能行时，将取消/Esc、语言及Layout保留为可达控制，输入编码和稳定键身份不变。常驻区优先显示组合、候选和必要控制，参考尺、帮助说明及开发状态按需展开。保持已放大的字符，避免靠整体缩键重新制造可读性和触点问题。17u/23u继续冻结。

先评估让上方约四成屏幕可供宿主使用，这是设计目标而非已经约定的物理验收尺寸。键盘下方停靠、宿主上方可见；具体预留工作区或调整宿主窗口的行为需在实现时明确，并验证对其他窗口、焦点和绑定世代的影响，不能只把窗口贴底后仍遮住正文就宣布完成。

先通过Word/Edge的空间可用性：当前输入段落/光标可见，常用控件可操作，能在键盘和宿主之间切换、重新绑定和最小化恢复。再做一小组手指/笔输入回归，视图固定后续测剩余P10及宿主案例。发生位置或命中区域变化的键按新视图记录，不拿旧结果直接补成通过。
