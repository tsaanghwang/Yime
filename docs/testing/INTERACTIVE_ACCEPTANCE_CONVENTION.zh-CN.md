# 人工交互验收惯例：分组操作、点选回报

用户决定：2026-11-07。适用于项目各机器上的人工交互验收，尤其是18u触摸盘的真实宿主、手指和笔测试。各测试端默认采用本惯例，统一引导和回报方式；机器、架构、产品、固定包和用例范围仍分别记录。

## 1. 默认用选择题回报，不要求反复手输中文

18u测试时，操作者可能需要最小化触摸盘、返回Codex，再临时切到微软拼音或美式英语才能方便回复。忘记切回测试用的专用输入法，会使下一轮看起来像“触摸输入又坏了”。返回聊天本身也会改变焦点，可能按设计取消旧组合或暂停连接。

因此每轮采用固定顺序：**说明一组操作 → 操作者连贯完成并观察 → 点选实际结果 → 记录 → 下一轮先恢复测试状态。**

- 代理负责先写好可点选的完整回复，操作者只需在完成后选择。优先使用交互问题工具（如 `request_user_input_async`），不要要求每台机器各自发明回报格式。
- 每题提供三种结果：**“符合预期：本组具体观察”／“出现异常，已停止”／“尚未完成或没看清，暂不判定”**。第一项必须写明关键观察，不能只有“正常”或笼统的“全部通过”。不要把“通过”标为推荐答案。
- 预选、预填文字、默认选中项、问题已送达及未回复均不是结果。只有用户操作后明确提交的回答才能登记为用户反馈；不得自动提交、代选通过或把预期文本写入测试正文。
- 不直接操作Codex聊天输入框来代填或代发。交互工具不可用时，给出相同的三个编号选项，允许回复 `1`、`2`、`3` 或复制一行答案，不强制输入中文长段落。复制答案只用于回报，不能代替触屏输入验收。
- 异常选项先接受“已停止”，再只询问失败步骤和必要现象；不要求用户继续操作以凑齐一份完整回答。

## 2. 把聊天状态与测试状态分开

| 阶段 | 操作者与代理的共同约定 |
| --- | --- |
| 回聊天报告 | 先在测试窗口观察并记下结果，再回聊天点选。需要文字补充时，操作者可临时选择本机已有的微软拼音、美式英语或其他可用输入法；不安装新输入法，不改变系统默认设置。 |
| 返回测试准备 | 恢复触摸盘，点回指定测试正文，确认本轮产品的专用输入法、前端CN/EN及编码模式，再等待本包规定的就绪状态。已正确选中时不重复切换。 |
| 执行一组操作 | 用本组指定的手指或笔完成输入；中途不打开聊天，不为报告而最小化或切换输入法。用例本身要求的切窗、设置暂停、最小化或退出按原步骤执行。 |
| 完成并报告 | 先核对所有目标正文、组合/候选和写入次数，再回聊天。回聊天后的失焦提示不倒推为刚才的提交失败。 |

**每次从聊天回来，都要重新确认测试状态，不能依赖上一轮已经选过输入法。** 代理每组都附上简短提醒，例如：

> 回到A正文，确认本轮专用18u输入法、CN／目标编码模式，等待自动就绪。完成整组后再回聊天；不要点“重连”。

这只是当前测试宿主的临时选择，不是设置默认输入法、调整语言列表或修改自启动。不要为了方便聊天或测试，替用户全局切换默认项。测试结束保留现场；需要恢复临时输入选择时，按本轮已约定的原选择处理，不擅自设定新的默认项。

18u前端的CN/EN、变码/全码/简码，与Windows当前选择的输入法是不同状态；不能只看其中一个按钮。安装态测试应在本轮入口确认匹配的专用profile或已加载DLL等身份依据，不能仅凭一个 `中`、`英` 或 `拼` 图标证明产品身份。预览模式则按预览用例检查，不要求激活已安装TIP。

## 3. 一次一组，保持用例语义完整

一组包含一个可以独立判定的场景，通常为2—4个连贯步骤。一次只发一组并等待实际结果；不要一次派发全部模式、全部宿主或整张矩阵。

但不能把需要保持焦点/组合的场景拆成“每点一下就回聊天”：例如“输入未确认组合 → 切B取消 → 回A不恢复 → 新输入一次”必须作为一组连贯执行，否则聊天切换本身会取消组合，无法判断被测行为。

每组操作前写清：

1. 本轮用例编号、A/B具体窗口及需要保留的已有正文；不以含糊的“输入框”同时指聊天框、前端组码区和宿主正文。
2. 起始语言/编码模式、物理输入设备、已知就绪条件；涉及组码时，从本机固定包配套资料确认键序和候选，不从另一布局或包照抄。
3. 按顺序列出动作、观察点和精确增量，例如“A只新增一个指定字、B不变、候选清空”。明确哪些候选只观察、不得确认。
4. 异常停止点和三个可点选结果。没有完整观察的项目保持“待确认”，不能靠猜测补齐。

全码、简码、变码各给一组：**旧模式留下未确认组合 → 打开设置暂停 → 选择一个目标模式 → 关闭后自动就绪、旧组合不恢复 → 用新模式输入并确认一次**。不能在一次设置里连点三个模式，只测试最后一种，却把三个子项全部记通过。

正常退出/重开需要代理参与启动时，可分成“用户退出且核对正文”和“确认进程已退出后启动一次、用户观察新输入”两个阶段。阶段一通过不能提前登记整个生命周期用例通过。重启Windows另按具体授权和保存工作确认处理。

## 4. 未就绪、异常与通过的判定

- **测试状态未恢复：** 从聊天回来仍选着微软拼音/美式英语、焦点还在聊天、前端仍最小化或模式未确认时，记“准备未就绪”。先恢复本轮规定的测试前提，不能仅凭这类状态判触摸输入故障，也不能登记通过。
- **需要区分的输入现象：** 先确认使用的是实体键盘还是屏幕触摸盘，英文/ASCII出现在聊天框、前端组码区还是宿主正文。某些固定安装版的专用TIP仅放行实体按键，中文需触屏前端；是否属于该包边界应查配套说明，不能推广到所有产品或版本，也不能据此忽略实际触屏CN提交异常。
- **前提已满足但行为异常：** 保留首次现场。不能把真正的错目标、重复/漏写、旧候选恢复、宿主退出或提交未知解释为“忘了切输入法”，也不能自动重连、补按、重装或更改设置使其看起来通过。
- **未知提交或锁定：** 依照该包已批准的停止/恢复合同处理；切回专用输入法、切模式、最小化或自动连接均不是解除锁定、重放旧请求的理由。正常设置暂停用例不证明未知锁定分支通过。
- **就绪等待：** 使用本轮已批准的时间界限和发现瞬态规则，不为所有机器硬套一个新时限或新增忽略错误的例外。
- **明确反馈：** 完成整组后，用户选择包含全部关键观察的“符合预期”，可记“通过（用户逐项反馈）”。若只回复“正常”且缺少必要观察，先补问缺项，不自动要求重跑已完成操作。未观察到的步骤保持待确认。

## 5. 统一问题模板

以下尖括号字段由代理在派发前替换成当前用例的已核实内容，不直接把占位符交给操作者。

```text
用例：<编号和单一场景>；输入设备：<手指或具体触控笔>。
A＝<明确测试窗口>；B＝<第二窗口或“不适用”>。保留已有正文。
开始前：回到A正文，确认<本轮专用输入法>、<CN/EN及编码模式>，等待<就绪条件>。

1. <动作和立即观察点；写明是否确认候选>
2. <动作和观察点>
3. <最终正文增量、另一窗口不变及候选状态>

整组完成后再回聊天点选。除用例要求外，中途不最小化、不切输入法、不点重连。
异常即停，不补按。

可点选回复：
1. 符合预期：<逐项关键观察>；<实际输入设备>，无手动重连。
2. 出现异常，已停在现场。
3. 尚未完成或有一步没看清，暂不判定。
```

这个模板说明如何提问，不预置验收结论。仅在用例要求无重连时使用对应选项；其他产品/历史显式绑定用例沿用其已批准步骤，不能为了统一模板擅自改成功判据。

## 6. 各机器的记录与接续

每台机器使用同一提问方法，填各自的证据：

| 字段 | 最少记录内容 |
| --- | --- |
| 批次身份 | 日期/时区、机器、原生架构、产品、版本、完整源码SHA、固定包链接和SHA-256、所用交接与惯例版本（Git提交） |
| 本轮环境 | 宿主/窗口及版本、进程架构、预览或安装态、前端模式、手指或具体笔；安装态的身份/就绪依据 |
| 用例 | 编号、派发的原始步骤、起始模式、实际组码/候选、预期增量和停止条件 |
| 回答 | 用户实际提交的选项原文和补充、时间；未提交的默认选项不收为反馈 |
| 结果 | 前后正文或精确增量、不变关系、组合/候选、写入次数；通过/失败/阻塞/待确认/不适用及原因 |
| 证据边界 | 分开标明用户反馈、代理直接观察、日志/静态检查；没有截图或回执时不虚构独立复核 |
| 接续 | 已完成项、当前模式/临时输入选择、未完成项、下一组的状态恢复提醒及现场保留情况 |

只采集本轮合成测试正文和必要证据，既有文档、私人词库及其他产品数据保留；不要求上传私人内容。主报告写清用户反馈的范围，不把鼠标、模拟触控、CI、旧包或其他机器的结果填成真人手指/笔通过。

复用已核验的固定包和已完成记录，不因换聊天、换代理或采用本惯例而重跑安装、重启、全量核包或已通过项目。开始前核对最新实际状态及相关执行子目录，不能只凭一份旧审批单或旧“未执行”报告重新安装。

本惯例只规定测试交互与记录，不发起任何机器的新安装或验收任务，不替换固定包、不扩大目标/产品范围。比如MSI的固定test.12与ASUS的ARM64候选各保留原身份；采用同一方法不代表可以共用包、组码或验收结论。具体用例入口见[项目测试指南](../YIME_TESTING_GUIDE.md)、[安装交接](../../installer/simple/HANDOFF.md)和[桌面交接](../../prototypes/touch-terminal/desktop/HANDOFF.md)。
